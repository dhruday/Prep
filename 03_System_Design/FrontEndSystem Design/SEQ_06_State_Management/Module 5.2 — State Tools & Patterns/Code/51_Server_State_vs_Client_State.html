Two fundamentally different types of state

🌍 Server State
• Lives on the server / database
• You only have a cached snapshot
• Can become stale at any time
• Async to fetch / mutate
• Other users may change it

Examples: user profile, product list, SAP purchase orders, Salesforce CRM records
💻 Client State
• Lives only in the browser
• Always up-to-date (you own it)
• Synchronous
• Lost on page refresh
• Private to this user/session

Examples: modal open/close, theme preference, form step, sidebar collapsed
Key insight: Mixing server and client state in Redux causes constant stale-data bugs. Use TanStack Query / SWR for server state, and Zustand / React state for client state.

TanStack Query for server state + Zustand for client state

// ─── Server State: TanStack Query ───
import { useQuery, useMutation } from '@tanstack/react-query';

const { data: orders, isLoading, isStale } = useQuery({
  queryKey: ['orders', userId],
  queryFn: () => fetchSAPOrders(userId),
  staleTime: 5 * 60 * 1000,  // 5 min
  gcTime:   10 * 60 * 1000,  // garbage-collect after 10 min
});

const createOrder = useMutation({
  mutationFn: postOrder,
  onSuccess: () => queryClient.invalidateQueries({ queryKey: ['orders'] }),
});

// ─── Client State: Zustand ───
const useUIStore = create()((set) => ({
  sidebarOpen: false,
  activeTab: 'overview',
  toggleSidebar: () => set(s => ({ sidebarOpen: !s.sidebarOpen })),
  setTab: (tab: string) => set({ activeTab: tab }),
}));

// ─── NEVER mix them in Redux ───
// 🚫 Don't put API responses in Redux slices — they become stale
// ✅ Keep ONLY truly global CLIENT state in Redux / Zustand
