IndexedDB — the browser's transactional NoSQL database

IndexedDB is an async, transactional, key-value + index store built into every browser. Unlike localStorage (5 MB, synchronous, strings-only), IndexedDB handles GBs of structured data, Blobs, binary files, and is accessible from Service Workers. At SAP, offline draft saving uses IndexedDB — users can fill purchase order forms without internet and sync when reconnected.

Key characteristics
  • 📦 Key-value store with indexes for queries
  • 🔄 Transactional (ACID-like)
  • ⚡ Async API (non-blocking)
  • 💾 Stores: objects, arrays, Blobs, typed arrays
  • 🔌 Accessible from Service Workers
Common use cases
  • 📝 Offline draft saving
  • 📊 Client-side data cache (large API datasets)
  • 🖼️ Binary file storage (images, PDFs)
  • 🔍 Full-text search index
  • 🔄 Pending mutations queue (background sync)

IndexedDB with idb library (wrapper)

// ─── Open DB ───
import { openDB, DBSchema } from 'idb';

interface SAPSchema extends DBSchema {
  orders: {
    key: string;
    value: { id: string; status: string; amount: number; createdAt: Date };
    indexes: { 'by-status': string };
  };
}
const db = await openDB<SAPSchema>('sap-offline', 1, {
  upgrade(db) {
    const store = db.createObjectStore('orders', { keyPath: 'id' });
    store.createIndex('by-status', 'status');
  },
});

// CRUD
await db.put('orders', { id: 'ORD-001', status: 'draft', amount: 1200, createdAt: new Date() });
const order = await db.get('orders', 'ORD-001');
const drafts = await db.getAllFromIndex('orders', 'by-status', 'draft');
await db.delete('orders', 'ORD-001');
