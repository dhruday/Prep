Browser cache tiers — from fastest to slowest

The browser has multiple internal caches. Understanding the tiers explains why a "hard refresh" behaves differently from a normal navigation, and why different resources are stored differently.

Memory cache — fastest, holds current session's cached responses in RAM. Lost on tab close. Resources fetched in this session (CSS, scripts) hit here first.
HTTP disk cache — persists across sessions. Respects Cache-Control headers. Shared across tabs within the same origin. Up to several GB.
Service Worker Cache (CacheStorage) — programmatic cache controlled by service worker script. Survives offline. Used for PWA shell, API response caching.
Push cache — HTTP/2 server push responses. Shortest lifetime (~5 min). Being deprecated in Chrome.

Service Worker CacheStorage patterns

// ─── SW install: pre-cache app shell ───
const CACHE_NAME = 'sap-fiori-v2';
const SHELL_ASSETS = ['/', '/main.abc123.js', '/styles.abc123.css'];

self.addEventListener('install', (e) => {
  e.waitUntil(
    caches.open(CACHE_NAME).then(c => c.addAll(SHELL_ASSETS))
  );
});

// ─── SW fetch: cache-first for shell, network-first for API ───
self.addEventListener('fetch', (e) => {
  const isAPI = e.request.url.includes('/api/');
  e.respondWith(isAPI ? networkFirst(e.request) : cacheFirst(e.request));
});

async function cacheFirst(req: Request): Promise<Response> {
  const cached = await caches.match(req);
  return cached ?? fetch(req);
}
async function networkFirst(req: Request): Promise<Response> {
  try {
    const res = await fetch(req);
    const cache = await caches.open(CACHE_NAME);
    cache.put(req, res.clone());
    return res;
  } catch {
    return (caches.match(req)) as Promise<Response>;
  }
}
