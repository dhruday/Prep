Performance problems disproportionately harm accessibility

Performance and accessibility are not separate disciplines — poor performance directly breaks accessibility. Users who rely on assistive technology (screen readers, switch access, zoom software) are disproportionately harmed by slow, unstable, or JS-heavy pages. Keyboard-only users and screen reader users are the first to experience broken focus, missing announcements, and unresponsive interactions caused by performance issues. This is a recurring interview topic at Adobe, Salesforce, Cisco, and Microsoft accessibility teams.

Long Tasks block keyboard
A Long Task (>50ms on main thread) blocks ALL input events. Keyboard users pressing Tab during a Long Task get no response — they don't know if the page is broken. Mouse users at least see a cursor. INP > 200ms = keyboard users feel unresponsive UI.
Layout shift disables screen readers
High CLS causes DOM changes that reset a screen reader's current reading position. NVDA / VoiceOver re-announces from the top. A CLS of 0.25 (poor) on a <nav> will constantly interrupt and disorient users mid-navigation.
Slow JS delays accessible widgets
Tabs, modals, accordions all require JS to set aria-expanded, aria-selected, and move focus. Until hydration completes, these elements exist in the DOM but don't respond to keyboard events — a dead zone for AT users.
Async content races AT announcements
Lazy-loaded content injected into aria-live regions too fast (before the region is in the AOM) won't be announced. Race condition: set aria-live BEFORE injecting content. setTimeout(inject, 0) is a common (wrong) fix.

Fixes: Long Task breaking, CLS, aria-live race condition

// ─── Break Long Tasks with scheduler.yield() (Chrome 115+) ───
async function processItems(items) {
  for (const item of items) {
    processItem(item);
    // Yield back to the event loop every chunk so keyboard events process
    if (scheduler?.yield) await scheduler.yield();
    else await new Promise(r => setTimeout(r, 0)); // fallback
  }
}

// ─── Prevent CLS — reserve space for lazy-loaded images ───
/* Always set width + height on <img> — browser calculates aspect ratio */
/* Use aspect-ratio CSS for responsive imgs */
img { width: 100%; height: auto; aspect-ratio: 16/9; }

/* For dynamic content (ads, banners) — reserve space in CSS */
.ad-slot {
  min-height: 90px;  /* prevents layout shift when ad loads */
  container-type: inline-size;
}

// ─── aria-live race condition fix ───
// WRONG: inject region and content at same time
container.innerHTML = `<div aria-live="polite">${message}</div>`; // screen reader misses this

// CORRECT: region pre-exists in DOM, content injected after
// In HTML:  <div id="status" aria-live="polite" aria-atomic="true"></div>
const region = document.getElementById('status');
region.textContent = '';
requestAnimationFrame(() => { region.textContent = message; }); // flush → announce

// ─── Defer non-critical third-party scripts (analytics, chat) ───
// These often cause Long Tasks that break keyboard responsiveness
<script defer src="analytics.js" />  // defer: after HTML parsed
<script async src="chat-widget.js" /> // async: non-blocking (unordered)
