The core problem — main thread blocking

JavaScript is single-threaded. Long tasks (>50ms) block the main thread, preventing frame renders and user input processing. The browser can't interrupt a running task — so a 200ms data processing loop will freeze the UI for that entire duration. The Scheduler API (WICG proposal, Chrome 94+) provides a priority queue for yielding between tasks, letting the browser interleave rendering and user input.

user-blocking
Runs ASAP, like a click handler. For: form validation, auto-complete response, menu toggle. Blocks rendering.
user-visible
Default priority. For: lazy-loading UI chunks, analytics, chart rendering. Interleaved with rendering.
background
Runs when browser is idle. For: log flushing, caching, prefetch, spell check. Like rIC but with priority

yield() pattern — chunking long tasks

Instead of one 300ms task, use await scheduler.yield() inside a loop to yield control to the browser every N iterations. The browser gets a chance to handle input and paint a frame, then your task resumes. This keeps INP (Interaction to Next Paint) low while still completing all the work.

Visualize task scheduling — click to run all 3 priority queues

When you queue tasks at different priorities, the browser runs them in priority order. User-blocking first, then user-visible, then background — but user-visible and background yield for rendering frames in between.

scheduler.postTask() with priority and cancellation

// Feature detect (Chrome 94+, polyfill otherwise)
const schedule = async (fn: () => void, priority: TaskPriority = 'user-visible') => {
  if ('scheduler' in window) {
    await (window as any).scheduler.postTask(fn, { priority });
  } else {
    await new Promise(r => setTimeout(r, 0));
    fn();
  }
};

// Cancelable task — e.g., cancel search if user types again
let controller: TaskController | null = null;

async function processSearchResults(query: string) {
  controller?.abort();
  controller = new (window as any).TaskController({ priority: 'user-visible' });
  
  try {
    await (window as any).scheduler.postTask(() => {
      renderResults(query);
    }, { signal: controller.signal });
  } catch (e) {
    if (e.name !== 'AbortError') throw e;
  }
}

// Chunked processing with yield — 10000 items without blocking
async function processProducts(products: Product[]) {
  const CHUNK = 100;
  for (let i = 0; i < products.length; i += CHUNK) {
    products.slice(i, i + CHUNK).forEach(process);
    await (window as any).scheduler.yield();  // yield for frame / input
  }
}
