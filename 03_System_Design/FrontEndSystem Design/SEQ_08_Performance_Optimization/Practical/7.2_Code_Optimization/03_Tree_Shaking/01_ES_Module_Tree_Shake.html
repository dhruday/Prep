ES Module Tree Shaking

Practical 7.2 · How bundlers eliminate dead code via static analysis

Tree Shaking in Action

// utils.js — exports 5 functions
export function add(a, b) { return a + b; }
export function subtract(a, b) { return a - b; }
export function multiply(a, b) { return a * b; }
export function divide(a, b) { return a / b; }
export function modulo(a, b) { return a % b; }

// app.js — only imports 1
import { add } from './utils';
console.log(add(2, 3));

// After tree shaking, bundle only contains:
// function add(a, b) { return a + b; }
// subtract, multiply, divide, modulo are removed!

// ❌ This DEFEATS tree shaking:
import * as utils from './utils';
// Bundler can't statically determine which exports are used
// (actually modern bundlers CAN handle this, but older ones can't)

// ❌ CommonJS is NOT tree-shakeable:
const utils = require('./utils');
// require() is dynamic — can't statically analyze
// Entire module is included

Why ES Modules Enable Tree Shaking

// ES Modules are STATICALLY analyzable:
//
// 1. import/export must be at top level (not inside if/function)
// 2. Module specifiers must be string literals (not variables)
// 3. Exports are named and known at compile time
//
// This means the bundler can BUILD A GRAPH at compile time:
//   app.js imports { add } from utils.js
//   → add is USED → keep it
//   → subtract is NOT imported anywhere → remove it
//
// CommonJS can NOT do this because:
//   const module = require(someVariable); // dynamic!
//   if (condition) { module.someMethod(); } // runtime-only knowledge
//
// Library best practice: publish ESM build
// package.json:
{
  "main": "dist/cjs/index.js",    // CommonJS fallback
  "module": "dist/esm/index.js",  // ESM for bundlers (tree-shaking)
  "exports": {
    ".": {
      "import": "./dist/esm/index.js",
      "require": "./dist/cjs/index.js"
    }
  }
}

Real Impact: lodash Example

// ❌ Import entire lodash: 71KB gzipped
import _ from 'lodash';
_.get(obj, 'a.b.c');

// ✅ Named import from lodash-es: tree-shakeable
import { get } from 'lodash-es';
get(obj, 'a.b.c');
// Bundle size: ~2KB instead of 71KB

// ✅ Direct path import (works with lodash too):
import get from 'lodash/get';
// Only includes the get function and its dependencies
