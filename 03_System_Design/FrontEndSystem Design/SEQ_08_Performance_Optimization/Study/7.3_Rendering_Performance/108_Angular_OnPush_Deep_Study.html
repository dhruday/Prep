1. Angular's Default Change Detection

// Angular uses Zone.js to intercept ALL async operations:
// - DOM events (click, input, scroll)
// - setTimeout, setInterval
// - Promise.then, fetch
// - requestAnimationFrame
//
// After ANY async operation completes:
// Zone.js notifies Angular → Angular runs change detection
//
// Default strategy: CHECK EVERY COMPONENT in the tree
//
// App
// ├── Header         ← checked
// │   ├── Logo       ← checked
// │   └── NavBar     ← checked
// ├── ProductList    ← checked
// │   ├── Item[0]    ← checked
// │   ├── Item[1]    ← checked
// │   └── Item[99]   ← checked
// └── Footer         ← checked
//
// Even a mouse move → Angular checks ALL 100+ components
// This is O(n) where n = total components in tree
//
// How checking works (per component):
// 1. Update input bindings
// 2. Run template expressions: {{ title }}, [class.active]="isActive"
// 3. Compare old vs new values (dirty checking)
// 4. If different → update DOM
// 5. Run child component checks (recursively)

2. The Performance Problem

// Problem: 500 components × 10 bindings each = 5000 dirty checks
// Per async event. On scroll: 60 events/sec = 300,000 checks/sec!
//
// Common triggers that cause unnecessary CD cycles:
//
// 1. Mouse events on unrelated elements
// 2. setInterval for unrelated timers
// 3. HTTP responses for unrelated data
// 4. Third-party library callbacks
// 5. WebSocket messages
//
// Template function calls are ESPECIALLY expensive:
//
// ❌ {{ getFullName() }}  ← called EVERY CD cycle
// ❌ *ngFor="let item of getFilteredItems()"  ← O(n) every cycle
// ❌ [class.highlight]="isHighlighted(item)"  ← per item per cycle
//
// Solution: OnPush + immutable data + observables

OnPush: How It Works

// OnPush tells Angular: "Only check this component when:"
//
// 1. An @Input() reference changes (Object.is comparison)
//    ✓ New object reference → check
//    ✗ Same object, mutated property → NOT checked
//
// 2. An event handler fires FROM THIS component or its children
//    ✓ (click)="onClick()" → triggers CD for this component
//    ✗ Event in sibling component → NOT checked
//
// 3. An Observable subscribed with async pipe emits
//    ✓ items$ | async → emits new value → marks dirty
//
// 4. Manually calling ChangeDetectorRef methods
//    markForCheck() → marks this + ancestors for next CD cycle
//    detectChanges() → runs CD immediately on this subtree

@Component({
  selector: 'app-product-item',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <div class="product">
      <h3>{{ product.name }}</h3>
      <span>{{ product.price | currency }}</span>
    </div>
  `
})
export class ProductItemComponent {
  @Input() product!: Product;
  // Only re-checked when parent passes a NEW product object
  // parent: this.products = [...this.products] ← new array
  // NOT: this.products[0].name = 'New' ← mutation, OnPush misses it
}

OnPush + Observables Pattern

@Component({
  selector: 'app-product-list',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <app-product-item
      *ngFor="let product of products$ | async; trackBy: trackById"
      [product]="product"
      (addToCart)="onAddToCart($event)"
    />
  `
})
export class ProductListComponent {
  products$ = this.store.select(selectProducts);
  // async pipe: subscribes, marks for check on emit, unsubscribes

  trackById(index: number, product: Product): string {
    return product.id;
    // trackBy prevents re-creating DOM for unchanged items
  }

  onAddToCart(product: Product): void {
    this.store.dispatch(addToCart({ product }));
    // NgRx emits new state → selector emits → async pipe marks dirty
  }
}

Angular Signals (17+): The Future

// Signals replace Zone.js for fine-grained reactivity
// No more "check everything" — only update what changed

@Component({
  selector: 'app-counter',
  template: `
    <h2>Count: {{ count() }}</h2>
    <p>Double: {{ doubled() }}</p>
    <button (click)="increment()">+1</button>
  `
})
export class CounterComponent {
  count = signal(0);
  doubled = computed(() => this.count() * 2);

  increment() {
    this.count.update(c => c + 1);
    // Only THIS component re-checks
    // No Zone.js needed, no tree-wide CD
  }
}

// Signal inputs (Angular 17.1+):
export class ProductItemComponent {
  product = input.required<Product>(); // signal-based input
  price = computed(() => this.product().price);
}

// bootstrapApplication(AppComponent, {
//   providers: [provideExperimentalZonelessChangeDetection()]
// });
// → No Zone.js → smaller bundle (–45KB)
// → CD only triggered by signals + events

FAANG Interview Questions

Q1: Explain Angular's change detection and how OnPush improves performance.
Angular's default change detection is triggered by Zone.js after every async operation — it walks the entire component tree top-down, dirty-checking every template binding. For a tree of 500 components with 10 bindings each, that's 5000 comparisons per async event. OnPush optimizes this by marking a component as "skip unless inputs change by reference, an event originates within it, or an async pipe emits." This converts the check from O(n) for all components to O(k) where k is components with actual changes. The key requirement is immutable data — instead of mutating objects, you create new references (spread operator, NgRx selectors). Combined with the async pipe (which automatically calls markForCheck), OnPush + observables gives near-optimal change detection. In Angular 17+, signals take this further — they provide fine-grained reactivity without Zone.js, so only components reading a changed signal re-render.
Follow-up: What happens if a team member mutates an @Input object in an OnPush component?
Q2: How would you migrate a large Angular app from Default to OnPush change detection?
Incremental, leaf-to-root migration. Start with leaf components (no children) — they're safest because they can't break child components. Add OnPush, test that the component still updates correctly. If it breaks, the component was relying on mutation somewhere. Fix: use immutable patterns or async pipe. Phase 1: All purely presentational (dumb) components → OnPush. These only receive @Input and emit @Output, so they're straightforward. Phase 2: Container components that use the store → switch to observable + async pipe pattern, then OnPush. Phase 3: Components with direct service subscriptions → convert to async pipe or use markForCheck() in subscribe callbacks. Phase 4: Root and routing components. Tooling: Angular ESLint rule prefer-on-push enforces OnPush on new components. The Angular team also recommends signals for new code, making this migration path cleaner over time.

OnPush Rules:
✅ Always use immutable data (new refs, not mutations)
✅ Use async pipe for observables
✅ Use trackBy with *ngFor
✅ Use pure pipes instead of method calls in templates
✅ Use computed() for derived values (signals)
❌ Don't mutate @Input objects
❌ Don't use function calls in templates
❌ Don't rely on setTimeout/setInterval for UI updates
❌ Don't use detectChanges() as a band-aid
