Tree shaking — eliminate dead code at build time

Tree shaking is a build-time process where bundlers (Webpack, Rollup, esbuild) statically analyse ES Module import/export graphs and remove any exported code that is never imported. Works only with ESM (import/export), not CommonJS (require()).

Why it works with ESM
ESM bindings are static — import { add } from './math' is resolved at parse time, not runtime. Bundler builds the full dependency graph and marks unreferenced exports as "dead".
Why it fails with CommonJS
const { add } = require('./math') is dynamic — what's destructured is only known at runtime. Bundler cannot safely eliminate any export. Everything ships.
SAP context: SAP UI5 components were imported as import * as UI5 — negating tree shaking by pulling in 890KB of unused components. Switching to named imports reduced bundle from 1.8MB → 640KB.

Tree shaking anti-patterns

// ❌ 1. namespace import — pulls entire module
import * as _ from 'lodash';        // 530KB
import * as UI5 from '@ui5/webcomponents'; // 890KB

// ✅ Named import — tree-shakeable
import { debounce } from 'lodash-es';  // ~2KB
import { Button } from '@ui5/webcomponents-react'; // only Button

// ❌ 2. Side-effect free library missing "sideEffects" flag
// Without package.json: { "sideEffects": false }
// Webpack can't safely tree-shake the library

// ❌ 3. CommonJS — no tree shaking
const { debounce } = require('lodash');  // entire 530KB lodash ships

// ❌ 4. Re-export barrel file defeats tree shaking
// components/index.ts
export * from './Button';
export * from './Modal';   // ← imports ALL, even if only Button used

// ✅ Direct import bypasses barrel
import { Button } from './components/Button';

Enabling tree shaking in your project

// ─── 1. Use ESM in your library (package.json) ───
{
  "main": "dist/index.cjs.js",     // CommonJS fallback
  "module": "dist/index.esm.js",   // ESM entry (bundlers prefer this)
  "sideEffects": false            // safe to tree-shake all exports
}

// ─── 2. tsconfig — preserve ESM ───
{ "compilerOptions": { "module": "ESNext", "moduleResolution": "bundler" } }

// ─── 3. Webpack config — production mode auto tree-shakes ───
module.exports = {
  mode: 'production',         // enables tree shaking + minification
  optimization: { usedExports: true },
};

// ─── 4. Verify with bundle analyser ───
// npm install --save-dev webpack-bundle-analyzer
