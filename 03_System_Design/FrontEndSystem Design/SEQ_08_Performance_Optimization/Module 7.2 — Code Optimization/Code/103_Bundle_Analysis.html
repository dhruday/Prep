Why bundle analysis matters

Without bundle analysis, your app silently grows. A new npm package added for one small utility can pull in 200KB of gzipped JavaScript that blocks the main thread and destroys LCP. Bundle analysis tools — webpack-bundle-analyzer, Rollup Visualizer, Vite Bundle Visualizer — make the invisible visible: exactly which package is how large, and what can be removed, split, or lazy-loaded.

webpack-bundle-analyzer
Interactive treemap. Drill into each chunk: stat → parsed → gzip size. Visual area = byte cost.
rollup-plugin-visualizer
Same concept for Rollup/Vite. Outputs sunburst, treemap, or network graph. CI-friendly stats.json output.
bundlesize / size-limit
CI enforcement: fails PR build if bundle exceeds budget. Stops regression before it ships.

The 3 sizes you must understand

Stat size
Raw output before minification. What webpack sees before optimizing. Usually 2–3x the final size.
Parsed size
After minification/tree-shaking. What's actually emitted in your dist folder. This is what you track.
Gzip size
Compressed transfer size. What users actually download over the network. Typically 60–70% of parsed.

Vite bundle analysis in CI

// vite.config.ts — add visualizer plugin
import { defineConfig } from 'vite';
import { visualizer } from 'rollup-plugin-visualizer';

export default defineConfig({
  plugins: [
    visualizer({
      filename: 'dist/bundle-report.html',
      open: false,   // Don't auto-open in CI
      gzipSize: true,
      brotliSize: true,
      template: 'treemap',  // 'treemap' | 'sunburst' | 'network'
    })
  ]
});

// package.json scripts:
// "analyze": "vite build && open dist/bundle-report.html"
// "size": "size-limit"

// .size-limit.json — CI budget enforcement
[
  { "path": "dist/assets/index.*.js", "limit": "150 KB" },
  { "path": "dist/assets/vendor.*.js", "limit": "200 KB" }
]

// GitHub Actions integration:
// - uses: andresz1/size-limit-action@v1
//   with:
//     github_token: ${{ secrets.GITHUB_TOKEN }}
//     # Posts size delta as PR comment automatically

Fix lodash tree-shaking (most common bundle win)

// ❌ WRONG — imports entire lodash, ~70KB parsed
import _ from 'lodash';
const result = _.groupBy(items, 'category');

// ✅ CORRECT — tree-shakeable ESM import, ~1KB
import { groupBy } from 'lodash-es';
const result = groupBy(items, 'category');

// ✅ EVEN BETTER — use native JS, zero dependency
const result = items.reduce((acc, item) => ({
  ...acc, [item.category]: [...(acc[item.category] ?? []), item]
}), {} as Record<string, Item[]>);
