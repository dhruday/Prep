What is Authorization Audit Logging?

Audit logging creates an immutable, structured record of every significant access control decision. Unlike application logs (for debugging), audit logs are for compliance evidence, forensic investigation, and anomaly detection.

Who

Identity Fields

userId, tenantId, sessionId, ipAddress (hashed for GDPR), userAgent

What

Action Fields

action (e.g. invoice:approve), resourceType, resourceId, method, path

Decision

Authorization Outcome

decision: allow | deny, decisionReason, policyVersion

When & Where

Context Fields

timestamp (ISO 8601 UTC), requestId, geo/region, mfaVerified

Canonical Audit Log Schema

timestampISO 8601 UTC// "2024-01-15T09:23:11.842Z"
requestIdstring (ULID)// correlation across services
tenantIdstring// multi-tenant isolation
userIdstring// who made the request
ipAddresshashed string// GDPR: never store raw IP in EU
actionstring// "invoice:approve"
resource.typestring// "Invoice"
resource.idstring (UUID)// never sequential integers (IDOR)
decision'allow' | 'deny'// BOTH allowed and denied
decisionReasonstring// "permission_granted" | "role_mismatch"
policyVersionstring// "v2.3.1" — which policy was active
sessionIdstring// session-level correlation

Kasync publish keeps audit logging off the critical request path. Transactional outbox (write to DB in same TX) guarantees no events are lost even if Kafka is down.

What NOT to Log

❌ Never
  • Passwords or password hashes
  • JWT tokens or session secrets
  • Raw PII (email, SSN, phone number)
  • Credit card numbers or CVVs
  • Full request bodies for sensitive ops
✅ Always
  • Both ALLOW and DENY decisions
  • requestId for cross-service tracing
  • Pseudonymized userId (hash PII)
  • policyVersion at time of decision
  • Timestamp in UTC ISO 8601
⚠️ Log ALLOW decisions too! Authorized users who access data and then misuse it are invisible if you only log DENY decisions. Insider threat detection requires allow-decision logs.

Transactional Outbox Pattern: Write the audit event to an audit_outbox table in the same database transaction as the business operation. A separate process reads the outbox and forwards to Kafka. If Kafka is down, events queue up safely. If the business transaction is rolled back, the audit event is also rolled back.

Code Patterns

NestJS Audit Interceptor (AOP Pattern)

// Intercepts every request — emits audit event automatically
@Injectable()
export class AuditInterceptor implements NestInterceptor {
  constructor(private readonly auditService: AuditService) {}

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const req = context.switchToHttp().getRequest();
    const requestId = req.headers['x-request-id'] ?? ulid();

    return next.handle().pipe(
      tap(
        () => this.emit(req, requestId, 'allow'),
        (err) => {
          if (err.status === 403) this.emit(req, requestId, 'deny', err.message);
        }
      )
    );
  }

  private emit(req: any, requestId: string, decision: 'allow' | 'deny', reason?: string) {
    this.auditService.emit({
      timestamp: new Date().toISOString(),
      requestId,
      tenantId:    req.jwtPayload.tenantId,
      userId:      req.jwtPayload.sub,
      action:      `${req.method.toLowerCase()}:${req.path}`,
      resourceType: req.params.resource ?? 'unknown',
      resourceId:   req.params.id ?? 'unknown',
      decision,
      decisionReason: reason,
      ipAddress: hashIp(req.ip),    // GDPR: pseudonymize
      policyVersion: process.env.POLICY_VERSION
    });
  }
}

Append-Only PostgreSQL (Tamper-Evident)

-- CREATE audit table
CREATE TABLE audit_log (
  id          UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  created_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  tenant_id   TEXT NOT NULL,
  user_id     TEXT NOT NULL,
  action      TEXT NOT NULL,
  resource_id TEXT,
  decision    TEXT CHECK(decision IN ('allow', 'deny')) NOT NULL,
  payload     JSONB
);

-- Make it append-only (prevent DELETE and UPDATE)
CREATE RULE no_delete AS ON DELETE TO audit_log DO INSTEAD NOTHING;
CREATE RULE no_update AS ON UPDATE TO audit_log DO INSTEAD NOTHING;

-- Partition by month for scalability
CREATE TABLE audit_log_2024_01 PARTITION OF audit_log
  FOR VALUES FROM ('2024-01-01') TO ('2024-02-01');

-- Query: per-user access history
SELECT * FROM audit_log
WHERE tenant_id = $1 AND user_id = $2
AND created_at > NOW() - INTERVAL '30 days'
ORDER BY created_at DESC LIMIT 100;

Transactional Outbox (Zero-Loss Guarantee)

// Write audit event in SAME transaction as business operation
async function approveInvoiceWithAudit(
  invoiceId: string, userId: string, tenantId: string
): Promise<void> {
  await prisma.$transaction([
    // Business operation
    prisma.invoice.update({ where: { id: invoiceId }, data: { status: 'approved' } }),

    // Audit outbox in same TX — atomically guaranteed
    prisma.auditOutbox.create({
      data: {
        eventType: 'invoice:approve',
        payload: JSON.stringify({ invoiceId, userId, tenantId }),
        status: 'pending'
      }
    })
  ]);
  // Outbox processor forwards to Kafka asynchronously
  // If Kafka down, events queue safely in DB
  // If TX rolled back, audit event also rolled back
}
