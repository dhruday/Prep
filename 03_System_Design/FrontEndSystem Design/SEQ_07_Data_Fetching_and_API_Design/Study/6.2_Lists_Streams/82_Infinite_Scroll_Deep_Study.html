1. IntersectionObserver API Internals

IntersectionObserver runs asynchronously off the main thread (compositor thread in Chromium). It uses a polling interval (~100ms) to check intersection ratios, NOT scroll events.

// Browser internals:
1. Observer registered → added to document's observer list
2. Compositor thread checks intersection every ~100ms
3. When threshold crossed → entry queued to microtask
4. Callback fires with IntersectionObserverEntry[]
5. Entry contains: intersectionRatio, isIntersecting,
   boundingClientRect, intersectionRect, rootBounds, time

// Key difference from scroll events:
// - No layout thrashing (no forced reflow)
// - No main thread blocking
// - Battery efficient (hardware compositor)
// - Multiple thresholds: [0, 0.25, 0.5, 0.75, 1.0]
Chrome's IntersectionObserver batches intersection checks with rAF timing. Firefox uses a separate thread. The 100ms polling is an implementation detail — the spec only guarantees async delivery.

2. Scroll Events vs IntersectionObserver

// Scroll event approach (legacy — avoid):
window.addEventListener('scroll', () => {
  // Fires 30-120 times/second during scroll
  // Each call triggers: getBoundingClientRect() → forced reflow
  // Layout thrashing: read → write → read → write...
  // scrollTop + innerHeight >= scrollHeight - threshold
});
// Problems: jank, battery drain, complex debounce needed

// IntersectionObserver approach (modern):
const observer = new IntersectionObserver(
  (entries) => { /* fires only when threshold crossed */ },
  { root: null, rootMargin: '200px', threshold: 0 }
);
// rootMargin: '200px' = trigger 200px BEFORE visible
// This prefetches data for smoother experience

Q1: Why use IntersectionObserver instead of scroll events for infinite scroll?
Three key reasons:
1. Performance: IO runs on compositor thread, doesn't block main thread. Scroll events fire 30-120/sec and require getBoundingClientRect() which forces layout reflow.
2. Battery: IO uses hardware-accelerated intersection checks. Scroll listeners keep CPU active during momentum scroll on mobile.
3. Simplicity: No manual debounce/throttle needed. IO fires exactly when threshold is crossed, not on every pixel change.

IO also supports rootMargin for prefetching (trigger 200px before visibility) and multiple thresholds for progressive loading.
Follow-up: What are IO's limitations?
1. ~100ms polling delay (not instant). 2. Can't detect scroll direction. 3. rootMargin doesn't support percentage on non-root elements in some browsers. 4. Disconnecting observers during rapid DOM changes can miss entries.
Q2: How would you implement virtual scrolling for 100K items with variable heights?
Architecture overview:
1. estimateSize: Provide estimated height (e.g., 60px) for initial render
2. measureElement: Use ResizeObserver to capture actual rendered height
3. Height cache: Map<index, measuredHeight> — falls back to estimate if unmeasured
4. Prefix sum array: Running total of heights for O(log N) scroll-to-index
5. Binary search: Given scrollOffset, find startIndex in prefix sums
6. Overscan: Render 3-5 items beyond visible range as buffer
7. Container: Fixed-height scroll container, inner div with totalHeight, items positioned with translateY

Key detail: When an item's measured height differs from estimate, all positions below shift. Must batch these recalculations to avoid layout thrashing. TanStack Virtual handles this with requestAnimationFrame batching.
Follow-up: How do you handle scroll position when item heights change after render (e.g., image loads)?
ResizeObserver on each item detects size changes. On resize: update height cache, recalc positions, adjust scrollTop to maintain visual position. Some libraries call this "scroll anchor correction." CSS overflow-anchor property helps for simple cases.
Q3: How do you prevent memory leaks in infinite scroll?
Memory grows unbounded as pages accumulate. Strategies:
1. Window dehydration: After N pages, remove data from oldest pages but keep metadata (count, height). Re-fetch on scroll back.
2. React Query maxPages: useInfiniteQuery({ maxPages: 5 }) — automatically drops oldest pages beyond limit.
3. Virtual DOM: Only mount visible items + buffer — unmounted items get garbage collected if no references held.
4. Image cleanup: Revoke blob URLs (URL.revokeObjectURL) for items scrolled far out of view.
5. WeakRef for caches: Use WeakRef for item caches, allowing GC under memory pressure.

At Google scale: Instagram feed limits in-memory pages to ~10, evicts oldest with placeholder. Scrolling back re-fetches.
Follow-up: How do you measure memory usage in practice?
performance.measureUserAgentSpecificMemory() (Chrome only), DevTools Memory tab heap snapshots, performance.memory.usedJSHeapSize. Set up automated memory regression tests with Puppeteer.
Q4: Design infinite scroll for a social media feed. What are the edge cases?
Core edge cases:
1. Empty state: No items → show "No posts yet" with CTA
2. Error mid-stream: Page 5 fails → show retry button inline, preserve pages 1-4
3. New content: While user is on page 3, 50 new posts arrive → show "50 new posts" toast at top, don't shift content
4. Rapid scroll: User scrolls to bottom instantly → queue/deduplicate page requests, show skeleton
5. Tab hidden: Stop prefetching when tab is background (Page Visibility API)
6. Offline: Show cached pages, hide "Load More", show offline banner
7. Deleted content: Item was deleted between page renders → placeholder "This post was deleted"
8. Accessibility: Screen reader needs to know new content loaded → aria-live region, focus management
Follow-up: How do you handle the "new content" notification without layout shift?
Fetch new items in background but DON'T prepend. Show floating toast "12 new posts" at top. On click: scroll to top, prepend items, animate in. Twitter/X uses this pattern.
Q5: Explain scroll position restoration with React and virtual scrolling.
Multi-layer approach:
1. Disable browser default: history.scrollRestoration = 'manual'
2. Save state: On route leave, persist { scrollOffset, firstVisibleIndex, pages: pageCount } to sessionStorage
3. Restore data: React Query's gcTime keeps data in cache. On return, cache is still warm.
4. Restore position: After data renders, virtualizer.scrollToIndex(savedIndex, { align: 'start' })
5. Verification: After scrollTo, check if target item is actually visible. If not (data changed), scroll to nearest valid position.

Race condition: data re-fetch may complete after scrollTo. Solution: wait for data to settle, then restore position in useEffect.
Follow-up: What about with React Router?
React Router v6.4+ has ScrollRestoration component. For virtual lists, create custom ScrollRestoration that saves virtualizer state, not raw scrollTop. Use useBeforeUnload for the save point.
Q6: When would you NOT use infinite scroll?
1. E-commerce search results: Users want to compare, bookmark, share page links → use pagination
2. Admin data tables: Need "jump to page 47", exact total count, export selection → pagination with page numbers
3. Legal/medical documents: Need precise references ("page 12, item 3") → traditional pagination
4. SEO content: Search engines have limited infinite scroll support → paginated with <link rel="next">
5. Accessibility-first: Screen readers struggle with dynamic content injection → provide pagination alternative
6. Footer important: If users need to reach the footer (contact, legal), infinite scroll pushes it unreachable

1. IntersectionObserver Sentinel Hook

function useIntersectionSentinel(onIntersect, options = {}) {
  const sentinelRef = useRef(null);
  const callbackRef = useRef(onIntersect);
  callbackRef.current = onIntersect; // Always fresh callback
  
  useEffect(() => {
    const el = sentinelRef.current;
    if (!el) return;
    
    const observer = new IntersectionObserver(
      (entries) => {
        // entries[0] — we observe single element
        if (entries[0].isIntersecting) {
          callbackRef.current();
        }
      },
      {
        root: options.root || null,      // null = viewport
        rootMargin: options.rootMargin || '200px', // prefetch buffer
        threshold: options.threshold || 0  // any visibility
      }
    );
    
    observer.observe(el);
    return () => observer.disconnect();
    // ^ Clean up on unmount — prevents memory leak
  }, []); // Empty deps — observer created once
  
  return sentinelRef;
}

2. Complete Infinite Scroll Component

function InfiniteFeed() {
  const {
    data, fetchNextPage, hasNextPage,
    isFetchingNextPage, status
  } = useInfiniteQuery({
    queryKey: ['feed'],
    queryFn: ({ pageParam }) => fetchFeed(pageParam),
    initialPageParam: null,
    getNextPageParam: (last) =>
      last.pageInfo.hasNextPage ? last.pageInfo.endCursor : undefined,
    maxPages: 10, // Memory limit: drop oldest pages
  });
  
  const allItems = data?.pages.flatMap(p => p.edges) ?? [];
  
  const sentinelRef = useIntersectionSentinel(() => {
    if (hasNextPage && !isFetchingNextPage) {
      fetchNextPage();
      // Guard: don't fetch if already fetching
    }
  });
  
  if (status === 'pending') return <FeedSkeleton />;
  if (status === 'error') return <ErrorFallback />;
  
  return (
    <div>
      {allItems.map(edge => (
        <FeedItem key={edge.cursor} item={edge.node} />
      ))}
      
      {/* Sentinel — invisible trigger element */}
      <div ref={sentinelRef} style={{ height: 1 }} />
      
      {isFetchingNextPage && <LoadingSpinner />}
      {!hasNextPage && <EndOfFeed />}
    </div>
  );
}

3. Virtual Scrolling with TanStack Virtual

function VirtualFeed() {
  const parentRef = useRef(null);
  const { data, fetchNextPage, hasNextPage } = useInfiniteQuery({...});
  const allItems = data?.pages.flatMap(p => p.data) ?? [];
  
  const virtualizer = useVirtualizer({
    count: allItems.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 80,  // estimated row height
    overscan: 5,              // render 5 extra items each side
    measureElement: (el) => el.getBoundingClientRect().height,
    // ^ Measures actual height after render
  });
  
  // Trigger fetch when nearing end of data
  const virtualItems = virtualizer.getVirtualItems();
  const lastItem = virtualItems[virtualItems.length - 1];
  
  useEffect(() => {
    if (lastItem && lastItem.index >= allItems.length - 5 && hasNextPage) {
      fetchNextPage();
    }
  }, [lastItem?.index]);
  
  return (
    <div ref={parentRef} style={{ height: '100vh', overflow: 'auto' }}>
      <div style={{ height: virtualizer.getTotalSize(), position: 'relative' }}>
        {virtualItems.map(vItem => (
          <div key={vItem.key}
            ref={virtualizer.measureElement}
            data-index={vItem.index}
            style={{
              position: 'absolute',
              top: 0,
              transform: `translateY(${vItem.start}px)`,
              width: '100%',
            }}>
            <FeedItem item={allItems[vItem.index]} />
          </div>
        ))}
      </div>
    </div>
  );
}
