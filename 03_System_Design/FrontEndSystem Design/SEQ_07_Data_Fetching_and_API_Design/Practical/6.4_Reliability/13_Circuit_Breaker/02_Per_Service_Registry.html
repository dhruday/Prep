Per-Service Isolation

Each service (products, posts, comments) gets its own CircuitBreaker instance with independent failure counters and states.
products → failRate=0.8 (very flaky) — trips fast.
posts → failRate=0.3 (mostly reliable) — rarely trips.
comments → failRate=0.5 (moderate) — trips occasionally.
When "products" circuit opens, "posts" and "comments" continue working independently.

BreakerRegistry

class BreakerRegistry {
  constructor() { this.breakers = new Map(); }

  get(name, opts) {
    if (!this.breakers.has(name))
      this.breakers.set(name, new CircuitBreaker(opts));
    return this.breakers.get(name);
  }

  getAll() {
    return [...this.breakers.entries()];
  }
}

// Usage
const registry = new BreakerRegistry();
const productsCB = registry.get('products');
const postsCB = registry.get('posts');
// Each is independent

Key Takeaways

✅ Never share a single breaker across unrelated services — a flaky endpoint will block healthy ones.
✅ A registry (Map) provides clean lookup by service name.
✅ Different services can have different thresholds and cooldowns.
✅ Dashboard visualization helps ops teams spot which services are degraded.
