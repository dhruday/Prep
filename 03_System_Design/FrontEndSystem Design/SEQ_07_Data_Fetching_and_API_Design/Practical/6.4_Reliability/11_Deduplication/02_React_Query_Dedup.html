How React Query Deduplicates

React Query (TanStack Query) uses the queryKey as a unique identifier. When multiple components call useQuery with the same key, the library:

1. Checks if an inflight fetch for that key already exists
2. If yes → subscribes the new observer to the existing promise
3. If no → starts a new fetch and stores it in the query cache
4. All subscribers receive the same data once the request resolves

queryKey Identity

// These two keys are considered EQUAL (deep comparison):
['products', { page: 1 }]
['products', { page: 1 }]

// These are DIFFERENT (different page):
['products', { page: 1 }]
['products', { page: 2 }]
React Query uses deterministic JSON serialization — key order doesn't matter: {a:1,b:2} equals {b:2,a:1}.

Shared Hook

// useProducts.ts
export function useProducts() {
  return useQuery({
    queryKey: ['products'],
    queryFn:  () => fetch('/api/rest/products')
                      .then(r => r.json()),
    staleTime: 30_000,  // data is fresh for 30s
  });
}

Multiple Components — Same Key

function Header()  { const { data } = useProducts(); ... }
function Sidebar() { const { data } = useProducts(); ... }
function Grid()    { const { data } = useProducts(); ... }
function Footer()  { const { data } = useProducts(); ... }
function Badge()   { const { data } = useProducts(); ... }

// All 5 mount → only 1 network request
// React Query shares the inflight promise via queryKey

Under the Hood — QueryCache

// Simplified internal logic
class QueryCache {
  queries = new Map();

  build(queryKey, queryFn) {
    const hash = hashKey(queryKey);
    if (!this.queries.has(hash)) {
      this.queries.set(hash, new Query(queryKey, queryFn));
    }
    return this.queries.get(hash);
  }
}

Why React Query Dedup is Powerful

• Zero setup — dedup is automatic via queryKey matching
• Works across deeply nested component trees
• Pairs with staleTime/gcTime for cache lifespan control
• DevTools show observer count per query

Common Pitfalls

• Unstable queryKey — if the key includes a new object reference each render, dedup breaks
• Different queryFn — React Query warns if two useQuery with the same key have different fetchers
• enabled: false — a disabled query won't participate in dedup
• Structural sharing — React Query returns stable references when data is unchanged

Dedup vs Caching

Feature            │ Dedup               │ Caching
───────────────────┼─────────────────────┼───────────────────
When               │ Parallel requests   │ Sequential requests
Duration           │ While inflight      │ staleTime + gcTime
Trigger            │ Same queryKey       │ Same queryKey
Network calls      │ 1 (shared promise)  │ 0 (cached result)
