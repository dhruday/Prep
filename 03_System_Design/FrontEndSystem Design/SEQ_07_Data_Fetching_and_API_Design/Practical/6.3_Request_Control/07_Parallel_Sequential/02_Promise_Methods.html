Promise Combinators Overview

Promise.all(promises)       // Rejects on FIRST failure
Promise.allSettled(promises) // Waits for ALL, never rejects
Promise.race(promises)      // Settles with FIRST to finish (success or fail)
Promise.any(promises)       // Resolves with FIRST success, rejects only if ALL fail

When to Use Each

Promise.all — All-or-nothing: loading a page that needs ALL data.
Promise.allSettled — Partial results OK: dashboard widgets that can fail independently.
Promise.race — Timeout patterns: race a fetch against a timer.
Promise.any — Redundancy: hit multiple CDN mirrors, use the fastest response.

How Promise Combinators Work Internally

All four fire requests immediately — they differ only in how they aggregate results on the microtask queue.

Promise.all: maintains a counter + results array. Each fulfilled promise fills its slot and decrements the counter. Any rejection immediately rejects the aggregate promise.

Promise.allSettled: same counter pattern, but wraps each outcome in {status, value/reason} — never short-circuits.

Race vs Any Internals

Promise.race: the first promise to settle (fulfill OR reject) wins. Internally it's Promise.resolve(p).then(resolve, reject) for each.

Promise.any: collects rejections into an array. Only when ALL reject does it throw AggregateError. First fulfillment wins.

After the aggregate promise settles, remaining in-flight requests still complete on the network layer — JS just ignores their results.

Q: What's the difference between Promise.all and Promise.allSettled?

A: Promise.all rejects immediately when any promise rejects — you lose all results. Promise.allSettled always waits for every promise and returns an array of {status, value/reason} objects, so you get partial results even if some fail.

Q: When would you use Promise.race?

A: Timeout pattern: Promise.race([fetch(url), timeout(5000)]). Also useful for racing multiple strategies (cache vs network) and using whichever responds first.

Q: What happens to "losing" promises in Promise.race?

A: They continue executing — there's no cancellation. The network requests complete, consuming bandwidth. To actually cancel, use AbortController on the losing fetches.

Q: What is AggregateError?

A: Thrown by Promise.any when ALL promises reject. It has an .errors array containing each individual rejection reason. Introduced in ES2021.
