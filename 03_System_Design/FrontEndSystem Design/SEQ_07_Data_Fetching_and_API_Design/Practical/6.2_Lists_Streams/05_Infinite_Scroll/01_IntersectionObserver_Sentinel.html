Sentinel Pattern

Place an invisible "sentinel" <div> at the bottom of the list. When it enters the viewport, fire a fetch for the next page.

// 1. Create sentinel element at bottom of list
const sentinel = document.getElementById('sentinel');

// 2. Create observer with rootMargin for pre-loading
const observer = new IntersectionObserver(entries => {
  if (entries[0].isIntersecting && !loading) {
    loadNextPage();
  }
}, {
  // Start loading 300px BEFORE sentinel is visible
  rootMargin: '0px 0px 300px 0px'
});

observer.observe(sentinel);
rootMargin: '0px 0px 300px 0px' — expands the intersection root by 300px at the bottom. The sentinel "intersects" 300px before it's actually visible, giving time to fetch data before the user reaches the end.

IntersectionObserver Internals

Unlike scroll event listeners, IntersectionObserver runs off the main thread in a compositor-side process. The browser batches geometry calculations and only invokes your callback when thresholds are crossed.

// The browser performs these steps internally:
// 1. Compositor thread tracks element bounding rects
// 2. On each frame, checks intersection ratio vs thresholds
// 3. When threshold crossed → queues microtask on main thread
// 4. Callback receives IntersectionObserverEntry[]

entry.isIntersecting     // boolean — is element in root?
entry.intersectionRatio  // 0..1 — how much is visible
entry.boundingClientRect // element's rect
entry.rootBounds         // root's rect (including rootMargin)
entry.time               // high-res timestamp
Performance advantage: scroll events fire 60+ times/sec on main thread. IntersectionObserver fires only on threshold crossings, off-thread. No layout thrashing.

Options Deep Dive

new IntersectionObserver(callback, {
  root: null,        // null = viewport, or a scrollable parent
  rootMargin: '300px', // CSS-like margin around root
  threshold: [0, 0.5, 1] // fire at 0%, 50%, 100% visible
});

Q: Why IntersectionObserver over scroll event?

1. Performance: Scroll events fire on every pixel of scrolling (60+ times/sec). Each handler call forces getBoundingClientRect → layout recalculation → potential layout thrashing. IntersectionObserver runs off-thread and only fires on threshold crossings.

2. No manual math: No need to calculate element.offsetTop - scrollTop - containerHeight. Observer does geometry checks natively.

3. rootMargin: Native pre-loading zone without manual scroll distance calculations.

4. Cleanup: observer.disconnect() vs removing scroll listener + debounce function.

Q: How to prevent duplicate fetches?

let loading = false;
let hasMore = true;

const observer = new IntersectionObserver(([entry]) => {
  if (!entry.isIntersecting || loading || !hasMore) return;
  loading = true;
  fetchNextPage().finally(() => loading = false);
});

// Also: unobserve sentinel when no more pages
if (!response.hasNextPage) {
  observer.unobserve(sentinel);
  hasMore = false;
}
Three-guard pattern: isIntersecting + loading flag + hasMore flag. This is the FAANG-expected answer.
