❌ REST: Over-fetching & Multiple Round-trips

To show a user profile page with posts and comments, REST requires 3 separate calls:

GET /users/1→ GET /users/1/posts→ GET /posts/1/comments
Each call returns ALL fields (name, email, address, phone, website…) even if the UI only needs name and avatar. This is over-fetching. Needing 3 calls is under-fetching.

✅ GraphQL: One Query, Exact Fields

query UserProfile {
  user(id: 1) {
    name
    avatar
    posts(limit: 5) {
      title
      comments(limit: 3) { body author }
    }
  }
}
Single POST request → server resolves all data → returns exactly the shape the UI needs. Zero over-fetching.

🔍 HTTP Method Differences

REST
• Uses GET for reads → cacheable by CDN/browser
• URL-based → cache key = URL
• Status codes: 200, 404, 500
• Content-Type: application/json
GraphQL
• Always POST (typically) → not CDN-cacheable by default
• Single endpoint /graphql
• Always 200 (errors in body)
• Must use persisted queries or GET for caching

🌐 CDN Caching Workarounds for GraphQL

// Persisted queries: hash query → GET with query ID
GET /graphql?extensions={"persistedQuery":{"sha256Hash":"abc123"}}

// APQ (Automatic Persisted Queries) flow:
// 1. Client sends hash → server checks cache
// 2. Miss → client resends full query
// 3. Server caches hash→query mapping
// 4. Next time: hash hits → CDN can cache GET

💬 "When would you choose REST over GraphQL?"

REST wins when: Simple CRUD, strong caching needed, file uploads, public APIs (discoverability), team unfamiliar with GraphQL, microservices with diverse data sources.
GraphQL wins when: Complex nested data, mobile apps (bandwidth matters), rapid iteration on UI, multiple client types (web/mobile/TV), aggregating multiple backends.

💬 "Explain the N+1 problem in GraphQL"

// Naive resolver: for each post, query DB for author
const resolvers = {
  Post: {
    author: (post) => db.users.findById(post.authorId)
    // ↑ Called N times (once per post) = N+1 total queries
  }
};

// Solution: DataLoader batches into 1 query
const userLoader = new DataLoader(ids => db.users.findByIds(ids));
// Collects all IDs in single tick → 1 SQL: WHERE id IN (...)

💬 "How do you handle errors in GraphQL?"

// GraphQL always returns 200. Errors are in the response body:
{
  "data": { "user": null },
  "errors": [{
    "message": "User not found",
    "path": ["user"],
    "extensions": { "code": "NOT_FOUND" }
  }]
}
This means you can't rely on HTTP status codes. Client libraries like Apollo check errors array and data nullability.
