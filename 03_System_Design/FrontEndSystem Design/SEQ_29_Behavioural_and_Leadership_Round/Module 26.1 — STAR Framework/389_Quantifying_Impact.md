## 1. ⚡ HIGH-LEVEL EXPLANATION
Every result needs numbers. **Performance metrics** (60→95 Lighthouse), **business metrics** (30% conversion increase), **efficiency metrics** (50% dev time reduction), **scale metrics** (serving 10K users). If you don't have exact numbers, estimate reasonably and say "approximately."

### Types of Metrics That Impress
| Category | Examples | Why It Works |
|---|---|---|
| **Performance** | LCP, FCP, Lighthouse, load time | Technical credibility |
| **Business** | Revenue, conversion, retention | Business awareness |
| **Efficiency** | Dev time, deploy frequency, bug rate | Process impact |
| **Scale** | Users, requests/sec, data volume | System complexity |
| **Quality** | Code coverage, bug rate, escalations | Engineering rigor |
| **Team** | Team size led, PRs reviewed, mentored | Leadership signal |

### How to Estimate When You Don't Have Exact Numbers
```
"Before my optimization, the page took about 4 seconds to load" ✅
 vs.
"The page was slow" ❌

"I estimate we reduced build times by roughly 40%" ✅
 vs. 
"Builds got faster" ❌

Use: "approximately", "roughly", "around", "reduced by an estimated"
Never fabricate — estimate honestly from memory
```

### Metric Formulas for Common Scenarios
```
Performance: "Reduced [metric] from [X] to [Y] — a [Z]% improvement"
Efficiency:  "Cut [process] from [X time] to [Y time] — saving [Z hours/week]"
Quality:     "Reduced [bugs/incidents] by [X]% over [time period]"
Scale:       "System now handles [X] concurrent users / [Y] requests/sec"
Team:        "Led a team of [N] across [M] time zones"
```
