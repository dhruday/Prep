1. JavaScript Prototype Chain Recap

// Every JS object has [[Prototype]] → chain of inheritance
const obj = {};
obj.__proto__ === Object.prototype; // true

// Property lookup walks up the chain:
// obj.toString → not on obj → found on Object.prototype
//
// Prototype Pollution = modifying Object.prototype
// → affects ALL objects in the runtime
//
// If attacker sets: Object.prototype.isAdmin = true
// Then: ({}).isAdmin === true for every object

2. How Pollution Happens

// The attack vector: recursive merge / deep clone without key checks

function merge(target, source) {
  for (const key in source) {
    if (typeof source[key] === 'object') {
      if (!target[key]) target[key] = {};
      merge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
}

// Attacker sends this JSON payload:
const payload = JSON.parse('{"__proto__":{"isAdmin":true}}');
merge({}, payload);

// Now EVERY object in the app has .isAdmin === true
const user = {};
console.log(user.isAdmin); // true ← polluted!

// Also works via: constructor.prototype
// {"constructor": {"prototype": {"isAdmin": true}}}

Attack: Client-Side Prototype Pollution

// Source: URL parameters, postMessage, JSON inputs

// URL-based pollution (common in SPAs):
// https://app.com/?__proto__[isAdmin]=true
// If the app parses query params into object with deep merge:
const params = parseQuery(location.search);
// params = {"__proto__": {"isAdmin": "true"}}
// deepMerge into config → Object.prototype polluted

// Client-side gadgets (what the pollution enables):
// 1. XSS via innerHTML template: if template checks obj.html
// 2. Open redirect: if config.redirectUrl is checked without hasOwn
// 3. DOM clobbering: combined with prototype pollution → XSS

Defense Strategies

// 1. Freeze the prototype (nuclear option)
Object.freeze(Object.prototype);
// ⚠️ May break libraries that extend Object.prototype

// 2. Use Map instead of plain objects for user data
const config = new Map(); // No prototype chain issues

// 3. Object.create(null) — no prototype at all
const safeObj = Object.create(null);
safeObj.__proto__; // undefined (not linked to Object.prototype)

// 4. Key sanitization in merge functions
function safeMerge(target, source) {
  for (const key of Object.keys(source)) {
    if (key === '__proto__' || key === 'constructor' || key === 'prototype') {
      continue; // Skip dangerous keys
    }
    if (typeof source[key] === 'object' && source[key] !== null) {
      target[key] = target[key] || {};
      safeMerge(target[key], source[key]);
    } else {
      target[key] = source[key];
    }
  }
  return target;
}

// 5. Use hasOwnProperty checks in access patterns
if (Object.prototype.hasOwnProperty.call(user, 'isAdmin')) { /* safe */ }

FAANG Interview Questions

Q1: What is prototype pollution and why is it dangerous in JavaScript?
Prototype pollution is when an attacker modifies Object.prototype (or any prototype in the chain) by injecting properties through unsafe deep merge, clone, or path assignment functions. Since all objects inherit from Object.prototype via the prototype chain, a polluted property like Object.prototype.isAdmin = true becomes visible on every object: ({}).isAdmin === true. The danger escalates based on "gadgets" — code paths that read properties without hasOwnProperty checks. On the server (Node.js), this has led to RCE: polluting __proto__.shell or __proto__.env.NODE_OPTIONS can hijack child_process.exec behavior. On the client, it can enable XSS if a template engine reads a polluted property and injects it as HTML. The fix: use Object.create(null) for dictionaries, sanitize keys (__proto__, constructor, prototype), use Map for user data, and validate with hasOwnProperty.
Follow-up: How would you detect prototype pollution in a large codebase?
Q2: How does prototype pollution differ between client-side and server-side JavaScript?
Client-side: the attack source is typically URL parameters (?__proto__[polluted]=value), postMessage payloads, or JSON from untrusted APIs. The impact is usually XSS via DOM gadgets — template engines, innerHTML paths, or config objects that control security-sensitive behavior. Server-side (Node.js): the source is HTTP request bodies (JSON payloads), and the impact is far more severe — potential RCE. For example, polluting __proto__.env.NODE_OPTIONS = '--require=./malicious.js' can cause any subsequent child_process.fork to load attacker code. Server libraries like Lodash.merge, jQuery.extend(true), and Handlebars compile have all had prototype pollution CVEs. The key difference is blast radius: client-side affects one user's browser tab; server-side affects the entire Node.js process and all requests.
Follow-up: Can you give an example of a prototype pollution → RCE chain?
Q3: How do modern frameworks and libraries protect against prototype pollution?
Several layers: (1) Lodash 4.17.12+ blocks __proto__ in merge/set paths. (2) JSON.parse is actually safe — it creates objects with __proto__ as a regular string key, not the special [[Prototype]] accessor, BUT if you then pass the result to an unsafe merge, it's still dangerous. (3) Zod/Joi schema validation strips unknown fields before they reach merge functions. (4) ESLint plugin no-prototype-builtins catches missing hasOwnProperty checks. (5) Node.js v19+ added --frozen-intrinsics flag to freeze all builtins. (6) TypeScript strict mode helps because accessing unknown properties is a type error. (7) npm audit catches known CVEs. In my projects, I use schema validation (Zod) at the API boundary so untrusted data never reaches internal merge functions with arbitrary keys.

1. Safe Deep Merge Implementation

const DANGEROUS_KEYS = new Set(['__proto__', 'constructor', 'prototype']);

function safeDeepMerge(target, ...sources) {
  for (const source of sources) {
    if (!source || typeof source !== 'object') continue;

    for (const key of Object.keys(source)) {
      if (DANGEROUS_KEYS.has(key)) continue;

      const val = source[key];
      if (val && typeof val === 'object' && !Array.isArray(val)) {
        target[key] = safeDeepMerge(target[key] || Object.create(null), val);
      } else {
        target[key] = val;
      }
    }
  }
  return target;
}

2. Detection Script

// Runtime detection: check if prototype was polluted
function checkPrototypePollution() {
  const clean = Object.create(null);
  const polluted = {};

  // Object.create(null) has no prototype
  // {} inherits from Object.prototype
  // If {} has keys that Object.create(null) doesn't → polluted

  const suspicious = Object.keys(polluted).filter(
    key => !(key in clean)
  );

  if (suspicious.length > 0) {
    console.error('Prototype pollution detected!', suspicious);
    // Clean up
    suspicious.forEach(key => delete Object.prototype[key]);
  }
}

Prevention Checklist

✅ Never use for...in without hasOwnProperty check for user data
✅ Use Object.create(null) for dictionaries holding user input
✅ Use Map/Set instead of plain objects for dynamic key-value stores
✅ Sanitize keys: block __proto__, constructor, prototype in merge/set
✅ Use Object.keys() / Object.entries() instead of for...in
✅ Validate input with Zod/Joi before deep merge operations
✅ Keep dependencies updated (npm audit)
✅ Use --frozen-intrinsics in Node.js production
✅ Add ESLint no-prototype-builtins rule
✅ Prefer structuredClone() over custom deep clone
