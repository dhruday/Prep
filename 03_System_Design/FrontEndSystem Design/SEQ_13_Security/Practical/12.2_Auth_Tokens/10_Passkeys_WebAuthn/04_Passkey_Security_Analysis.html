Passkey Edge Cases & Challenges

// 1. ACCOUNT RECOVERY
// What if user loses all devices?
// Solutions: Multiple passkeys on different devices,
//   recovery codes, backup security key, email-based recovery

// 2. SHARED DEVICES
// Kiosk, library computer → can't use platform authenticator
// Solution: Cross-device flow (use phone via QR + BLE)

// 3. CORPORATE / MANAGED DEVICES
// IT needs to manage which authenticators are allowed
// Solution: Use attestation to restrict by AAGUID

// 4. SYNCED PASSKEYS SECURITY
// Passkeys synced via iCloud / Google → cloud account compromise
//   means passkey compromise
// Mitigation: Cloud accounts have their own protection
//   (2FA, Advanced Protection Program)
// For high-security: require device-bound credentials

// 5. CROSS-ORIGIN / SUBDOMAIN
// RP ID must be a registrable suffix of the current origin
// login.example.com can use RP ID "example.com"
// But NOT "other-site.com" or "com"

Google Senior Frontend — Passkey Security

Q: Should passkeys completely replace passwords?

Not yet as sole factor, but as the primary factor with fallbacks. Google's approach: (1) Passkeys as primary sign-in. (2) Password as recovery fallback (with strong protections). (3) Recovery phone/email for account recovery. Long-term vision: password-optional accounts where passkey is the only auth method, with recovery codes for lost devices. The transition strategy matters: Don't force passkey-only. Offer passkey alongside password, then nudge users to go passwordless. For enterprise: require device-bound passkeys (not synced) for admin accounts. Allow synced passkeys for regular users.

Q: How does your frontend handle the WebAuthn API across browsers?

Feature detection pyramid: (1) Check window.PublicKeyCredential exists. (2) Check isUserVerifyingPlatformAuthenticatorAvailable(). (3) Check isConditionalMediationAvailable() for autofill. Based on capabilities: Show "Sign in with passkey" button if platform authenticator available. Show autofill if conditional mediation available. Fall back to "Use security key" for roaming only. Show password form as ultimate fallback. Libraries like @simplewebauthn/browser handle base64url encoding, ArrayBuffer conversions, and response serialization. Never build the WebAuthn client from scratch.
