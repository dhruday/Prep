Google Senior Frontend — Password Security

Q: Is it the frontend's responsibility to hash passwords?

No — and doing so can be harmful. Client-side hashing gives a false sense of security: the hash becomes the password (an attacker who captures the hash can replay it). The correct approach: (1) Always use HTTPS — this protects the password in transit. (2) Hash on the server with bcrypt/argon2. (3) The frontend's job: validate password strength, check breaches via HIBP API, warn on weak passwords. Exception: Some banking apps use client-side key derivation (PBKDF2) specifically to protect the plaintext password from the server (zero-knowledge proof pattern), but this is rare.

Q: How does Google Password Manager check breaches without revealing your password?

Uses a protocol similar to HIBP k-anonymity: hash the password, send only a prefix (first 5 hex chars of SHA-1), server returns all matching breached hashes. Client checks locally for full match. Google enhanced this with Private Set Intersection (PSI): a cryptographic protocol where neither the client reveals its password nor the server reveals its full breach database. The server learns nothing about which specific credential was checked.
