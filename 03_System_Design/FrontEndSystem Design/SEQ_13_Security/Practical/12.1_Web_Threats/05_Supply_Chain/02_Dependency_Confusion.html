How Dependency Confusion Works

// The Setup:
// Company "Acme" has an internal npm package: @acme/auth-utils
// It's published on their private Artifactory registry
// Their .npmrc: registry=https://artifactory.acme.com/npm/

// The Attack:
// 1. Attacker discovers the internal package name (from GitHub, job postings, etc.)
// 2. Registers "auth-utils" (unscoped) on public npmjs.com
// 3. Publishes version 99.0.0 (higher than internal 1.2.3)
// 4. npm resolves to PUBLIC version 99.0.0 (higher version wins!)

// Why it works:
// npm checks BOTH private and public registries
// If the public registry has a higher version, it installs that one
// The malicious package runs postinstall → exfiltrates secrets

// Real impact (Alex Birsan, 2021):
// Successfully compromised builds at Apple, Microsoft, PayPal,
// Shopify, Netflix, Tesla, Uber — earned $130K+ in bug bounties

Defense Strategies

// 1. USE SCOPED PACKAGES (@org/package)
// Scoped packages are namespaced — can't be impersonated
// @acme/auth-utils is different from auth-utils
// Configure scope to always use private registry:
// .npmrc: @acme:registry=https://artifactory.acme.com/npm/

// 2. REGISTRY PINNING in .npmrc
// registry=https://artifactory.acme.com/npm/
// @acme:registry=https://artifactory.acme.com/npm/
// This ensures @acme scope ALWAYS resolves from private registry

// 3. LOCKFILE with integrity hashes
{
  "packages": {
    "node_modules/@acme/auth-utils": {
      "version": "1.2.3",
      "resolved": "https://artifactory.acme.com/npm/@acme/auth-utils/-/auth-utils-1.2.3.tgz",
      "integrity": "sha512-abc123..." // integrity check prevents tampering
    }
  }
}

// 4. CLAIM YOUR NAMESPACE on public npm
// Register placeholder packages for all internal names
// npm publish with "private": true to block others

// 5. USE --ignore-scripts during CI installs
// npm install --ignore-scripts
// Then run allowed scripts explicitly

Google Senior Frontend — Dependency Confusion

Q: Your company has 50+ internal npm packages. How do you prevent dependency confusion?

1. Scope everything: All packages under @company-name scope. 2. .npmrc enforced via repository template: @company-name:registry=private-url. 3. Lockfile committed with integrity hashes verified in CI. 4. Claim placeholders on public npm for every internal package name. 5. Private registry proxy (Artifactory/Nexus): configure it to NOT cascade to public npm for your scoped packages. 6. CI validation: script that checks resolved URLs in lockfile — fail build if any @company-name package resolved from public npm. Google's approach: Bzl/Bazel manages dependencies with pinned SHA256 hashes — no dynamic resolution at build time.
