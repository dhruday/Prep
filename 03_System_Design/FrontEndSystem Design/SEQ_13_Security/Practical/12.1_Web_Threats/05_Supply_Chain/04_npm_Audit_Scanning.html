Google Senior Frontend — Dependency Management

Q: A critical CVE is published for a transitive dependency (dep of a dep). Your lockfile pins the vulnerable version. What do you do?

Step 1: Run npm ls vulnerable-package to find which direct deps use it. Step 2: Check if the direct dep has a new version with the fix (npm outdated). Step 3a: If yes, update the direct dep (npm update direct-dep). Step 3b: If no, use npm overrides (npm 8.3+) to force the patched version. Step 4: Run tests to verify nothing breaks. Step 5: If override breaks things, consider forking the direct dep temporarily with the patched transitive dep. At Google: Bazel's dependency management pins transitive deps explicitly, making this faster to fix.

Q: npm audit reports 50 vulnerabilities. How do you prioritize?

1. Filter by severity: Focus critical/high first. 2. Check if they're in dependencies vs devDependencies (devDeps don't affect production). 3. Check exploitability: Is the vulnerable code path actually reachable in your app? 4. CVSS score + EPSS (Exploit Prediction Scoring System) for likelihood of exploitation. 5. Use npm audit --production to see only production vulnerabilities. Most npm audit noise is from devDeps or unreachable code paths.
