Google Senior Frontend — Supply Chain Security

Q: How would you design a supply chain security strategy for a frontend monorepo?

Layer 1 — Lock: Use lockfiles (package-lock.json) with integrity hashes. Pin exact versions, no ranges. Layer 2 — Audit: npm audit in CI, Snyk/Dependabot for automated PRs. Layer 3 — Registry: Use a private registry (Artifactory/Verdaccio) as a proxy — whitelist approved packages. Layer 4 — Install scripts: Use --ignore-scripts by default, allowlist specific packages. Layer 5 — Monitoring: Socket.dev for real-time package change alerts. Layer 6 — Vendoring: For critical deps, vendor the source into your repo. Google uses a curated third-party directory with manual security review for every dependency.

Q: A dependency you use has been compromised. What's the incident response?

Immediate (0-1h): Pin to last known good version in lockfile, deploy. Check CI logs for postinstall script execution. Scan build artifacts for injected code. Short-term (1-24h): Check if your builds/deployments used the compromised version. Rotate any secrets that may have been exfiltrated. File security advisory. Medium-term: Evaluate alternatives, add package to monitoring watchlist, implement the layered strategy above.
