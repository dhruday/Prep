What Counts as "Same-Site"?

// Same-site = same eTLD+1 (effective top-level domain + 1)

https://app.example.com  →  eTLD+1 = example.com
https://api.example.com  →  eTLD+1 = example.com  ← SAME SITE
https://evil.com         →  eTLD+1 = evil.com     ← CROSS SITE

// Public suffixes (eTLDs) are maintained in the Public Suffix List:
// .com, .co.uk, .github.io, .herokuapp.com are all eTLDs
// So app1.github.io and app2.github.io are CROSS-SITE!

SameSite Edge Cases & Gotchas

1. Lax+POST (2-minute window): Chrome sends Lax cookies on cross-site POST requests for the first 2 minutes after the cookie is set. This is for backward compatibility with OAuth flows. An attacker could exploit this narrow window.

2. Subdomain isolation: SameSite only checks eTLD+1. So if attacker controls sub.example.com (via XSS), they can attack app.example.com because they're same-site.

3. iframe embedding: If your site is loaded in an iframe on evil.com, SameSite=Lax blocks cookies on the initial load. SameSite=None + Secure is required for cross-site iframe auth (e.g., embedded payment forms).

4. Scheme consideration: Chrome now treats HTTP → HTTPS as cross-site ("Schemeful SameSite"). A cookie set on https://example.com won't be sent to http://example.com in a cross-site context.

Set-Cookie Best Practice

// For auth session cookies:
Set-Cookie: session=abc123;
  HttpOnly;        // JS can't read it
  Secure;          // HTTPS only
  SameSite=Lax;    // blocks cross-site POST
  Path=/;          // available on all paths
  Max-Age=86400;   // 24 hours

// For cross-site cookies (OAuth, analytics):
Set-Cookie: tracking=xyz;
  SameSite=None;   // must set for cross-site
  Secure;          // REQUIRED with SameSite=None
  Partitioned;     // CHIPS: per-top-level-site isolation

Google Senior Frontend — SameSite Questions

Q: Chrome plans to deprecate third-party cookies. How does SameSite relate?

SameSite=None cookies ARE third-party cookies when used cross-site. Chrome's Privacy Sandbox replaces them with APIs like CHIPS (Cookies Having Independent Partitioned State), Topics API, and Attribution Reporting. CHIPS uses the Partitioned attribute — the cookie is scoped to the (top-level site, embedded site) pair, preventing cross-site tracking while allowing embedded functionality.

Q: Your OAuth login requires a cross-site redirect. SameSite=Strict breaks it. What's the fix?

Use SameSite=Lax for the session cookie. Lax allows cookies on top-level GET navigations (which is what the OAuth redirect callback is). If you need Strict for maximum security, use a two-cookie approach: a Lax "landing" cookie that triggers re-authentication, and a Strict "session" cookie for actual API access.
