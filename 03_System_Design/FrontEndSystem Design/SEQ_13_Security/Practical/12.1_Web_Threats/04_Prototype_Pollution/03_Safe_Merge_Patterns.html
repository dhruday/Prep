// Available in all modern browsers (Chrome 98+, Firefox 94+, Safari 15.4+)

const userInput = JSON.parse('{"__proto__": {"polluted": true}}');

// ❌ Vulnerable:
const copy1 = JSON.parse(JSON.stringify(userInput));
// __proto__ is preserved → pollution possible if merged

// ✅ Safe:
const copy2 = structuredClone(userInput);
// __proto__ key is NOT copied → pollution impossible

Google Senior Frontend — Safe Patterns

Q: You're building a config system that merges user preferences with defaults. How do you prevent prototype pollution?

1. Schema validation first: only allow known keys (reject any key not in the schema). 2. Use structuredClone() for deep copying user input before merging. 3. Use Object.create(null) for the config store. 4. Merge with Object.keys() iteration, never for...in. 5. ESLint rule to ban for...in across the codebase. At Google: protobuf schemas enforce structure — unknown fields are dropped, making pollution impossible by design.

Q: Should we freeze Object.prototype in production?

Trade-off: Maximum protection vs compatibility risk. Freeze prevents ANY extension of Object.prototype, including polyfills. For new projects without legacy deps: yes, freeze early. For existing projects: audit all dependencies first. Facebook uses a similar approach with their "invariant" checks. Google's Angular team considered it but opted for ESLint rules + code review instead, due to third-party library concerns.
