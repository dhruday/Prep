Clickjacking (UI Redressing)

// Clickjacking: trick user into clicking something invisible

// Attack structure:
// 1. Attacker creates a page with an invisible iframe
// 2. The iframe loads the TARGET site (your app)
// 3. The iframe is positioned over a decoy button
// 4. User thinks they click "Win a Prize!"
// 5. Actually clicking "Delete Account" in hidden iframe

<style>
  /* Attacker's CSS */
  .overlay {
    position: relative;
    width: 500px;
    height: 300px;
  }
  .overlay iframe {
    position: absolute;
    top: 0; left: 0;
    width: 500px;
    height: 300px;
    opacity: 0;        /* invisible! */
    z-index: 2;        /* on top of decoy */
  }
  .decoy-btn {
    position: absolute;
    top: 130px; left: 200px;  /* aligned with target button */
    z-index: 1;
  }
</style>

<div class="overlay">
  <button class="decoy-btn">🎁 Click to win!</button>
  <iframe src="https://victim.com/settings"></iframe>
</div>

Real-World Clickjacking Attacks

// 1. Facebook Like-jacking (2010)
//   Hidden Facebook Like button over "Play Video"
//   Users unknowingly liked spam pages

// 2. Twitter Follow-jacking
//   Hidden Follow button → mass bot followers

// 3. OAuth Authorization
//   Hidden "Authorize App" button
//   User clicks decoy → grants attacker OAuth scope

// 4. Camera/Microphone Access
//   Hidden browser permission dialog
//   User clicks "Allow" without knowing

// 5. Drag-and-Drop Hijacking
//   User drags "image" → actually drags auth token text
//   Dropped into attacker's hidden input field

// Variants:
// - Cursorjacking: Custom cursor offset from real position
// - Scroll-jacking: Scroll iframe to dangerous button
// - Double-click: First click positions, second click triggers

Google Senior Frontend — Clickjacking

Q: How do you prevent clickjacking? Compare all approaches.

(1) X-Frame-Options header — Legacy. Values: DENY (no framing), SAMEORIGIN (only same origin), ALLOW-FROM uri (one origin; deprecated). Limitations: doesn't support multiple origins, no granularity. (2) Content-Security-Policy: frame-ancestors — Modern replacement. frame-ancestors 'none' = DENY, frame-ancestors 'self' = SAMEORIGIN, frame-ancestors https://partner.com = allow specific. Supports multiple origins, wildcards. (3) JavaScript frame-busting — if (top !== self) { top.location = self.location }. Bypassable: attacker uses sandbox="allow-scripts" without allow-top-navigation. Or: X-Frame-Options on attacker's page. Use as defense-in-depth only. (4) SameSite cookies — SameSite=Strict prevents cookies from being sent in iframes from different origins. Without cookies, the iframe request is unauthenticated. Best practice: Use both CSP frame-ancestors AND X-Frame-Options (for old browsers) AND SameSite cookies.
