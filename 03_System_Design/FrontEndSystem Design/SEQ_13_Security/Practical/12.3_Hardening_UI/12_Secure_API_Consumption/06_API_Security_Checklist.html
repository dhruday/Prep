Frontend API Security Checklist

// ═══════ TRANSPORT ═══════
✅ HTTPS for all API calls (no mixed content)
✅ HSTS header with preload
✅ Certificate pinning for mobile apps

// ═══════ AUTHENTICATION ═══════
✅ Bearer tokens in Authorization header (not cookies for APIs)
✅ Short-lived access tokens (5-15 min)
✅ Secure refresh token rotation
✅ Logout revokes all tokens

// ═══════ INPUT ═══════
✅ Client-side validation for UX
✅ Server-side validation for security
✅ Parameterized queries (prevent SQLi)
✅ Input length limits
✅ Content-Type validation

// ═══════ OUTPUT ═══════
✅ Minimal response data (no over-fetching)
✅ Generic error messages (no stack traces)
✅ JSON content type header
✅ No sensitive data in URLs/query strings

// ═══════ PROTECTION ═══════
✅ Rate limiting (per user + per IP)
✅ Request timeouts (AbortController)
✅ CORS properly configured
✅ CSRF protection for cookie-based auth

OWASP API Security Top 10 (2023)

API1: Broken Object Level Authorization (BOLA/IDOR)
  GET /api/users/123 → can access user 456 by changing ID
  Fix: Verify ownership on every request

API2: Broken Authentication
  Weak tokens, no rate limit on login, credential stuffing

API3: Broken Object Property Level Authorization
  PATCH /api/user with { role: "admin" } succeeds
  Fix: Allowlist updatable fields per role

API4: Unrestricted Resource Consumption
  No rate limits, pagination, file size limits

API5: Broken Function Level Authorization
  Regular user can access /api/admin/deleteUser

API6: Unrestricted Access to Sensitive Business Flows
  Bot buying all concert tickets, automated coupon abuse

API7: Server-Side Request Forgery (SSRF)
  API fetches user-provided URL: fetch(userUrl)

API8: Security Misconfiguration
  Default credentials, verbose errors, missing headers

API9: Improper Inventory Management
  Old API versions still running, undocumented endpoints

API10: Unsafe Consumption of APIs
  Trusting third-party API responses without validation

Google Senior Frontend — API Security

Q: Design a secure API client module for a large React app.

Architecture: (1) Centralized API client (apiClient.ts) that wraps fetch. All requests go through it. (2) Interceptors: Request interceptor adds Authorization header from auth store. Response interceptor handles 401 (refresh token), 429 (backoff), 5xx (retry with exponential backoff). (3) Type safety: Generated TypeScript types from OpenAPI spec. Compile-time validation of request/response shapes. (4) Security: Content-Type validation on responses (reject non-JSON). AbortController with default 30s timeout. No credentials: 'include' by default. CSRF token added for mutation requests. (5) Error handling: Map status codes to user-friendly ErrorBoundary messages. Log errors to server with request correlation ID. Never expose raw error messages. (6) Testing: Mock Service Worker (MSW) for integration tests. Contract tests against OpenAPI spec.
