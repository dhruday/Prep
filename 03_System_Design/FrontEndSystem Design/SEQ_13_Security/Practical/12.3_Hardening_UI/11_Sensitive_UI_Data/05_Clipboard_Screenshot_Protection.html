Clipboard & Visual Protection

// 1. PREVENT COPY of sensitive fields
element.addEventListener('copy', e => {
  e.preventDefault();
  // Optionally: set sanitized clipboard data
  e.clipboardData.setData('text/plain', '[PROTECTED]');
});

// 2. CSS-BASED PROTECTION
.sensitive {
  -webkit-user-select: none;  /* prevent text selection */
  user-select: none;
}

// 3. VISIBILITY-BASED REVEAL
// Show data only on hover/focus, blur otherwise
.sensitive-blur {
  filter: blur(5px);
  transition: filter 0.2s;
}
.sensitive-blur:hover { filter: none; }

// 4. CLIPBOARD SANITIZATION on paste
input.addEventListener('paste', e => {
  e.preventDefault();
  const text = e.clipboardData.getData('text/plain');
  const sanitized = DOMPurify.sanitize(text, {ALLOWED_TAGS: []});
  document.execCommand('insertText', false, sanitized);
});

// 5. PRINT PROTECTION
@media print { .sensitive { display: none !important; } }

Honest Limitations

// ⚠️ Client-side protection is COSMETIC, not security

// Can be bypassed:
// 1. DevTools → Elements → read innerHTML directly
// 2. DevTools → Console → getComputedStyle() or textContent
// 3. Browser extensions can override event listeners
// 4. Screenshots can't be prevented by web APIs
// 5. Print-to-PDF bypasses @media print on some browsers
// 6. Accessibility tools (screen readers) read the text
// 7. User can just disable JavaScript

// What client-side protection DOES accomplish:
// ✅ Prevents casual copying (non-technical users)
// ✅ Reduces accidental exposure (shoulder surfing)
// ✅ Shows compliance effort (auditors like it)
// ✅ Log/audit copy attempts (for monitoring)

// Real security = server-side:
// Don't send the full data to the browser in the first place
// Use DRM for truly sensitive documents (but DRM has its own issues)

Google Senior Frontend — Clipboard Security

Q: The compliance team wants to prevent users from copying sensitive data from your web app. What's your approach?

Be honest about limitations while implementing defense-in-depth: (1) Server-side: Don't send full sensitive data. Return masked values by default. Reveal via authenticated endpoint with audit logging. (2) Client UX: Use blur filters for at-rest display (reduce shoulder surfing). Disable user-select on sensitive elements. Intercept copy events to sanitize clipboard content. (3) Monitoring: Log all copy/paste events on sensitive fields. Alert on bulk data extraction patterns. (4) Print: Use @media print to hide sensitive sections. Add watermark with username when printing. (5) Be transparent with compliance: "We can make casual copying difficult and detect/audit extraction attempts, but a determined user with DevTools access can always read what's on their screen. The real control is not sending the data in the first place." This is the mature engineering answer.
