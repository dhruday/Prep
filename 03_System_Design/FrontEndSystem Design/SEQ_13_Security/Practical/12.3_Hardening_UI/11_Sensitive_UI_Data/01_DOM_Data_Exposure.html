Where Secrets Hide in the Frontend

// 1. Hidden form fields
<input type="hidden" name="api_key" value="sk-live-abc123">
// ❌ Visible in DOM inspector, form submissions, network

// 2. Data attributes
<div data-user-ssn="123-45-6789">
// ❌ Readable via element.dataset or querySelectorAll

// 3. JavaScript variables on window
window.__CONFIG__ = { apiKey: "sk-live-abc123", dbUrl: "..." };
// ❌ Any script/extension can read window properties

// 4. Inline scripts in HTML
<script>var SECRET = "my-secret";</script>
// ❌ Visible in page source

// 5. Comments in production HTML/JS
// TODO: Remove before deploy. API key: sk-live-abc123

// 6. Error messages exposing internals
// "Connection failed: postgres://admin:password@db:5432"

// 7. Source maps in production
// .map files expose original source code including comments

Mitigation Strategies

// ✅ 1. Never put secrets in frontend code
//   API keys, DB credentials → server-side only
//   Use BFF proxy for API calls that need secrets

// ✅ 2. Sanitize API responses
//   Server should return only needed fields
//   Never send: password hashes, internal IDs, tokens

// ✅ 3. Use environment variables (server-side)
process.env.API_KEY  // ← never bundle into client code
//   ⚠️ NEXT_PUBLIC_*, REACT_APP_* ARE bundled into client!

// ✅ 4. Remove source maps in production
//   webpack: devtool: false
//   Or upload to error tracking service (Sentry) privately

// ✅ 5. Strip HTML comments in build
//   html-minifier: removeComments: true

// ✅ 6. Audit with browser DevTools
//   Elements tab → search for "key", "token", "secret"
//   Console → check window properties
//   Sources → check for .map files

Google Senior Frontend — Sensitive Data

Q: A code review shows REACT_APP_API_SECRET in the React app. What's the issue?

Critical issue: Any env variable prefixed with REACT_APP_ is embedded into the client bundle at build time. It's in the JavaScript that ships to every user's browser. Anyone can extract it from the bundle (view source, DevTools, or just searching the JS file). Fix: (1) Remove the secret from client code immediately. (2) Create a server-side API route that makes the authenticated call. (3) If it's a publishable key (like Stripe's pk_live), that's fine in the client — but any secret key (sk_live) must never be in frontend code. (4) Add a pre-commit hook or CI check that scans for secrets in client code (tools: truffleHog, detect-secrets, git-secrets).
