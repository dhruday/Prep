Monorepo vs Polyrepo — Key Differences

✅ Monorepo wins

Atomic cross-package commits
Single version of shared deps
Easy code sharing
Refactoring across packages
Unified lint/test/build config
One PR affects related packages

⚠️ Monorepo challenges

CI must be smart (affected only)
Large repo clone time
Tooling learning curve (Nx, Turbo)
Accidental coupling risk
Permissions (all devs see all code)

Nx / Turborepo — Affected builds only

# Nx — only build/test packages affected by changed files
$ nx affected:build --base=main --head=HEAD
# Nx detects: @ds/tokens changed → rebuild @ds/components, web-app, docs
# Skips: @api/orders (no change) — saves 4 minutes

# Turborepo — pipeline with caching
# turbo.json
{
  "pipeline": {
    "build": {
      "dependsOn": ["^build"],  // build deps first
      "outputs": ["dist/**"]
    },
    "test": {
      "dependsOn": ["build"],
      "inputs": ["src/**", "*.test.ts"]
    }
  }
}
# turbo build --filter=@web/app → builds only affected packages
# Remote cache: second run restores from cache (0s rebuild)

Monorepo folder structure (pnpm workspaces)

monorepo/
  packages/
    design-system/       // @ds/components — shared UI components
    tokens/              // @ds/tokens — design tokens
    utils/               // @shared/utils — pure utility functions
    api-client/          // @shared/api — typed API client
  apps/
    web/                 // Main customer-facing Next.js app
    admin/               // Internal admin React app
    docs/                // Storybook / docs site
  pnpm-workspace.yaml
  turbo.json

# pnpm-workspace.yaml
packages:
  - 'packages/*'
  - 'apps/*'

# Install from root — all workspaces share node_modules
$ pnpm install

# Run build only in web app's dependency graph
$ turbo run build --filter=@apps/web
