CSR Request Lifecycle

1
Browser requests URL → Server returns a near-empty HTML shell with a <div id="root">
2
Browser downloads JS bundle (main.js, vendor.js etc.) — this is the "blank screen" phase
3
JS executes → React/Angular/Vue bootstrap, hydrates the root container
4
API calls fire (data fetching inside useEffect / ngOnInit)
5
DOM painted — only now does the user see content (FCP ≈ LCP lags behind SSR)
Key metrics affected:
✦ Large JS bundle → high TBT, poor TTI
✦ No HTML content at FCP → Google deducts SEO points
✦ Excellent for logged-in dashboards (SAP Fiori, Salesforce LWC)

Timeline: 3G connection, 200KB JS bundle

CSR Pros & Cons

✅ Advantages
Rich interactivity after load
Simple static hosting (CDN only)
Full SPA navigation, no page reloads
Ideal for authenticated apps
Easy caching of JS/CSS assets
❌ Disadvantages
Blank screen until JS loads
Poor SEO (empty initial HTML)
Slow FCP on slow networks
Large bundle → high TBT
Accessibility issues (screen readers)

When to use CSR at SAP?

SAP Fiori dashboards, analytics workbench, ERP configuration portals — all benefit from CSR because users are authenticated, SEO is irrelevant, and rich interactivity is paramount. Hruday optimised Fiori bundles from 2.8MB→800KB via lazy routes reducing TTI by 60%.

Typical CSR bootstrap (React)

// index.html — server serves this shell for ALL routes
<!DOCTYPE html>
<html><body>
  <div id="root"></div>   <!-- empty -->
  <script defer src="/main.js"></script>
</body></html>

// main.tsx — client entry point
import { createRoot } from 'react-dom/client';
import App from './App';

createRoot(document.getElementById('root')!).render(<App />);

// App.tsx — data fetched client-side
function Dashboard() {
  const [data, setData] = useState(null);
  useEffect(() => {
    fetch('/api/dashboard')
      .then(r => r.json())
      .then(setData);
  }, []);
  return data ? <DashboardContent data={data} /> : <Spinner />;
}
