Authorization as infrastructure: tiered latency model

Three tiers — choose based on check complexity
Tier 1: JWT claims
90% of checks — <0.1ms — no I/O, in-memory Set.has()
Tier 2: Redis cache
8% of checks — <1ms — single Redis GET, permission Set
Tier 3: OPA sidecar
2% of checks — ~0.5ms — complex ABAC, local socket call
The math: 10M DAU
10M users × 100 API calls/day = 1B checks/day = ~11,600 checks/second. Without caching: 11K DB queries/sec → DB saturates. With 95% cache hit: 580 DB queries/sec → manageable.

Hybrid authorization — tiered dispatch

async authorize(input: AuthzInput): Promise<boolean> {
  // Tier 1: JWT claims — 0ms, handles 90% of checks
  if (input.type === 'simple')
    return jwtClaims.hasPermission(input.permission);

  // Tier 2: Redis cache — <1ms
  if (input.type === 'cached') {
    const cached = await redis.get(`perm:${input.tenantId}:${input.userId}`);
    if (cached) return new Set(cached).has(input.permission);
  }

  // Tier 3: OPA sidecar — ~0.5ms, complex ABAC
  try {
    const result = await opaClient.evaluate(input.policy, input);
    return result.allow === true;
  } catch {
    // Circuit breaker: fail-closed for sensitive ops
    return input.sensitive ? false : true;
  }
}
