Two dimensions: row-level + field-level

Row-Level Security (RLS)
Which records can this user access?
SELECT * FROM invoices
WHERE owner_id = :userId
-- PostgreSQL RLS policy enforces this
-- even if app forgets the WHERE clause
Field-Level Security (FLS)
Which fields within a record are visible?
ViewerDto: { id, amount, status }
AdminDto:  { id, amount, status,
             creditCard, taxId, notes }
// Never expose field in DTO = never in response
IDOR: the #1 broken access control exploit
GET /api/invoices/1235 — attacker increments ID by 1 → accesses another user's invoice. Fix: UUID IDs + ownership check in every query.

IDOR-safe endpoint pattern (NestJS)

    
@Get(':id')
async findOne(
  @Param('id', ParseUUIDPipe) id: string,
  @CurrentUser() user: AuthUser
): Promise<InvoiceDto> {
  const invoice = await this.service.findByIdAndOwner(id, user.id);
  if (!invoice) throw new NotFoundException(); // 404 not 403
  return plainToClass(
    user.hasPermission('invoice:admin') ? InvoiceAdminDto : InvoiceViewerDto,
    invoice,
    { excludeExtraneousValues: true }
  );
}

  

  

    
PostgreSQL Row-Level Security

    
CREATE POLICY invoice_isolation ON invoices
  USING (owner_id = current_setting('app.user_id')::uuid
     OR current_setting('app.is_admin') = 'true');
ALTER TABLE invoices ENABLE ROW LEVEL SECURITY;
