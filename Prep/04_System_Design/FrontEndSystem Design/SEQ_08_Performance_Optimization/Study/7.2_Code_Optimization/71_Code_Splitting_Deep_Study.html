1. Why Code Split?

// Problem: Modern SPAs bundle ALL code into a single file
// A typical React app: 500KB-2MB of JavaScript
// User visits homepage → downloads ALL JS including admin panel, settings, etc.
//
// Impact on performance:
// 1. Download: 500KB gzipped on 3G (1.6Mbps) = ~2.5 seconds
// 2. Parse: V8 parses JS at ~1MB/sec on mobile = 500ms
// 3. Compile: Bytecode compilation adds ~200ms
// 4. Execute: Module initialization, side effects
// Total: 3-4 seconds before page is interactive
//
// Code splitting = load only what's needed for the current route/view
// Split 500KB → 80KB initial + load rest on demand
// Result: TTI drops from 4s to ~1.5s
//
// Webpack/Vite create "chunks" — separate .js files
// Each chunk loaded on demand via dynamic import()

2. How Dynamic import() Works Internally

// import() is an ES2020 spec feature (not webpack-specific)
//
// Static import (build time):
import { Dashboard } from './Dashboard';
// → Bundler includes Dashboard in the main bundle
// → Loaded immediately on page load

// Dynamic import (runtime):
const { Dashboard } = await import('./Dashboard');
// → Bundler creates a SEPARATE chunk for Dashboard
// → Only loaded when this code path executes
// → Returns a Promise that resolves to the module

// Under the hood (webpack):
// 1. Webpack replaces import() with __webpack_require__.e(chunkId)
// 2. Runtime creates a <script> tag pointing to the chunk URL
// 3. Script loads and executes, registering its modules
// 4. Promise resolves with the module exports
//
// Naming chunks:
const mod = await import(/* webpackChunkName: "dashboard" */ './Dashboard');
// Produces: dashboard.abc123.js (instead of random number)

Pattern 1: Route-Based Splitting (React)

import { lazy, Suspense } from 'react';
import { Routes, Route } from 'react-router-dom';

// Each route = separate chunk
const Home = lazy(() => import('./pages/Home'));
const Products = lazy(() => import('./pages/Products'));
const Admin = lazy(() => import('./pages/Admin'));

function App() {
  return (
    <Suspense fallback={<PageSkeleton />}>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/products" element={<Products />} />
        <Route path="/admin/*" element={<Admin />} />
      </Routes>
    </Suspense>
  );
}

Pattern 2: Component-Level Splitting

// Split heavy components that aren't needed on initial render

// Modal — loaded on button click
const HeavyModal = lazy(() => import('./HeavyModal'));

function ProductPage() {
  const [showModal, setShowModal] = useState(false);
  return (
    <>
      <button onClick={() => setShowModal(true)}>View 3D</button>
      {showModal && (
        <Suspense fallback={<ModalSkeleton />}>
          <HeavyModal onClose={() => setShowModal(false)} />
        </Suspense>
      )}
    </>
  );
}

Pattern 3: Prefetching & Preloading Chunks

// Prefetch = download in idle time (low priority)
// Preload = download immediately (high priority)

// webpack magic comments:
const Admin = lazy(() => import(
  /* webpackPrefetch: true */
  './pages/Admin'
));
// Adds: <link rel="prefetch" href="admin.chunk.js">
// Browser downloads during idle time — ready when user navigates

// Hover-based preloading (predictive):
function NavLink({ to, children }) {
  const preloadRef = useRef(false);

  const handleMouseEnter = () => {
    if (!preloadRef.current) {
      preloadRef.current = true;
      // Trigger dynamic import on hover — chunk starts loading
      if (to === '/admin') import('./pages/Admin');
      if (to === '/products') import('./pages/Products');
    }
  };

  return (
    <Link to={to} onMouseEnter={handleMouseEnter}>{children}</Link>
  );
}

// Adaptive loading — only prefetch on fast connections
if (navigator.connection?.effectiveType !== 'slow-2g') {
  import('./pages/Products'); // Prefetch
}

FAANG Interview Questions

Q1: Explain code splitting and why it's important for performance.
Code splitting breaks your JavaScript bundle into smaller chunks loaded on demand. Without it, users download all application code upfront — including pages they may never visit. The impact is threefold: download time (500KB over slow 4G takes ~2.5s), parse time (mobile CPUs parse JS at ~1MB/sec), and execution time (module initialization blocks the main thread). By splitting at route boundaries, only the current route's code loads initially — reducing initial JS from 500KB to maybe 80KB, cutting TTI by 60-70%. Implementation: use dynamic import() which bundlers (webpack/Vite) recognize as split points, creating separate chunk files. React provides React.lazy() which wraps dynamic import for component-level splitting with Suspense for loading states.
Follow-up: What's the difference between route-level and component-level splitting? When would you use each?
Q2: How would you implement prefetching for code-split chunks?
Three strategies ranked by intelligence: (1) webpack prefetch comments — add /* webpackPrefetch: true */ to import(), which injects <link rel="prefetch"> into the document. Browser downloads during idle time with lowest priority. Simple but not smart — prefetches everything. (2) Hover-based preloading — trigger the dynamic import when user hovers over a navigation link. Average hover-to-click time is 200-400ms, enough to start downloading the chunk. This is what Next.js does with its Link component. (3) Predictive prefetching — use analytics data to predict which page the user will visit next based on the current page. Google's Guess.js does this with Google Analytics data to build a Markov chain of navigation probability. Only prefetch routes with >60% transition probability. Additionally, I'd check navigator.connection.saveData and effectiveType — skip prefetching on data-saver mode or slow connections.
Follow-up: How does Next.js handle code splitting differently from Create React App?
Q3: What are the tradeoffs of aggressive code splitting?
Over-splitting has real costs. (1) Request waterfall — too many tiny chunks means many sequential HTTP requests, especially on HTTP/1.1 (limited to 6 parallel connections). Each chunk has request overhead (DNS, TCP, TLS if not HTTP/2). (2) Chunk loading latency on navigation — users see loading spinners between routes instead of instant transitions. (3) Duplicate code — shared dependencies between chunks get duplicated unless properly configured with splitChunks. (4) Cache invalidation complexity — more chunks = more cache entries to manage. Balance: split at route boundaries (big wins, few chunks), identify components over 30KB for component-level splitting, and use webpack's splitChunks.cacheGroups to extract shared vendor code into a common chunk. The goal is fewer than 10 chunks per route, with the initial chunk under 170KB gzipped.

webpack splitChunks Configuration

// webpack.config.js — Production-grade splitting
module.exports = {
  optimization: {
    splitChunks: {
      chunks: 'all',
      maxInitialRequests: 10,    // Max parallel requests for initial load
      maxAsyncRequests: 15,      // Max parallel requests for on-demand
      minSize: 20000,             // 20KB min chunk size
      cacheGroups: {
        // React core — rarely changes, long cache
        react: {
          test: /[\\/]node_modules[\\/](react|react-dom|scheduler)[\\/]/,
          name: 'react-vendor',
          priority: 30,
          chunks: 'all',
        },
        // Other vendors — change occasionally
        vendors: {
          test: /[\\/]node_modules[\\/]/,
          name: 'vendors',
          priority: 20,
          chunks: 'all',
          minSize: 50000,
        },
        // Shared code between routes
        common: {
          minChunks: 2,  // Used in 2+ chunks
          name: 'common',
          priority: 10,
          reuseExistingChunk: true,
        },
      },
    },
    runtimeChunk: 'single',  // Separate runtime for long-term caching
  },
};

// vite.config.ts
export default defineConfig({
  build: {
    rollupOptions: {
      output: {
        manualChunks: {
          'react-vendor': ['react', 'react-dom'],
          'router': ['react-router-dom'],
          'ui': ['@radix-ui/react-dialog', '@radix-ui/react-tooltip'],
        },
      },
    },
    chunkSizeWarningLimit: 250, // Warn if chunk > 250KB
  },
});

Production Checklist

✅ Route-level splitting with React.lazy + Suspense
✅ Heavy components split (modals, charts, editors > 30KB)
✅ Vendor chunk separated (react-vendor, other-vendors)
✅ Common chunk for shared code between routes
✅ Prefetch likely-next-route chunks on hover/idle
✅ Loading skeletons for all Suspense boundaries
✅ Error boundaries wrapping lazy components
✅ Bundle analyzer run on each PR (webpack-bundle-analyzer)
✅ HTTP/2 enabled on CDN for parallel chunk loading
✅ Service worker precaches critical chunks
