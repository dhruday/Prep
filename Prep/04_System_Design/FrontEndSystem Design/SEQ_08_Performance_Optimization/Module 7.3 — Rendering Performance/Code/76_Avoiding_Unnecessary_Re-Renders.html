The 5 most common causes of unnecessary re-renders

1. New object/array literals as props
style={{ color: 'red' }} creates a new object reference each render → React.memo sees "new prop" → re-renders. Same for inline arrays as deps.
2. Unstable function references
onClick={()=>doX()} creates a new function each render. Memo'd children see new prop → bypass memo. Fix: useCallback.
3. Context value changes
All consumers of a Context re-render when provider value changes — even if they don't use the changed slice. Fix: split contexts or use selector pattern (useSyncExternalStore / Zustand).
4. Wide Redux selectors
useSelector(state => state) subscribes to the entire store. Any slice update triggers re-render. Fix: granular selectors + reselect memoisation.
5. State lifted too high
Tooltip open/close state in root component causes full tree re-render. Fix: co-locate state as close to the consumer as possible.

Fix strategies — ranked by effort

1. Co-locate state (free) — move state to the deepest common ancestor that needs it. A tooltip state that lives in the button itself doesn't re-render the whole page.
2. React.memo — wraps components whose props rarely change (tables, row items, sidebar). Combined with useCallback for handlers and useMemo for derived objects.
3. Granular Redux selectors — useSelector(s => s.orders.list) not useSelector(s => s). Use createSelector (reselect) for derived data — returns same reference if inputs unchanged.
4. Split Context — separate ThemeContext from UserContext from DataContext. A theme change won't re-render data consumers.
5. Angular OnPush strategy — component only checks for changes when @Input reference changes or an async pipe emits. Cuts CD cycles by 80%+ in SAP dashboard experience.

Prevention patterns in TypeScript

// ─── Granular selector (reselect) ───
const selectPendingOrders = createSelector(
  (s: RootState) => s.orders.list,
  // only recomputes when list reference changes
  list => list.filter(o => o.status === 'pending')
);
// In component — re-renders only when pendingOrders changes
const pending = useSelector(selectPendingOrders);

// ─── Stable callback + memo'd child ───
const Dashboard = () => {
  const dispatch = useDispatch();
  const handleApprove = useCallback(
    (id: string) => dispatch(approveOrder(id)),
    [dispatch]
  );
  return <OrderTable onApprove={handleApprove} />; // memo'd
};

// ─── Angular OnPush ───
@Component({
  selector: 'app-order-row',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `<div>{{order.id}}</div>`
})
export class OrderRowComponent {
  @Input() order!: Order; // only checks reference
}

// ─── Zustand slice selector (no unnecessary re-renders) ───
const count = useStore(s => s.cart.count); // re-renders only when count changes
