Why virtualization matters

Rendering a 10 000-row table puts 10 000 DOM nodes in memory simultaneously. Each node has style, layout, event listeners. At SAP we had an order table with 5 000 rows — first paint took 4.2 s and scroll was janky at 15 fps.

Without virtualization
  • 10 000 DOM nodes always in memory
  • Layout thrash on every scroll event
  • First paint ≥ 4 s
  • Memory: 400 MB+
With virtualization
  • Only ~20 DOM nodes ever mounted
  • Position via transform/top — no relayout
  • First paint 80 ms
  • Memory: ~8 MB

Key idea: Maintain a "window" of visible rows. As user scrolls, recycle DOM nodes by updating their content and absolute Y position. Total container height = itemCount × itemHeight (simulates full scroll bar).

react-window + TanStack Virtual patterns

// ─── react-window FixedSizeList ───
import { FixedSizeList } from 'react-window';

const Row = ({ index, style, data }: ListChildComponentProps) => (
  <div style={style}>{data[index].name}</div>
);

<FixedSizeList
  height={600} width="100%" itemCount={items.length}
  itemSize={40}  // px per row
  overscanCount={3} itemData={items}
>{Row}</FixedSizeList>

// ─── @tanstack/react-virtual (hook-based) ───
const parentRef = useRef<HTMLDivElement>(null);
const virtualizer = useVirtualizer({
  count: rows.length,
  getScrollElement: () => parentRef.current,
  estimateSize: () => 40,
  overscan: 5,
});

return (
  <div ref={parentRef} style={{ height: 600, overflow: 'auto' }}>
    <div style={{ height: virtualizer.getTotalSize() }}>
      {virtualizer.getVirtualItems().map(item => (
        <div key={item.key}
          style={{ position: 'absolute', top: item.start, height: item.size }}>
          {rows[item.index].name}
        </div>
      ))}
    </div>
  </div>
);

// ─── Angular CDK Virtual Scrolling ───
// template
<cdk-virtual-scroll-viewport itemSize="40" style="height:600px">
  <div *cdkVirtualFor="let item of items">{{item.name}}</div>
</cdk-virtual-scroll-viewport>
