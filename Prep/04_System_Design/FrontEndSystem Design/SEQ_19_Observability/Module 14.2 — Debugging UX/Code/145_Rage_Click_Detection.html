Rage clicks — the canary for broken or frustrating UX

A rage click is 3+ rapid clicks on the same element within ~1 second — a clear signal the user is frustrated (button appears unresponsive, loading state is invisible, UI is broken). Tools like FullStory, Hotjar, and Sentry Replay detect rage clicks automatically. They surface the top rage-clicked elements in your app so you can prioritize fixes. Frustration signals = rage clicks + dead clicks + error clicks + quick backs. At SAP, product health dashboards include frustration signal rank per feature.

Rage click detector implementation + frustration analytics

// ─── Custom rage click detector ───
const RAGE_THRESHOLD = 3;
const RAGE_WINDOW_MS  = 1000;
const clickLog = new Map<string, number[]>();

document.addEventListener('click', (e) => {
  const el    = e.target as Element;
  const key   = el.closest('[data-track]')?.getAttribute('data-track') || el.tagName;
  const now   = Date.now();
  const times = (clickLog.get(key) || []).filter(t => now - t < RAGE_WINDOW_MS);
  times.push(now);
  clickLog.set(key, times);

  if (times.length >= RAGE_THRESHOLD) {
    analytics.track('rage_click', {
      element: key,
      clickCount: times.length,
      path: location.pathname
    });
    reportToSentry({ element: key, type: 'rage_click' });
    clickLog.delete(key);  // reset after reporting
  }
}, { capture: true });

// ─── Dead click detector ───
let domChanged = false;
new MutationObserver(() => { domChanged = true; }).observe(
  document.body, { childList: true, subtree: true, attributes: true }
);
document.addEventListener('click', () => {
  domChanged = false;
  requestAnimationFrame(() => {
    if (!domChanged) analytics.track('dead_click', { path: location.pathname });
  });
}, { capture: true });
