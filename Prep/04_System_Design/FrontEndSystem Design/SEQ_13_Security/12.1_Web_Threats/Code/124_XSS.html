XSS: attacker injects malicious JavaScript into pages viewed by other users

XSS is the #3 OWASP vulnerability. It has three forms: (1) Stored XSS — payload saved in DB (e.g., comment field), served to all future visitors; (2) Reflected XSS — payload in URL/query param, reflected back in response; (3) DOM-based XSS — payload read from URL hash/fragment and written to DOM via innerHTML in client JS. Impact: session hijacking, credential theft, keylogging, redirects.

Stored XSS
Attacker stores payload in DB. All visitors load script. Most dangerous — persists.
Reflected XSS
Payload in URL. Victim must click malicious link. Phishing-enabled.
DOM-based XSS
Client JS reads location.hash → writes to innerHTML. Pure client-side, no server.

✅ Safe rendering — textContent vs innerHTML

❌ Vulnerable (innerHTML)
div.innerHTML = userInput
// If userInput = '<img src=x onerror=steal()>'
// → script executes!
✅ Safe (textContent)
div.textContent = userInput
// Renders as text, never executes
// "<img>" shows literally

DOMPurify + React safe patterns

// ─── Safe HTML rendering with DOMPurify ───
import DOMPurify from 'dompurify';

function SafeHtml({ html }: { html: string }) {
  const clean = DOMPurify.sanitize(html, {
    ALLOWED_TAGS: ['b', 'i', 'a', 'p'],
    ALLOWED_ATTR: ['href']
  });
  return <div dangerouslySetInnerHTML={{ __html: clean }} />;
}

// ─── CSP header (Next.js) ───
// In _document.tsx or headers config:
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-{NONCE}';  // per-request nonce
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  connect-src 'self' https://api.app.com;
  frame-ancestors 'none';

// ─── Trusted Types (Chrome 83+) ───
if (window.trustedTypes?.createPolicy) {
  const policy = trustedTypes.createPolicy('default', {
    createHTML: (input) => DOMPurify.sanitize(input)
  });
}
