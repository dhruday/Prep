Passkey UX Guidelines

// 1. DISCOVERY — Let users know passkeys exist
//   Show "Create a passkey" prompt after successful password login
//   Don't force it — let users opt in

// 2. CREATION — Make it simple
//   "Create a passkey to sign in faster next time"
//   One button, one biometric prompt, done
//   Show success confirmation with device info

// 3. SIGN IN — Conditional UI preferred
//   Passkey appears in autofill alongside saved passwords
//   No separate "Sign in with passkey" step needed
//   Fallback: dedicated button for passkey sign-in

// 4. MANAGEMENT — credential inventory
//   Show registered passkeys in security settings
//   Display: device name, creation date, last used
//   Allow deletion (with re-authentication)

// 5. RECOVERY — always have a fallback
//   Password, recovery codes, email link, backup passkey
//   Never lock users out if they lose their device

Migration Strategy

// Phase 1: ADD Passkey Support (keep everything else)
//   - Add WebAuthn registration in account settings
//   - Add passkey sign-in alongside password form
//   - Prompt to create passkey after password login
//   Duration: 3-6 months

// Phase 2: PREFER Passkeys
//   - Make passkey the default sign-in method
//   - Move password to "Other sign-in methods"
//   - Enable conditional UI (autofill)
//   - Increase passkey creation prompts
//   Duration: 6-12 months

// Phase 3: PASSWORD-OPTIONAL
//   - Allow users to remove their password
//   - Require multiple passkeys before allowing removal
//   - Recovery: backup codes, security key, trusted device
//   Duration: 12+ months

// Metrics to track:
//   - Passkey creation rate (% of active users)
//   - Passkey sign-in rate vs password sign-in
//   - Sign-in success rate (compare passkey vs password)
//   - Support tickets related to passkeys

Login Form with Progressive Enhancement

// The complete progressive enhancement pattern:

async function initAuth() {
  const capabilities = await detectCapabilities();

  if (capabilities.conditionalUI) {
    // Best: Start conditional mediation (autofill passkeys)
    startConditionalAuth();
    showPasswordForm(); // Still show form as fallback
  } else if (capabilities.platformAuth) {
    // Good: Show explicit passkey button
    showPasskeyButton();
    showPasswordForm();
  } else if (capabilities.webauthn) {
    // OK: Security key support only
    showSecurityKeyOption();
    showPasswordForm();
  } else {
    // Baseline: Password only
    showPasswordForm();
  }
}

async function detectCapabilities() {
  const webauthn = !!window.PublicKeyCredential;
  let platformAuth = false, conditionalUI = false;

  if (webauthn) {
    platformAuth = await PublicKeyCredential
      .isUserVerifyingPlatformAuthenticatorAvailable();
    if (PublicKeyCredential.isConditionalMediationAvailable) {
      conditionalUI = await PublicKeyCredential
        .isConditionalMediationAvailable();
    }
  }
  return { webauthn, platformAuth, conditionalUI };
}

Google Senior Frontend — Passkey UX

Q: Design the login page for a banking app that supports passkeys, passwords, and MFA.

Layout: (1) Username input with autocomplete="username webauthn" — enables conditional UI. Passkeys and passwords both appear in autofill. (2) On focus, start conditional mediation. If user selects passkey → authenticate directly (skip password field). (3) If user types username and submits → show password field. (4) After password → require MFA (TOTP or push notification). (5) "Use security key" link below form for hardware key users. (6) After successful password login → "Secure your account with a passkey" prompt. (7) For banking: require userVerification: "required" (always biometric/PIN). Don't accept UV=false. (8) Session: HttpOnly cookie, 15-min idle timeout, absolute 8-hour max. (9) High-risk operations (transfers) → re-authenticate with passkey even if session is valid.
