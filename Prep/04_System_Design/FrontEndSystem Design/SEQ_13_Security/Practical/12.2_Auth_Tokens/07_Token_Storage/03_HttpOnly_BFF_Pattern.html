Backend-for-Frontend (BFF) Token Pattern

// THE PROBLEM:
// SPA needs access tokens to call APIs
// Storing tokens in the browser = attack surface

// THE BFF SOLUTION:
// The token NEVER touches the browser
// A same-origin backend proxy holds the token

// Flow:
// 1. User logs in → BFF authenticates with auth server
// 2. BFF receives access_token + refresh_token
// 3. BFF stores tokens server-side (session/Redis)
// 4. BFF sets HttpOnly session cookie for the browser
// 5. SPA calls BFF API (cookie auto-sent)
// 6. BFF attaches the access_token to upstream API calls
// 7. SPA never sees the access_token!

// Browser ←(cookie)→ BFF ←(access_token)→ API

Benefits:
✅ Tokens never in browser — immune to XSS token theft
✅ HttpOnly + SameSite cookie — no XSS or CSRF
✅ Token rotation handled server-side
✅ Can add extra security (IP binding, rate limiting)
✅ Token audience/scope stays between BFF and API

Google Senior Frontend — BFF Pattern

Q: When should you use BFF vs in-memory tokens?

BFF when: (1) High-security apps (banking, healthcare, government). (2) You have SSR capability (Next.js, Nuxt.js). (3) You need to hide API tokens/keys from the browser entirely. (4) Complex OAuth flows with multiple token exchanges. In-memory when: (1) Simpler apps without SSR backend. (2) Static SPAs deployed to CDN. (3) Mobile API reuse (same API for web and mobile). Google's approach: Many Google services use BFF — the web frontend talks to a same-origin BFF that handles auth and proxies to backend services. This is why you rarely see Bearer tokens in Google web app network traffic.

Q: What's the performance cost of BFF?

Every API call adds one network hop (browser → BFF → API). Mitigation: (1) Deploy BFF close to API servers (same datacenter/VPC). (2) BFF can batch multiple API calls into one. (3) BFF can cache responses. (4) Use HTTP/2 multiplexing between BFF and APIs. (5) BFF enables server-side rendering for initial page load. The latency cost is typically 1-5ms per hop in the same cloud region — negligible compared to the security benefits.
