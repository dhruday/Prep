Web Crypto API Overview

// Web Crypto API — browser-native cryptography
// Available as window.crypto.subtle (SubtleCrypto)
// Runs OUTSIDE the main thread (no blocking)
// Cannot export CryptoKey as raw bytes (extractable: false)

// Key operations:
crypto.subtle.generateKey()   // Generate new key
crypto.subtle.encrypt()       // AES-GCM, RSA-OAEP
crypto.subtle.decrypt()       // Decrypt ciphertext
crypto.subtle.sign()          // HMAC, RSA-PSS, ECDSA
crypto.subtle.verify()        // Verify signature
crypto.subtle.digest()        // SHA-256, SHA-384, SHA-512
crypto.subtle.deriveKey()     // PBKDF2, HKDF
crypto.subtle.wrapKey()       // Encrypt a key with another key

// Use case: Encrypt sensitive data before storing in localStorage
// The key stays in CryptoKey object — XSS can't extract raw bytes
// (when extractable: false)

IndexedDB + Non-Extractable Keys

// The most secure client-side key storage pattern:
// 1. Generate non-extractable AES key
const key = await crypto.subtle.generateKey(
  { name: 'AES-GCM', length: 256 },
  false,  // ← extractable: false — CANNOT be exported!
  ['encrypt', 'decrypt']
);

// 2. Store key in IndexedDB (survives page reload)
// IndexedDB can store CryptoKey objects natively
const db = await openDB('keys', 1);
await db.put('keyStore', key, 'encryptionKey');

// 3. Use the key to encrypt tokens before localStorage
const iv = crypto.getRandomValues(new Uint8Array(12));
const encrypted = await crypto.subtle.encrypt(
  { name: 'AES-GCM', iv },
  key,
  new TextEncoder().encode(token)
);
localStorage.setItem('token', btoa(encrypted));

// ⚠️ Limitation: XSS can still USE the key to decrypt
// But it CANNOT export the raw key bytes
// This prevents offline attacks and key exfiltration

Google Senior Frontend — Crypto Storage

Q: Is encrypting tokens in localStorage a good security practice?

It's defense in depth, not a primary defense. If XSS is present, the attacker can call crypto.subtle.decrypt() with the non-extractable key. The value of encryption: (1) Prevents simple localStorage theft (browsing DevTools). (2) Non-extractable keys can't be exfiltrated for offline attacks. (3) Adds complexity for the attacker. But the real defense is preventing XSS in the first place. Encryption of stored tokens is most useful for: offline apps that must store tokens, high-security environments with multiple defense layers, compliance requirements. For most SPAs: in-memory + HttpOnly refresh cookie is simpler and more effective.
