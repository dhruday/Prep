What are Trusted Types?

Trusted Types is a W3C web spec (originated at Google) that prevents DOM XSS by requiring all dangerous sink assignments to go through a policy. Instead of assigning raw strings to innerHTML, you must create a TrustedHTML object through a policy function that sanitizes the input.

// WITHOUT Trusted Types (vulnerable):
element.innerHTML = userInput;  // any string works → XSS possible

// WITH Trusted Types (CSP: require-trusted-types-for 'script'):
element.innerHTML = userInput;  // TypeError! Raw string not allowed

// You MUST create a policy first:
const policy = trustedTypes.createPolicy('sanitizer', {
  createHTML: (input) => DOMPurify.sanitize(input)
});
element.innerHTML = policy.createHTML(userInput);  // ✅ TrustedHTML type

Three Trusted Types

// TrustedHTML  → innerHTML, outerHTML, insertAdjacentHTML
// TrustedScript → eval(), setTimeout(string), script.text  
// TrustedScriptURL → script.src, iframe.src, fetch()

// CSP to enable enforcement:
Content-Security-Policy: require-trusted-types-for 'script';

// CSP to allow specific policy names:
Content-Security-Policy: trusted-types sanitizer default;

Implementing Trusted Types in Production

// Step 1: Deploy in report-only mode first
Content-Security-Policy-Report-Only: 
  require-trusted-types-for 'script';
  trusted-types sanitizer default;
  report-uri /csp-report;

// Step 2: Create a default policy (catches all unmodified code)
if (typeof trustedTypes !== 'undefined') {
  trustedTypes.createPolicy('default', {
    createHTML: (s) => DOMPurify.sanitize(s),
    createScript: () => { throw new Error('Scripts not allowed'); },
    createScriptURL: (s) => {
      const url = new URL(s, location.origin);
      if (url.origin === location.origin) return s;
      throw new Error(`Blocked: ${s}`);
    }
  });
}

Google's Trusted Types Deployment

• Google Search, Gmail, YouTube, Maps all use Trusted Types in enforcement mode

• 9 out of 10 DOM XSS bugs are caught by Trusted Types before they reach production

• Google wrote codemods to auto-migrate 500K+ innerHTML call sites → TrustedHTML policies

• Frameworks like Angular have built-in Trusted Types support (DomSanitizer)

• React has partial support — dangerouslySetInnerHTML triggers Trusted Types in report mode

Google Senior Frontend — Trusted Types Questions

Q: How do Trusted Types complement CSP?

CSP with nonces prevents injection of NEW script elements. Trusted Types prevents EXISTING scripts from being tricked into DOM XSS (via innerHTML, eval, etc.). Together they provide complete coverage: CSP handles reflected/stored XSS, Trusted Types handles DOM-based XSS.

Q: What's the "default" policy and why is it powerful?

The 'default' policy is a catch-all: any code that tries to assign a raw string to a sink goes through this policy automatically. This lets you deploy Trusted Types incrementally — the default policy sanitizes everything, then you create stricter named policies for specific code paths. It's how Google migrated massive codebases without rewriting every innerHTML call.

Q: Browser support for Trusted Types?

Chromium-based browsers (Chrome, Edge) support enforcement. Firefox supports it behind a flag. Safari does not yet support it. For cross-browser, use the polyfill in report-only mode, and serve the CSP header only to Chromium browsers (via User-Agent detection).
