What is Prototype Pollution?

Prototype Pollution is a JavaScript vulnerability where an attacker can inject properties into Object.prototype, affecting ALL objects in the application. Since every object inherits from Object.prototype, a single pollution can corrupt the entire runtime.

// The attack vector — polluting Object.prototype:
const obj = {};
obj.__proto__.isAdmin = true;

// Now EVERY object in the app has isAdmin === true:
const user = {};
console.log(user.isAdmin); // true! ← pollution

// More dangerous with JSON.parse + recursive merge:
const payload = JSON.parse('{"__proto__": {"isAdmin": true}}');
merge({}, payload); // pollutes Object.prototype

Attack Surface

// Three common paths to prototype pollution:

// 1. Unsafe recursive merge/extend:
function merge(target, source) {
  for (let key in source) {
    if (typeof source[key] === 'object') {
      target[key] = merge(target[key] || {}, source[key]);
    } else {
      target[key] = source[key]; // key = "__proto__" → pollutes!
    }
  }
}

// 2. Property path assignment:
setPath(obj, "__proto__.isAdmin", true);

// 3. Direct __proto__ access:
obj["__proto__"]["polluted"] = true;

🔬 V8 Prototype Chain Internals

Hidden Classes (Maps): V8 assigns a hidden class to each object, tracking its shape (property names, offsets). When you access obj.isAdmin and it's not on obj itself, V8 walks the prototype chain: obj → Object.prototype. If Object.prototype has been polluted, V8 finds "isAdmin" there.

Inline Caches (ICs): V8 caches property lookup results. After pollution, ICs for "isAdmin" may still point to the old (non-polluted) hidden class. V8 eventually invalidates these, but there's a brief window of inconsistency.

__proto__ vs Object.getPrototypeOf: __proto__ is a getter/setter on Object.prototype. It's a legacy mechanism. Object.getPrototypeOf() and Object.setPrototypeOf() are the modern APIs. Using __proto__ as a key in JSON enables the attack because JSON.parse treats it as a regular property.

Object.create(null): Creates an object with NO prototype. obj.__proto__ is undefined. This is the strongest defense — no prototype to pollute.

Google Senior Frontend — Prototype Pollution

Q: How can prototype pollution lead to XSS?

If a template engine or DOM library checks obj.innerHTML or obj.srcdoc without own-property check, an attacker can pollute Object.prototype with those properties. Example: jQuery's $.extend was vulnerable — polluting __proto__.srcdoc could inject HTML into iframes. Lodash merge had CVEs for the same reason. The chain: prototype pollution → gadget in framework code → XSS execution.

Q: How do you prevent prototype pollution at scale?

1. Object.freeze(Object.prototype) — prevents ALL modifications. But may break some libraries. 2. Use Map instead of plain objects for key-value stores. 3. ESLint rule no-proto to ban __proto__ usage. 4. Use structuredClone() instead of JSON.parse(JSON.stringify()) — it doesn't have __proto__ issues. 5. For merge functions: check with hasOwnProperty and reject __proto__, constructor, prototype keys. At Google: Closure Library's goog.object.extend is prototype-pollution-safe.
