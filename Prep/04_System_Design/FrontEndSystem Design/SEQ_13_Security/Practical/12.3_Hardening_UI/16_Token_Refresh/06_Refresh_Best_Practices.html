Token Refresh Best Practices

// ═══ ACCESS TOKEN ═══
✅ Short lifetime: 5-15 minutes
✅ Stored in memory only (not localStorage)
✅ Sent as Authorization: Bearer header
✅ Stateless JWT (no server-side tracking)
✅ Include: userId, roles, exp, iat, jti

// ═══ REFRESH TOKEN ═══
✅ HttpOnly Secure SameSite=Strict cookie
✅ OR: Encrypted in secure storage (mobile)
✅ Rotation: new refresh token on every use
✅ Family tracking for theft detection
✅ Grace period: 30s for lost-response recovery
✅ Absolute expiry: 7-30 days max
✅ Bound to: user-agent, IP range (optional)

// ═══ CLIENT ═══
✅ Proactive refresh at 75% of access token lifetime
✅ Request queue: deduplicate concurrent refreshes
✅ Multi-tab sync via BroadcastChannel
✅ Graceful degradation: redirect to login on failure
✅ AbortController for refresh timeout (10s)

// ═══ SERVER ═══
✅ Rate limit refresh endpoint (5/min per user)
✅ Reuse detection → revoke entire family
✅ Audit log every refresh event
✅ Support forced logout (revoke all families)

Server-Side Refresh Implementation

// Express.js refresh endpoint
app.post('/api/auth/refresh', async (req, res) => {
  const refreshToken = req.cookies.refreshToken 
    || req.body.refreshToken;
  
  if (!refreshToken) {
    return res.status(401).json({ error: 'No refresh token' });
  }

  const stored = await db.findRefreshToken(refreshToken);
  
  if (!stored || stored.revoked) {
    return res.status(401).json({ error: 'Invalid token' });
  }

  // REUSE DETECTION
  if (stored.used) {
    // Theft detected! Revoke entire family
    await db.revokeTokenFamily(stored.familyId);
    await alertSecurity(stored.userId, 'token_reuse');
    return res.status(401).json({ error: 'Token reuse detected' });
  }

  // Mark old token as used
  await db.markTokenUsed(stored.id);

  // Generate new pair
  const accessToken = jwt.sign(
    { userId: stored.userId, role: stored.role },
    SECRET, { expiresIn: '15m' }
  );
  const newRefresh = await db.createRefreshToken({
    userId: stored.userId,
    familyId: stored.familyId, // same family
  });

  res.cookie('refreshToken', newRefresh.token, {
    httpOnly: true, secure: true,
    sameSite: 'strict', maxAge: 7 * 24 * 60 * 60 * 1000
  });
  res.json({ accessToken });
});

Google Senior Frontend — Complete Auth Design

Q: Design the auth system for a Google-scale app.

Architecture: (1) BFF pattern (Backend for Frontend): Thin server between SPA and API. BFF holds refresh token in server-side session. SPA gets short access tokens only. No sensitive tokens in browser. (2) Token details: Access: 10-min JWT with userId, role, scopes. Refresh: opaque token (not JWT) stored server-side, 7-day expiry, rotated on use. (3) Multi-device: Each device gets its own token family. Revoking one device doesn't affect others. "Sign out all devices" revokes all families. (4) Monitoring: Prometheus metrics: refresh_rate, reuse_detection_count, refresh_failure_rate. Alert on: spike in reuse detection (mass token theft), refresh rate > 10x normal (automated attack), single user refreshing from multiple IPs simultaneously. (5) Graceful degradation: If auth service is down: accept access tokens until they expire (stateless). Queue refreshes with exponential backoff. Show degraded UI after 3 failed retries.
