CSP Report-Only Mode

// Report-Only: logs violations WITHOUT blocking resources
// Perfect for testing CSP before enforcement

// Enforcing (blocks violations):
Content-Security-Policy: script-src 'self'; report-uri /csp-report

// Report-only (logs but doesn't block):
Content-Security-Policy-Report-Only: script-src 'self'; report-uri /csp-report

// Deployment strategy:
// Week 1: Deploy Report-Only, collect violations
// Week 2: Fix legitimate sources (add to policy)
// Week 3: Reduce violations to near-zero
// Week 4: Switch to enforcing mode
// Ongoing: Keep report-uri for monitoring

// You can run BOTH simultaneously:
Content-Security-Policy: default-src 'self'
Content-Security-Policy-Report-Only: default-src 'self'; script-src 'self' 'nonce-abc'

// Modern: Use report-to instead of report-uri
Report-To: {"group":"csp","max_age":86400,
  "endpoints":[{"url":"https://example.com/csp-report"}]}
Content-Security-Policy: default-src 'self'; report-to csp

Violation Report Format

// Browser sends POST to report-uri with this JSON:
{
  "csp-report": {
    "document-uri": "https://example.com/page",
    "referrer": "",
    "violated-directive": "script-src",
    "effective-directive": "script-src",
    "original-policy": "script-src 'self'; report-uri /csp",
    "blocked-uri": "https://evil.com/malware.js",
    "status-code": 200,
    "source-file": "https://example.com/page",
    "line-number": 42,
    "column-number": 8
  }
}

// Server-side handler (Express):
app.post('/csp-report', express.json({ type: 'application/csp-report' }),
  (req, res) => {
    const report = req.body['csp-report'];
    logger.warn('CSP Violation', {
      blockedUri: report['blocked-uri'],
      directive: report['violated-directive'],
      page: report['document-uri']
    });
    res.sendStatus(204);
  }
);

Google Senior Frontend — CSP Deployment

Q: How would you deploy CSP for a large existing application?

Phase 1 — Audit: (1) Use browser DevTools Network tab to catalog all resource origins. (2) Audit inline scripts, eval() usage, style attributes. (3) Check third-party analytics, ads, widgets. Phase 2 — Report-Only: Deploy Content-Security-Policy-Report-Only with a permissive policy. Route reports to a pipeline (e.g., report-uri.com or custom endpoint → ElasticSearch). Categorize violations: legitimate (add to policy), malicious (XSS attempt), browser extensions (ignore). Phase 3 — Tighten: Remove 'unsafe-inline' by converting to nonces/hashes. Remove 'unsafe-eval' by eliminating eval(). Migrate from URL allowlists to nonce + strict-dynamic. Phase 4 — Enforce: Switch to Content-Security-Policy. Keep report-uri active. Set up alerts for spike in violations (potential attack or regression). Google's scale: millions of reports/day. Sample 1%, deduplicate by page+directive+blocked-uri, aggregate into dashboards.
