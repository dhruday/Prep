Data Masking Strategies

// Masking = showing partial data for recognition without full exposure

// Credit Card: 4111 1111 1111 1111 → •••• •••• •••• 1111
// SSN: 123-45-6789 → •••-••-6789
// Email: alice@example.com → a***e@example.com
// Phone: +1 (555) 123-4567 → +1 (555) •••-4567
// Bank Account: 1234567890 → ••••••7890

// Key principles:
// 1. Show enough to IDENTIFY (last 4 digits)
// 2. Hide enough to PROTECT (mask everything else)
// 3. Mask on the SERVER, not just the client
//    (client masking is cosmetic, not security)
// 4. Log the MASKED version, never the full value
// 5. Full value only when explicitly needed (and audited)

Server-Side Response Filtering

// ❌ Bad: Send full user object
app.get('/api/user/:id', (req, res) => {
  const user = db.getUser(req.params.id);
  res.json(user); // Includes password hash, SSN, internal IDs!
});

// ✅ Good: Explicit field selection
app.get('/api/user/:id', (req, res) => {
  const user = db.getUser(req.params.id);
  res.json({
    id: user.publicId,          // not internal DB ID
    name: user.name,
    email: maskEmail(user.email),
    phone: maskPhone(user.phone),
    memberSince: user.createdAt
    // ❌ Omitted: passwordHash, ssn, internalId, role
  });
});

// Middleware pattern for consistent masking:
function sanitizeResponse(data, allowedFields) {
  if (Array.isArray(data)) {
    return data.map(item => sanitizeResponse(item, allowedFields));
  }
  return Object.fromEntries(
    Object.entries(data)
      .filter(([key]) => allowedFields.includes(key))
  );
}

Google Senior Frontend — Data Masking

Q: When should masking happen on the frontend vs backend?

Always server-side. Frontend masking is cosmetic — the full value is still in the network response, in memory, and accessible via DevTools. Backend approach: (1) Default: API returns masked values. SSN → •••-••-6789. (2) "Reveal" action: Separate API endpoint that requires re-authentication and logs an audit event. GET /api/user/42/ssn with step-up auth. (3) Never send the full value in the initial page load. (4) For display-only data: mask server-side, no need for reveal. (5) For editable data: use "edit mode" that fetches the real value with elevated auth. Google's approach: Fields are classified by sensitivity level (public, internal, restricted, secret). Each level has different masking rules and access controls applied at the API layer.
