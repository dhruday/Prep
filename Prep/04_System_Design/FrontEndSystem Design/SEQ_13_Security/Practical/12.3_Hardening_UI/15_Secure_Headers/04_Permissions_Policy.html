Permissions-Policy Features

// Permissions-Policy (formerly Feature-Policy)
// Controls which browser APIs your page can use

// Syntax: feature=(allowlist)
Permissions-Policy: camera=(), microphone=(), geolocation=()
// () = disabled entirely (empty allowlist)

// Available features:
camera=()           Block camera access
microphone=()       Block microphone access
geolocation=()      Block location access
payment=()          Block Payment Request API
usb=()              Block WebUSB
bluetooth=()        Block Web Bluetooth
autoplay=()         Block media autoplay
fullscreen=(self)   Allow fullscreen only for same origin
display-capture=()  Block screen capture
accelerometer=()    Block accelerometer sensor
gyroscope=()        Block gyroscope sensor

// Allowlist values:
// ()           → disabled for all
// (self)       → allowed for same origin only
// (*)          → allowed for all origins
// ("https://trusted.com") → specific origin

// Example: Allow camera only for video chat partner
Permissions-Policy: camera=(self "https://meet.google.com")

Recommended Configuration

// E-commerce app (needs payment, no camera/mic):
Permissions-Policy:
  camera=(),
  microphone=(),
  geolocation=(),
  payment=(self),
  usb=(),
  bluetooth=(),
  autoplay=(),
  display-capture=(),
  document-domain=()

// Video conferencing app:
Permissions-Policy:
  camera=(self),
  microphone=(self),
  display-capture=(self),
  geolocation=(),
  payment=(),
  usb=()

// Blog / content site:
Permissions-Policy:
  camera=(),
  microphone=(),
  geolocation=(),
  payment=(),
  usb=(),
  bluetooth=(),
  autoplay=(),
  display-capture=(),
  interest-cohort=()  // Block FLoC tracking

// Express.js middleware:
app.use((req, res, next) => {
  res.setHeader('Permissions-Policy',
    'camera=(), microphone=(), geolocation=(), payment=(self)');
  next();
});

Google Senior Frontend — Permissions-Policy

Q: Why disable APIs your app doesn't use?

Defense in depth against: (1) XSS exploitation: If attacker gets XSS, they can't access camera/microphone/geolocation even with JavaScript execution. Without Permissions-Policy, XSS could silently request camera access. (2) Third-party script abuse: Advertising or analytics scripts embedded on your page could abuse these APIs. Ad networks have been caught using microphone access for audio fingerprinting. (3) Iframe-based attacks: Embedded iframes cannot use restricted features. Prevents permission-jacking via invisible iframes. (4) Supply chain attacks: A compromised npm package injected into your bundle can't access hardware APIs. (5) Principle of least privilege: Your shopping app doesn't need camera access. Disable it. If you add video reviews later, enable it explicitly. Best practice: Start with everything disabled, enable only what you need, with minimum scope (self vs specific origins).
