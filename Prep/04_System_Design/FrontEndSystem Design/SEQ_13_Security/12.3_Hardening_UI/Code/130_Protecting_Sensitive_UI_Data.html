Sensitive data — show minimum needed, mask the rest, never log or cache it

PII, financial, health, and auth data require special handling in the UI. Key principles: (1) data minimization — only request/display what the user needs right now, (2) masking at display layer (show last 4 digits), (3) never store sensitive data in client storage (localStorage, IndexedDB), (4) prevent accidental logging (no console.log of tokens/PII), (5) clear sensitive data from DOM when component unmounts. SAP follows strict GDPR data minimization in all its cloud products.

Masking utility + Sentry PII scrubbing + secure form cleanup

// ─── Masking utilities ───
const mask = {
  card: (n: string) => `•••• •••• •••• ${n.slice(-4)}`,
  email: (e: string) => {
    const [user, domain] = e.split('@');
    return `${user[0]}${'•'.repeat(user.length-2)}${user.slice(-1)}@${domain}`;
  },
  ssn: (s: string) => `•••-••-${s.slice(-4)}`
};

// ─── Sentry: scrub PII from error events ───
Sentry.init({
  beforeSend(event) {
    // Remove sensitive keys from breadcrumbs
    event.breadcrumbs?.values.forEach(b => {
      if (b.data) {
        delete b.data.password; delete b.data.token; delete b.data.ssn;
      }
    });
    return event;
  }
});

// ─── React: clear sensitive state on unmount ───
function PaymentForm() {
  const [cvv, setCvv] = useState('');
  useEffect(() => {
    return () => setCvv(''); // clear CVV when form closes
  }, []);
}
