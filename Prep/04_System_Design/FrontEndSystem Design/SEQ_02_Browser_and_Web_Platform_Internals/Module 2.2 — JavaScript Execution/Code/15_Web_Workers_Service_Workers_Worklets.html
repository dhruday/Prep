Web Worker: Runs JS in a background thread. Communicate via postMessage. No DOM access. Great for heavy CPU tasks, WASM, parsing large JSON, crypto operations. Lives as long as you keep the reference.

postMessage flow:

main → worker.postMessage({ task, data })
worker → self.postMessage({ result })
main → worker.onmessage = (e) => use(e.data)

Data is structured-cloned (copied) by default.
Use Transferable (ArrayBuffer) for zero-copy transfer.

Service Worker: A network proxy between your app and the network. Can cache resources, enable offline mode, push notifications, and background sync. Runs in its own thread, persists between page loads. Requires HTTPS (except localhost).

🎨 CSS Paint Worklet (Houdini)

CSS Paint Worklets run on the compositor thread — no main thread involvement. They let you create custom CSS background patterns in JS.

🎵 Audio Worklet (Web Audio API)

Audio Worklets run on the high-priority audio thread. They process audio samples in real-time without ever touching the main thread.
Worklets vs Workers:
Worklets run on specialized threads (compositor / audio). They cannot be communicated with freely — they hook into specific browser pipelines. They're lower-level and higher-performance than regular workers.
