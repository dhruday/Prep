⚖️ Frontend vs Backend System Design

Different constraints, different trade-offs, same rigour

🖥️ Frontend System Design
⚡
Primary constraint
Browser capabilities, device CPU/RAM, network latency, rendering pipeline
👤
User is always present
Every design decision directly affects perceived user experience — latency, jank, layout shifts, accessibility
🌍
Execution environment
Unknown, untrusted: any device, any browser, any network, any screen size
📦
Scale unit
Bundle size, DOM node count, re-render frequency, network requests per page
🔐
Security posture
Defence in depth: XSS, CSRF, CORS, token storage, CSP — client-side code is always attackable

⚙️ Backend System Design
🏗️
Primary constraint
Throughput, latency, consistency, availability — CAP theorem trade-offs
🤖
Machine-to-machine
Optimise for RPS, p99 latency, fault tolerance — users don't directly observe implementation
🖥️
Execution environment
Known, controlled: your servers, your OS, your hardware — predictable and configurable
🗄️
Scale unit
QPS, read/write ratio, data size, number of microservices, database shards
🔑
Security posture
Auth, authorization, SQL injection, secrets management — server-side enforcement

📖 Comparison Detail

Performance: LCP < 2.5s, INP < 200ms, CLS < 0.1. Measured on real user devices via RUM. Lighthouse CI gates performance in the pipeline. Every KB of JS has a parse cost on mobile.

Backend: p50/p99 response time (< 100ms API, < 10ms DB). Measured at server. Load balancers + horizontal scaling handle throughput.
Interview framing: When asked "how is this different from backend design?", show you understand that the frontend runs in an untrusted, resource-constrained, user-observed environment. The same problem (caching, consistency, scaling) has different solutions because the constraints are fundamentally different.
