Hydration Phases

Hybrid apps send HTML from server (SEO + fast paint), then hydrate on client (interactivity). The gap between HTML visible and app interactive is critical.

Hydration gap problem: HTML is displayed but buttons don't work until JS hydrates. Users click a "Add to Cart" button that appears responsive but fires no event. Solution: selective hydration (React 18+), Islands Architecture.

Next.js App Router — mixing strategies

// app/layout.tsx — Server Component (rendered on server, no JS sent)
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return <html><body>{children}</body></html>;
}

// app/page.tsx — Static (SSG) — built at deploy time
export const revalidate = Infinity; // never revalidate
export default async function HomePage() {
  const hero = await fetchHeroContent(); // runs at build time only
  return <HeroSection {...hero} />;
}

// app/products/[id]/page.tsx — ISR — revalidate every 60s
export const revalidate = 60;
export default async function ProductPage({ params }: { params: { id: string } }) {
  const product = await fetchProduct(params.id);
  return <ProductDetail product={product} />;
}

// app/dashboard/page.tsx — Dynamic SSR — fresh per request
export const dynamic = 'force-dynamic';
export default async function DashboardPage() {
  const metrics = await fetchLiveMetrics(); // always fresh
  return <Dashboard metrics={metrics} />;
}

// 'use client' — CSR island in a server-rendered page
'use client';
const CartButton = () => {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(c => c+1)}>🛒 {count}</button>;
};
