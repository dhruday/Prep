How state changes trigger re-renders

React / useState
  • setState → component + all children re-render
  • Object/array reference changes trigger re-render even if values are the same
  • useCallback / useMemo prevent child re-renders
  • React.memo skips re-render if props unchanged
Zustand / Redux
  • Selector must return different value to trigger re-render
  • Bad selector: useStore(s => s) — any change re-renders
  • Good selector: useStore(s => s.count) — only count changes
  • TanStack Query: only triggers re-render if selected field changes
SAP context: SAP Fiori dashboard had 400ms input lag. Root cause: entire store subscribed without selectors. Adding granular selectors + React.memo cut re-renders from ~120/keystroke to ~3/keystroke.

Optimization techniques checklist

Granular selectors
Select only the field you need: useStore(s => s.cart.count) not useStore(s => s.cart)
React.memo
Wrap pure child components. Prevents re-render when parent state changes but props haven't.
useMemo / useCallback
Stabilise object/array/function references passed as props. Prevents React.memo from being bypassed.
Context splitting
Split one large Context into AuthContext, ThemeContext, UIContext. Only affected consumers re-render.
startTransition
Mark low-priority state updates as transitions. React can interrupt them for urgent updates (typing).

Performance patterns in code

// ❌ Whole-store subscription — re-renders on ANY field change
const store = useStore(s => s);

// ✅ Granular selector
const count = useStore(s => s.count);
const cartTotal = useStore(s => s.cart.reduce((sum, i) => sum + i.price, 0));

// ✅ React.memo — skip re-render if props same
const CartItem = React.memo(({ item }: { item: Item }) => (
  <div>{item.name} — ${item.price}</div>
)); // shallow prop comparison

// ✅ Stable callbacks — prevent memo bypass
const handleDelete = useCallback((id: string) => {
  removeItem(id);
}, []); // stable reference — CartItem won't re-render due to this prop

// ✅ startTransition for low-priority updates
const handleSearch = (e: ChangeEvent<HTMLInputElement>) => {
  setSearchInput(e.target.value);          // urgent: shows in input
  startTransition(() => {
    setFilteredResults(filterData(e.target.value)); // deferrable
  });
};
