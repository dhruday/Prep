Redux Toolkit — the official modern way to write Redux

createSlice
Combines reducer + actions in one. Uses Immer under the hood — allows "mutating" syntax that is actually immutable. Eliminates switch boilerplate.
createAsyncThunk
Handles pending / fulfilled / rejected lifecycle. Dispatches action types for each stage automatically. Used for one-off mutations.
RTK Query
Full data-fetching + caching solution built into RTK. Generates hooks automatically from endpoint definitions. Replaces createAsyncThunk for CRUD.
SAP context: SAP Fiori legacy apps use Redux heavily. At SAP Labs Hruday migrated one such app from raw Redux to RTK — reducing ~3000 lines of boilerplate to ~700 lines.

RTK Query vs createAsyncThunk — when to use which

RTK Query — use for CRUD operations
Auto-generates hooks, manages cache, handles loading/error states, automatic deduplication of concurrent requests, built-in tag-based invalidation.
✅ GET /orders, POST /orders, PUT /order/:id, DELETE /order/:id
createAsyncThunk — use for custom logic
When you need custom side effects (local storage, auth token refresh, orchestrating multiple calls). More control, more boilerplate.
✅ Login (store token + redirect), complex multi-step workflows

createSlice + createAsyncThunk + RTK Query

// ─── createSlice ───
const cartSlice = createSlice({
  name: 'cart',
  initialState: { items: [] as Item[], total: 0 },
  reducers: {
    addItem(state, action: PayloadAction<Item>) {
      state.items.push(action.payload);  // Immer: looks mutable, is immutable
      state.total += action.payload.price;
    },
    removeItem(state, action: PayloadAction<string>) {
      const item = state.items.find(i => i.id === action.payload);
      if (item) { state.total -= item.price; state.items = state.items.filter(i => i.id !== action.payload); }
    },
  },
});

// ─── createAsyncThunk ───
const fetchOrders = createAsyncThunk('orders/fetch', async (userId: string) => {
  const res = await fetch(`/api/orders/${userId}`);
  return res.json();   // payload: fulfilled action
});
ordersSlice.extraReducers = builder => {
  builder
    .addCase(fetchOrders.pending,   s => { s.status = 'loading' })
    .addCase(fetchOrders.fulfilled, (s, a) => { s.orders = a.payload; s.status = 'idle' })
    .addCase(fetchOrders.rejected,  s => { s.status = 'error' });
};

// ─── RTK Query ───
const ordersApi = createApi({
  reducerPath: 'ordersApi',
  baseQuery: fetchBaseQuery({ baseUrl: '/api' }),

  }),
});
