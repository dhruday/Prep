Prop Drilling — passing through intermediaries

Prop drilling occurs when a prop is passed through multiple component layers that don't use it — just forward it to their children. It creates tight coupling, makes refactoring painful, and violates the principle that components should only know what they need.

🔴 Drilling pain — App → Layout → Page → Section → Widget → Button all take user prop
🔴 Coupling — If user structure changes, update every intermediate component
✔ Context fix — App provides UserContext, Button reads it directly
⚠ Context is NOT free — every consumer re-renders on context value change

Context performance gotcha — split contexts

When context value changes, ALL consumers of that context re-render — even if they don't use the changed part. Solution: split context by update frequency.

// ❌ Single fat context — theme change re-renders user consumers
const AppContext = createContext({ user: ..., theme: ..., lang: ... });

// ✅ Split contexts by change frequency
const UserContext = createContext(user);    // changes on login only
const ThemeContext = createContext(theme);  // changes on toggle
const LangContext = createContext(lang);    // changes rarely

// Each component subscribes to only the context it needs
const theme = useContext(ThemeContext); // only re-renders on theme change
💡 Use useMemo for context value to prevent object identity changes causing re-renders: const value = useMemo(() => ({user}), [user])

Context API — SAP theme example

// contexts/ThemeContext.tsx
import { createContext, useContext, useState, useMemo } from 'react';

type Theme = 'light' | 'dark' | 'sap-belize';

interface ThemeContextValue {
  theme: Theme;
  setTheme: (t: Theme) => void;
}

const ThemeContext = createContext<ThemeContextValue | null>(null);

export function ThemeProvider({ children }) {
  const [theme, setTheme] = useState<Theme>('sap-belize');
  // useMemo prevents new object on every parent render
  const value = useMemo(() => ({ theme, setTheme }), [theme]);
  return <ThemeContext.Provider value={value}>{children}</ThemeContext.Provider>;
}

export function useTheme() {
  const ctx = useContext(ThemeContext);
  if (!ctx) throw new Error('useTheme must be used within ThemeProvider');
  return ctx;
}

// Usage — anywhere in tree, no drilling
function Header() {
  const { theme, setTheme } = useTheme();
  return <button onClick={() => setTheme('dark')}>Toggle</button>;
}
