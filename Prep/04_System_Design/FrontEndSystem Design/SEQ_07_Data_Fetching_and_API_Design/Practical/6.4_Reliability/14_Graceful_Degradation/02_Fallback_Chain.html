The Fallback Chain

When a fetch fails, walk down the chain until something works:

1. Fresh Cache→ 2. Stale Data→ 3. Default Value→ 4. Hide Widget

Fresh Cache: Data cached <5 min ago — use as-is

Stale Data: Older cache with "last updated" badge

Default: Hardcoded placeholder ("$0.00", "N/A")

Hide: Remove the widget entirely, no empty state

The chain ensures the user always sees something meaningful — or nothing at all — never a broken blank box.

Fallback Chain Implementation

class FallbackChain {
  #cache = new Map();
  #defaults;

  constructor(defaults) { this.#defaults = defaults; }

  async fetch(key, fetchFn, maxAge = 300000) {
    // Level 1: try fresh fetch
    try {
      const data = await fetchFn();
      this.#cache.set(key, { data, ts: Date.now() });
      return { data, level: 'fresh' };
    } catch(e) {}

    // Level 2: fresh cache
    const cached = this.#cache.get(key);
    if (cached && Date.now() - cached.ts < maxAge)
      return { data: cached.data, level: 'cached' };

    // Level 3: stale cache
    if (cached)
      return { data: cached.data, level: 'stale' };

    // Level 4: default value
    if (this.#defaults[key] !== undefined)
      return { data: this.#defaults[key], level: 'default' };

    // Level 5: hide
    return { data: null, level: 'hide' };
  }
}

Key Points

• The chain is sequential — stop at the first level that provides data

• Always show "last updated X ago" badge for stale/cached data

• Default values should be obviously placeholder ("—", "$0.00") not misleading

• "Hide" is better than showing an empty card with no explanation

• Log which fallback level was used — it's a key reliability metric
