Why Shape Matching Matters

A generic spinner → content appearing causes layout shift (CLS). Shape-matched skeletons reserve the exact space content will occupy:

• Avatar placeholder = exact circle size as real avatar

• Text lines = same height, width proportions as expected text

• Card skeleton = same padding, border-radius, height as real card

• Result: content swaps in with CLS ≈ 0

The skeleton IS the layout — content fills the same container, no reflow needed.

Shape-Matched Component

/* Skeleton and content share SAME dimensions */
.card-skeleton,
.card-content {
  width: 100%;
  height: 200px;       /* exact same height */
  padding: 14px;       /* exact same padding */
  border-radius: 8px; /* exact same radius */
}

.avatar-skeleton,
.avatar-img {
  width: 48px;
  height: 48px;
  border-radius: 50%;
}

.text-skeleton {
  height: 14px;         /* matches line-height */
  margin-bottom: 8px;   /* matches text spacing */
  border-radius: 4px;
}

/* Swap: just change inner content, container stays */
function replaceWithContent(container, html) {
  container.innerHTML = html;
  // No layout shift — same outer dimensions
}

Key Points

• Skeleton and content MUST share the same container dimensions (height, padding, margin)

• Use explicit heights for skeleton elements matching real text line-height

• Avatar skeletons must be exact size/shape of real avatars

• Component-level skeletons are better than page-level — each part loads independently

• Test with Lighthouse or PerformanceObserver to verify CLS ≈ 0
