Delayed Skeleton

200ms threshold — skip skeleton for fast loads, show only if data is slow

The 200ms Threshold

Showing a skeleton for 50ms and then immediately replacing it with content causes an annoying flash. The fix: delay the skeleton by ~200ms.

Fast load (<200ms): Show nothing → content appears instantly. No flash.

Slow load (>200ms): After 200ms, show skeleton. Content replaces it when ready.

Delayed Skeleton Implementation

async function loadWithDelayedSkeleton(container, fetchFn, delay = 200) {
  let showSkeleton = false;

  // Start timer: show skeleton after delay
  const timer = setTimeout(() => {
    showSkeleton = true;
    container.innerHTML = renderSkeleton();
  }, delay);

  try {
    const data = await fetchFn();

    // Data arrived — cancel skeleton if not shown yet
    clearTimeout(timer);

    // If skeleton was shown, add min display time
    if (showSkeleton) {
      await new Promise(r => setTimeout(r, 300));
    }
    renderContent(container, data);
  } catch(e) {
    clearTimeout(timer);
    renderError(container, e);
  }
}

Key Points

• 200ms is the sweet spot — below this, humans perceive the load as "instant"

• If skeleton appears, show it for at least 300ms to avoid a different flash

• This is a UX optimization: fewer perceived loading states = smoother experience

• Works great with skeleton + suspense patterns in React

• The timer approach works with any async operation, not just fetch

Interview tip: "We delay skeleton display by 200ms so fast API responses never flash a loading state."
