Queue + Token Bucket

Instead of rejecting excess requests, they enter a FIFO queue. A drain loop checks for available tokens and processes queued requests in order.
  1. Request arrives → if token available, execute immediately.
  2. If no token → push to queue (FIFO).
  3. Every 200ms, drain loop: refill tokens, process queued items.
  4. Queue has max size to prevent unbounded growth.

Implementation

class QueuedBucket {
  constructor(cap, refillRate, maxQueue) {
    this.tokens = cap; this.cap = cap;
    this.rate = refillRate;
    this.queue = []; this.maxQ = maxQueue;
    setInterval(() => this.tick(), 200);
  }
  tick() {
    this.tokens = Math.min(this.cap,
      this.tokens + this.rate * 0.2);
    while (this.queue.length && this.tokens >= 1) {
      this.tokens--;
      const fn = this.queue.shift();
      fn(); // execute queued request
    }
  }
  submit(fn) {
    if (this.tokens >= 1) {
      this.tokens--; fn(); return 'immediate';
    }
    if (this.queue.length < this.maxQ) {
      this.queue.push(fn); return 'queued';
    }
    return 'dropped';
  }
}

Key Takeaways

Queuing converts hard rejections into delayed execution, improving UX for bursty workloads.
  • Queue smooths bursts — no data lost unless queue overflows
  • Max queue size prevents memory leaks
  • FIFO ensures fairness among requests
  • Trade-off: latency increases under sustained load
  • Used in job processors, API gateways, message brokers
