🗄️ How Normalized Cache Works

Apollo Client flattens nested responses into a dictionary keyed by __typename:id. Nested objects become references.

Server Response (nested)→ Normalize by __typename:id→ Flat Cache Map

❌ Without Normalization (document cache)

// Query A result stored as-is:
cache["query:UserProfile(1)"] = { user: { id:1, name:"Alex", posts:[...] } }

// Query B also stores same user:
cache["query:PostsByUser(1)"] = { posts: [{ author: { id:1, name:"Alex" } }] }

// Update user name → must update BOTH entries manually
// Miss one? UI shows stale "Alex" in one place, "Alexander" in another

✅ With Normalization

// Flat cache — single source of truth:
{
  "User:1": { id:1, __typename:"User", name:"Alex", avatar:"..." },
  "Post:10": { id:10, __typename:"Post", title:"...", author: { __ref:"User:1" } },
  "Post:11": { id:11, __typename:"Post", title:"...", author: { __ref:"User:1" } }
}
// Update User:1.name → ALL queries reading User:1 auto-update

💬 "Explain Apollo's cache normalization"

// Apollo InMemoryCache normalizes in 3 steps:

// 1. Traverse response tree
// 2. For each object with __typename + id → create cache key
const key = `${obj.__typename}:${obj.id}`; // e.g. "User:1"

// 3. Replace nested objects with __ref pointers
{ author: { __ref: "User:1" } }

// Custom key fields:
new InMemoryCache({
  typePolicies: {
    Product: { keyFields: ["sku"] }, // "Product:WH-1000"
    CartItem: { keyFields: ["product", ["sku"]] } // nested key
  }
});

💬 "How does cache eviction work?"

cache.evict({ id: 'User:1' }) — removes the entity. But other objects may still hold stale __ref: "User:1" → dangling reference.
cache.gc() — garbage collects unreachable entities. Any object not referenced by any ROOT_QUERY path is removed. Run after evictions.
// Evict + GC pattern:
cache.evict({ id: 'Post:42' });
cache.evict({ id: 'Post:42', fieldName: 'comments' }); // field-level
cache.gc(); // clean up orphans

// Cache write policies:
// merge: true  → deep merge incoming with existing
// merge: false → replace existing entirely (default for arrays)
typePolicies: {
  User: { fields: {
    posts: { merge(existing = [], incoming) {
      return [...existing, ...incoming]; // pagination merge
    }}
  }}
}

💬 "Document cache vs normalized cache?"

Document Cache (React Query, SWR)
• Key = query string/URL
• Stores full response per query
• Duplicate data across queries
• Manual invalidation
• Simpler mental model
Normalized Cache (Apollo, Relay, URQL)
• Key = __typename:id
• Flat entity store
• Single source of truth
• Auto-update on mutation
• Complex but powerful
