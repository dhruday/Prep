How Offset Pagination Works

The server skips offset rows, then returns the next limit rows.

SELECT * FROM items
ORDER BY id
LIMIT 10 OFFSET 20;   -- page 3 (0-indexed offset)

Client sends: GET /items?page=3&limit=10
Server computes: OFFSET = (page - 1) * limit

Page Number Calculation

// Given: totalCount from X-Total-Count header
const totalPages = Math.ceil(totalCount / limit);
const offset    = (page - 1) * limit;

// Page 1 → OFFSET 0   (rows 1-10)
// Page 2 → OFFSET 10  (rows 11-20)
// Page 5 → OFFSET 40  (rows 41-50)

Ghost Records Problem

If a row is inserted or deleted between page requests, items can be duplicated or skipped.

// User fetches page 2 (OFFSET 10)
// Meanwhile, row #5 is deleted → all offsets shift by -1
// Page 3 (OFFSET 20) now SKIPS what was row #21
// Result: user never sees that item — a "ghost" record
In write-heavy systems, offset pagination causes data inconsistency between pages.

Database Cost of High Offsets

With OFFSET N, the database must scan and discard N rows before returning results.

-- Page 1: scan 10 rows   → O(10)
SELECT * FROM items LIMIT 10 OFFSET 0;

-- Page 100: scan 1000 rows → O(1000)
SELECT * FROM items LIMIT 10 OFFSET 990;

-- Page 10000: scan 100,000 rows → O(100,000) 🐌
SELECT * FROM items LIMIT 10 OFFSET 99990;
Time complexity: O(offset + limit) — linear in page number.

EXPLAIN Plan Comparison

-- Page 1 (fast):
EXPLAIN ANALYZE SELECT * FROM items LIMIT 10 OFFSET 0;
→ Index Scan: 0.05ms, 10 rows fetched

-- Page 5000 (slow):
EXPLAIN ANALYZE SELECT * FROM items LIMIT 10 OFFSET 49990;
→ Seq Scan: 120ms, 50000 rows scanned, 10 returned

When Offset Pagination Is Acceptable

  • Small datasets — under 10K rows, offset cost is negligible
  • Admin panels — low traffic, paginating through manageable data
  • Search results — users rarely go past page 5 (Google caps at ~30 pages)
  • Jump-to-page requirement — only offset supports "Go to page 42"
  • Simple implementation — no cursor state to manage

When to Avoid Offset

  • Millions of rows — deep pages become very slow
  • Real-time feeds — inserts cause ghost/duplicate records
  • Infinite scroll — cursor pagination is more natural
  • Mobile APIs — cursor is simpler for "load more" UX

Interview Key Points

✅ Offset = simple, supports page numbers, good for small data
❌ O(offset) scan cost — degrades linearly with page depth
❌ Ghost records on write-heavy tables
