Serve stale immediately — revalidate in the background

SWR (stale-while-revalidate) is a cache strategy that always returns the cached (stale) response immediately for zero latency, while simultaneously sending a background request to refresh the cache. The next request then gets the updated data. This gives users instant UX with eventually-consistent freshness. Named after the RFC 5861 HTTP directive and popularized by Vercel's SWR library.

1
Request arrives — check cache. Data is stale (past max-age) but within swr window.
2
Return stale immediately — user sees data instantly. Zero wait.
3
Background fetch starts — new request sent to origin/network in parallel.
4
Cache updated — fresh data stored. Next request gets the fresh version.
Header format: Cache-Control: max-age=60, stale-while-revalidate=300 — fresh for 60s, serve stale for up to 5 more minutes while refreshing.

Both complement each other: use HTTP SWR on CDN edges for network-level caching, layer JS SWR in the app for client-side deduplication and focus-based refresh.

HTTP header + SWR library + React Query patterns

// ─── HTTP: stale-while-revalidate directive ───
// nginx
add_header Cache-Control "public, max-age=60, stale-while-revalidate=300";

// ─── Vercel SWR library ───
import useSWR from 'swr';
function Catalog() {
  const { data, isLoading, isValidating } = useSWR(
    '/api/catalog', fetcher,
    {
      revalidateOnFocus: true,   // refetch when tab gains focus
      revalidateOnReconnect: true,
      dedupingInterval: 60_000,    // dedupe within 1 min
    }
  );
  return <div>{isValidating && <Spinner />}{data && <List items={data} />}</div>;
}

// ─── React Query SWR pattern ───
useQuery({
  queryKey: ['catalog'],
  queryFn: fetchCatalog,
  staleTime: 60_000,     // consider fresh for 60s
  gcTime: 300_000,        // keep in memory 5 min
  refetchOnWindowFocus: true,
  placeholderData: keepPreviousData, // show old data while fetching
});
