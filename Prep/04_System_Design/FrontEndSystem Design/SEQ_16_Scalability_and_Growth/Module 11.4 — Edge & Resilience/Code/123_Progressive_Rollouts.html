Progressive rollout: gradually increase exposure — monitor metrics, roll back instantly if error rate spikes

Progressive rollouts (also called canary deployments for frontend) mean: (1) deploy new code to 1% of users, (2) monitor key metrics for 30 min, (3) advance to 10% → 30% → 100% if healthy. If error rate or p99 latency spikes, auto-rollback. Combined with feature flags, this can be done without redeployment — just change the flag rollout percentage. This is how SAP BTP rolls out new Fiori UI updates to enterprise customers.

Percentage-based rollout with auto-rollback

// ─── Percentage rollout check ───
function isInRollout(userId: string, percentage: number): boolean {
  let hash = 0;
  for (const c of userId) hash = (hash * 31 + c.charCodeAt(0)) & 0xffff;
  return (hash % 100) < percentage;
}

// ─── Error rate monitor with auto-rollback ───
class RolloutMonitor {
  private errors = 0; private requests = 0;

  record(success: boolean) {
    this.requests++;
    if (!success) this.errors++;
    if (this.requests >= 100 && this.errorRate() > 0.01) {
      this.rollback();
    }
  }

  errorRate() { return this.errors / Math.max(this.requests, 1); }

  rollback() {
    flagService.setPercentage('new_checkout', 0);
    alerting.page('Auto-rollback: error rate exceeded 1%');
  }
}
