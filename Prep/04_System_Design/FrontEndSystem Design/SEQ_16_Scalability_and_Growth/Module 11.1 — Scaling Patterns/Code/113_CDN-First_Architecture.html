CDN-first: design every HTTP response to be cacheable at the edge by default

In CDN-first architecture, you design BEFORE you code: every resource type has a defined cache strategy. Static assets use immutable hashes. HTML pages use stale-while-revalidate. API calls are either fully public (cacheable by CDN) or private (bypass CDN). Edge workers handle personalization so origin servers never serve uncacheable responses at scale.

CDN-first rules
  • JS/CSS/images: immutable, 1yr
  • HTML pages: SWR 60s, stale 24h
  • Public API: cache 30s
  • Private/auth: no-store
  • A/B variants: route to edge, vary by cookie
Common mistakes
  • No Cache-Control header → CDN guesses
  • Same URL for different users → wrong cache key
  • SPA HTML with immutable → app stuck in old version
  • Token in URL → leaks in CDN logs
  • Forgetting to purge on deploy

Next.js headers config + Cloudflare cache rules

// ─── next.config.ts ───
const nextConfig = {
  async headers() {
    return [
      {
        source: '/_next/static/:path*',
        headers: [{ key: 'Cache-Control', value: 'public, max-age=31536000, immutable' }]
      },
      {
        source: '/api/public/:path*',
        headers: [{ key: 'Cache-Control', value: 'public, max-age=30, stale-while-revalidate=120' }]
      },
      {
        source: '/api/private/:path*',
        headers: [{ key: 'Cache-Control', value: 'private, no-store' }]
      }
    ];
  }
};

// ─── Cloudflare Worker: purge on deploy ───
const purgeCDN = async (zone: string, token: string) => {
  await fetch(`https://api.cloudflare.com/client/v4/zones/${zone}/purge_cache`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ purge_everything: true }) // or {files:[...specific urls]}
  });
};
