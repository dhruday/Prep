Full-duplex, persistent TCP channel over HTTP upgrade

WebSockets start with an HTTP handshake (Upgrade: websocket), then both client and server can push messages at any time over the same TCP connection. No HTTP overhead per message — just a small frame header (~2–14 bytes). At SAP Bosch, the Angular dashboards used WebSockets for live machine telemetry (temperature, pressure every 100ms) — impossible with polling.

✅ WebSocket strengths
  • Low per-message overhead
  • True bi-directional push
  • Sub-millisecond messaging
  • Perfect for chat, live collab, gaming
⚠️ WebSocket trade-offs
  • Custom reconnect logic needed
  • No automatic HTTP auth headers
  • Hard to proxy/load balance
  • Idle connections hold server resources

WebSocket client + React hook + Angular service

// ─── React hook ───
function useWebSocket(url: string) {
  const [messages, setMessages] = useState<string[]>([]);
  const wsRef = useRef<WebSocket>();
  useEffect(() => {
    wsRef.current = new WebSocket(url);
    wsRef.current.onmessage = (e) => setMessages(m => [...m, e.data]);
    wsRef.current.onerror   = (e) => console.error('WS error', e);
    return () => wsRef.current?.close();
  }, [url]);
  const send = (msg: string) => wsRef.current?.send(msg);
  return { messages, send };
}

// ─── Angular service ───
@Injectable({ providedIn: 'root' })
export class WsService {
  connect(url: string): Observable<string> {
    return new Observable(observer => {
      const ws = new WebSocket(url);
      ws.onmessage = e => observer.next(e.data);
      ws.onerror   = e => observer.error(e);
      ws.onclose   = ()  => observer.complete();
      return () => ws.close();
    });
  }
}
