Presence system architecture

Presence (online/offline/away) and typing indicators require a different design from regular data sync. They are: ephemeral (don't persist to DB permanently), high-frequency (typing events fire every keystroke), and fan-out intensive (your typing must propagate to all other collaborators in the room). These properties make them expensive at scale.

Heartbeat / Ping
Client sends heartbeat every 15-30s. Server marks user offline if heartbeat misses 2×. Low frequency, reliable presence tracking.
Typing — throttle + debounce
Emit "typing" on first keypress, then throttle (max 1/sec). Auto-stop after 3s no-keystroke debounce. Prevents thousands of events/min.
Scale: Pub/Sub
With multiple server instances, presence must use Redis Pub/Sub or Ably/Pusher channels. Single server won't see all users.

Typing indicator — throttle + debounce pattern

class TypingIndicator {
  private isTyping = false;
  private stopTimer: ReturnType<typeof setTimeout> | null = null;
  
  constructor(private socket: Socket, private roomId: string, private userId: string) {}
  
  onKeystroke() {
    // Only emit once when typing STARTS (state change pattern)
    if (!this.isTyping) {
      this.isTyping = true;
      this.socket.emit('typing:start', { roomId: this.roomId, userId: this.userId });
    }
    
    // Debounce stop: reset timer on each keystroke
    if (this.stopTimer) clearTimeout(this.stopTimer);
    this.stopTimer = setTimeout(() => this.stopTyping(), 3000);
  }
  
  stopTyping() {
    if (this.isTyping) {
      this.isTyping = false;
      this.socket.emit('typing:stop', { roomId: this.roomId, userId: this.userId });
    }
    if (this.stopTimer) { clearTimeout(this.stopTimer); this.stopTimer = null; }
  }
}
