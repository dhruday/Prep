Never hammer a struggling server — back off exponentially with jitter

When a WebSocket or SSE connection drops, naive immediate-retry floods the server at exactly the wrong time (when it's overloaded). Exponential backoff spaces retries geometrically: wait 1s, then 2s, then 4s, then 8s, up to a cap. Jitter (random variance) prevents the "thundering herd" problem where thousands of clients all retry at the same moment. At SAP, the Bosch WebSocket service used decorrelated jitter with max 30s delay.

❌ Immediate retry
Retry instantly every disconnect → DDoS your own server during outage
⚠️ Fixed delay retry
All clients retry at T+10s → synchronized thundering herd wave
✅ Exp backoff + jitter
Clients spread out retries randomly → server load smoothed

WebSocket reconnect with exponential backoff + jitter

// ─── Resilient WebSocket manager ───
class ResilientWS {
  private ws: WebSocket | null = null;
  private attempt = 0;
  private readonly MAX_DELAY = 30_000;
  private readonly BASE     = 1_000;
  connect() {
    this.ws = new WebSocket(this.url);
    this.ws.onopen  = () => { this.attempt = 0; this.onOpen?.(); };
    this.ws.onclose = () => this.scheduleReconnect();
    this.ws.onerror = () => this.ws?.close();
  }
  private scheduleReconnect() {
    const exp   = this.BASE * Math.pow(2, this.attempt);
    const delay = Math.min(this.MAX_DELAY, Math.random() * exp); // full jitter
    this.attempt++;
    setTimeout(() => this.connect(), delay);
  }
}
