Relay Connection Spec — Structure

The Relay Connection Specification defines a standardized shape for cursor-based pagination in GraphQL.

{
  "data": {
    "users": {                    // Connection
      "edges": [                   // Edge[]
        {
          "cursor": "YXJyYXljb25uZWN0aW9uOjA=",  // opaque cursor
          "node": {                // the actual entity
            "id": "1",
            "name": "Alice"
          }
        },
        {
          "cursor": "YXJyYXljb25uZWN0aW9uOjE=",
          "node": { "id": "2", "name": "Bob" }
        }
      ],
      "pageInfo": {              // PageInfo
        "hasNextPage": true,
        "hasPreviousPage": false,
        "startCursor": "YXJyYXljb25uZWN0aW9uOjA=",
        "endCursor": "YXJyYXljb25uZWN0aW9uOjE="
      }
    }
  }
}

GraphQL Pagination Arguments

# Forward pagination
query {
  users(first: 5, after: "cursor_abc") {
    edges { cursor node { id name } }
    pageInfo { hasNextPage endCursor }
  }
}

# Backward pagination
query {
  users(last: 5, before: "cursor_xyz") {
    edges { cursor node { id name } }
    pageInfo { hasPreviousPage startCursor }
  }
}

// first + after = forward   |   last + before = backward

Type Definitions

type UserConnection {
  edges: [UserEdge]
  pageInfo: PageInfo!
}

type UserEdge {
  cursor: String!     // opaque, per-edge cursor
  node: User!
}

type PageInfo {
  hasNextPage: Boolean!
  hasPreviousPage: Boolean!
  startCursor: String
  endCursor: String
}

Why Standardized Pagination Matters

  • Client libraries auto-handle it — Relay, Apollo, urql understand the shape
  • Automatic cache merging — Apollo can merge pages by cursor
  • Predictable API — every connection works the same way
  • Tooling & codegen — GraphQL codegen generates typed hooks
  • Edge metadata — each edge can carry extra data (e.g., relationship info)

Relay Compiler — Automatic Pagination

// With @connection directive, Relay handles everything:
const { data, loadNext, hasNext } = usePaginationFragment(
  graphql`
    fragment UserList_query on Query
    @refetchable(queryName: "UserListPaginationQuery") {
      users(first: $count, after: $cursor)
      @connection(key: "UserList_users") {
        edges {
          node { id name avatar }
        }
      }
    }
  `,
  queryRef
);

// Usage: just call loadNext(10) — Relay does the rest!
return (
  <FlatList
    data={data.users.edges.map(e => e.node)}
    onEndReached={() => hasNext && loadNext(10)}
  />
);
Relay's compiler statically analyzes this fragment and generates optimized pagination queries at build time.

Apollo Client — fetchMore

const { data, fetchMore } = useQuery(GET_USERS, {
  variables: { first: 10 }
});

const loadMore = () => fetchMore({
  variables: { after: data.users.pageInfo.endCursor },
  updateQuery: (prev, { fetchMoreResult }) => ({
    users: {
      ...fetchMoreResult.users,
      edges: [...prev.users.edges, ...fetchMoreResult.users.edges]
    }
  })
});

Relay Connection vs Custom Pagination

Relay Connection

{
  "edges": [{
    "cursor": "abc",
    "node": { "id": 1 }
  }],
  "pageInfo": {
    "hasNextPage": true,
    "endCursor": "abc"
  }
}

Custom Pagination

{
  "items": [{ "id": 1 }],
  "next_cursor": "abc",
  "has_more": true
}

Interview Key Points

✅ Relay Connection = standard cursor pagination for GraphQL
✅ edges/node/cursor/pageInfo — know the structure by heart
✅ first+after (forward), last+before (backward)
❌ Verbose for simple REST APIs — use simple cursor instead
