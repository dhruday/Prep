The Problem

User scrolls down through 500 items in a feed, clicks on item #347 for details, presses Back — and is sent back to the top. This is a major UX failure for infinite scroll lists.

// Solution: Save scroll position before navigating away

// Option 1: sessionStorage (survives tab refresh)
function saveScrollPos(key, scrollTop) {
  sessionStorage.setItem(`scroll_${key}`, scrollTop);
}

// Option 2: history.state (tied to navigation entry)
function saveScrollPos(scrollTop) {
  history.replaceState(
    { ...history.state, scrollY: scrollTop },
    ''
  );
}

// Restore on return
function restoreScrollPos(container, key) {
  const saved = sessionStorage.getItem(`scroll_${key}`);
  if (saved) container.scrollTop = parseInt(saved);
}
Critical detail: You must also restore the data (all 500 items), not just the scroll position. Without the items, there's nothing to scroll to. Cache the list data alongside the scroll offset.

// Disable browser's auto-restore if you handle it manually:
if ('scrollRestoration' in history) {

// For SPA routers (React Router, Next.js):
// Browser can't restore because the DOM is reconstructed
// You MUST handle it yourself

Manual Approach (SPA Pattern)

// React example with useEffect
function FeedList() {
  const listRef = useRef();
  const location = useLocation();

  // Save on unmount (navigating away)
  useEffect(() => {
    return () => {
      sessionStorage.setItem(
        `scrollPos:${location.key}`,
        listRef.current.scrollTop
      );
    };
  }, [location.key]);

  // Restore on mount (returning to page)
  useEffect(() => {
    const saved = sessionStorage.getItem(`scrollPos:${location.key}`);
    if (saved && listRef.current) {
      // Wait for data to render, then restore
      requestAnimationFrame(() => {
        listRef.current.scrollTop = parseInt(saved);
      });
    }
  }, [data]); // restore AFTER data is loaded
}
Timing is critical: Restore scroll AFTER the list content has rendered. Use requestAnimationFrame or wait for data loading to complete.

Q: What storage strategy for scroll position?

sessionStorage — Best for most cases. Survives page refresh, scoped to tab, auto-cleared on tab close. Key by route + navigation entry.

history.state — Tied to the exact navigation entry. Automatically cleaned up by the browser. Ideal for SPA back/forward. But lost on page refresh in some browsers.

In-memory (React state/context) — Fast, no serialization. But lost on refresh. Use with React Query/SWR cache for data + scroll combo.

FAANG answer: Use history.replaceState as primary (tied to nav entry), fall back to sessionStorage for durability. Key format: scroll:{routeKey}:{listId}.

Q: How to handle list changes between navigations?

// Problem: User at scrollTop=5000, goes to detail, comes back
// But new items were added → item #347 is now at different offset

// Solution 1: Save item ID + offset within item
savePosition({
  itemId: 'item-347',
  offsetWithinItem: 12, // px from top of that item
});

// On restore: find item by ID, scroll to it
const el = document.querySelector(`[data-id="${saved.itemId}"]`);
el.scrollIntoView({ block: 'start' });
container.scrollTop -= saved.offsetWithinItem;

// Solution 2: Immutable list + cache
// Keep cached data, restore exact state
// Only refresh when user explicitly pulls-to-refresh
Anchor-based restoration (saving item ID instead of pixel offset) is the robust FAANG answer. Pixel-based breaks when list content changes.
