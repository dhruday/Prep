Pull to Refresh Pattern

User pulls down beyond the top of a scrollable list. Beyond a threshold (e.g., 60px), release triggers a data refresh. CSS transform translates the content down to reveal a spinner indicator.

// Core touch event flow
let startY = 0;
let pulling = false;

el.addEventListener('touchstart', e => {
  if (el.scrollTop === 0) {
    startY = e.touches[0].clientY;
    pulling = true;
  }
});

el.addEventListener('touchmove', e => {
  if (!pulling) return;
  const dy = e.touches[0].clientY - startY;
  if (dy > 0) {
    // Apply resistance curve (diminishing returns)
    const pull = Math.min(dy * 0.4, 100);
    indicator.style.height = pull + 'px';
  }
});

el.addEventListener('touchend', () => {
  if (pullDistance > THRESHOLD) refresh();
  else resetPull();
});
Resistance curve: dy * 0.4 makes pulling feel "elastic". The further you pull, the harder it resists — mimicking native iOS/Android behavior.

Touch Event Handling

// Three events, three phases

// 1. touchstart — Record initial Y, check if at top
el.addEventListener('touchstart', e => {
  if (el.scrollTop !== 0) return; // only at top
  startY = e.touches[0].clientY;
  startTime = Date.now(); // for velocity calc
}, { passive: true });

// 2. touchmove — Track delta, show indicator
el.addEventListener('touchmove', e => {
  const dy = e.touches[0].clientY - startY;
  if (dy > 10 && el.scrollTop === 0) {
    e.preventDefault();  // prevent native scroll
    const pull = applyResistance(dy);
    updateIndicator(pull);
  }
}, { passive: false }); // passive:false to allow preventDefault

// 3. touchend — Threshold check, trigger refresh or snap back
el.addEventListener('touchend', () => {
  if (pullDistance >= THRESHOLD) {
    showSpinner();
    fetchFreshData().then(resetIndicator);
  } else {
    animateSnapBack();
  }
});

overscroll-behavior CSS

/* Prevent browser's native pull-to-refresh (Chrome) */
html, body {
  overscroll-behavior-y: contain;
}

/* Or on the scrollable container specifically */
.feed-container {
  overscroll-behavior-y: contain;
  /* contain = no scroll chaining, no overscroll effects */
  /* none = same as contain + no bounce on iOS */
}

/* Without this, Chrome on Android fires its own
   pull-to-refresh which reloads the entire page! */
overscroll-behavior: contain is the single most important CSS property for custom pull-to-refresh. Without it, the browser's native refresh competes with yours.

Q: How to prevent browser default pull-to-refresh?

1. CSS overscroll-behavior:
overscroll-behavior-y: contain on the scrollable element. This prevents scroll chaining and the browser's native pull-to-refresh gesture. Supported in Chrome 63+, Firefox 59+, Safari 16+.

2. preventDefault on touchmove:
Call e.preventDefault() during touchmove when at scrollTop=0 and pulling down. Must use passive: false in addEventListener options (Chrome 56+ defaults touch events to passive).

3. meta viewport:
<meta name="viewport" content="... interactive-widget=resizes-content">

FAANG answer: Use overscroll-behavior CSS as the primary defense, preventDefault for cross-browser safety. Never rely solely on JavaScript — CSS solution is non-blocking and more reliable.

Q: Accessibility considerations for pull-to-refresh

// Problem: pull-to-refresh is a gesture — inaccessible to:
// - Screen reader users
// - Keyboard users
// - Users with motor impairments

// Solution 1: Provide a visible "Refresh" button
<button aria-label="Refresh feed"
        onclick="refresh()">↻ Refresh</button>

// Solution 2: aria-live region for status
<div role="status" aria-live="polite" class="sr-only">
  {{refreshing ? 'Refreshing feed...' : ''}}
</div>

// Solution 3: Keyboard shortcut
document.addEventListener('keydown', e => {
  if (e.key === 'F5' || (e.ctrlKey && e.key === 'r')) {
    e.preventDefault();
    refresh();
  }
});
FAANG answer: Pull-to-refresh must never be the only way to refresh. Always provide a visible button alternative and announce refresh state via aria-live. The gesture is an enhancement, not a requirement.
