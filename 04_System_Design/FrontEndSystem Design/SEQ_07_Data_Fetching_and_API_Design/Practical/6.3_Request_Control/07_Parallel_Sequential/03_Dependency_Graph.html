What Is a Dependency Graph (DAG)?

A Directed Acyclic Graph models request dependencies. Nodes are API calls; edges mean "must finish before". Independent nodes run in parallel; dependent nodes run in sequence.

// Dependency graph for a profile page:
//   user ──→ posts ──→ comments
//   user ──→ followers
//   categories (independent)

Optimal Scheduling

// Level 0 (parallel): user, categories
const [user, categories] = await Promise.all([
  fetchUser(), fetchCategories()
]);
// Level 1 (parallel, depends on user): posts, followers
const [posts, followers] = await Promise.all([
  fetchPosts(user.id), fetchFollowers(user.id)
]);
// Level 2 (depends on posts): comments
const comments = await fetchComments(posts[0].id);
3 sequential steps instead of 5 — maximum parallelism within each dependency level.

How Frameworks Solve This

React Query / TanStack Query: Each component declares its own data dependency. Independent queries run in parallel automatically. Dependent queries use the enabled option to wait for parent data.

Relay: Compiles a single GraphQL query from the component tree — the server resolves the dependency graph, eliminating client-side waterfalls entirely.

Browser Connection Reuse

When executing a DAG, the browser reuses TCP connections (HTTP keep-alive). Level-1 requests skip DNS + TLS because the connection from level-0 is still warm.

HTTP/2 multiplexing means all requests to the same origin share a single TCP connection — even parallel ones avoid connection overhead.

Server-Side DAG Resolution

GraphQL DataLoader batches and deduplicates within a single tick. The server builds its own dependency graph, resolving independent fields in parallel.

Moving the DAG to the server (RSC, BFF pattern) eliminates round-trip latency between levels — server→DB is microseconds vs client→server milliseconds.

Q: How do you model API dependencies for optimal fetching?

A: Build a DAG of requests. Group independent requests per level and use Promise.all within each level. Chain levels sequentially. This gives the theoretical minimum total latency.

Q: What's the difference between waterfall and dependency chain?

A: A waterfall is accidental sequential fetching of independent requests. A dependency chain is intentional — request B genuinely needs data from response A. The goal is to eliminate waterfalls while respecting real dependencies.

Q: How does React Suspense handle nested data dependencies?

A: Each Suspense boundary starts fetching when it renders. Without care, parent→child rendering creates waterfalls. Solutions: hoist fetches to a common ancestor, use useSuspenseQueries for parallel fetching, or prefetch in route loaders.

Q: What is the BFF (Backend for Frontend) pattern?

A: A thin server layer that aggregates multiple backend calls into a single response for the client. The BFF resolves the dependency graph server-side with low-latency internal calls, then sends one payload to the client — eliminating all client-side waterfalls.
