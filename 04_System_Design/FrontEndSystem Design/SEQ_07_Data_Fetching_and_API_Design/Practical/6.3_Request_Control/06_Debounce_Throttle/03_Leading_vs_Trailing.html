Edge Modes Explained

Leading (immediate): Fires on the first call, then ignores until the cooldown expires.
Trailing (default): Fires once after the last call + delay.
Both: Fires on the first call and once after the burst ends.

Implementation with Options

function debounce(fn, delay, { leading=false, trailing=true }={}) {
  let timer, lastArgs;
  return (...args) => {
    lastArgs = args;
    const callNow = leading && !timer;
    clearTimeout(timer);
    timer = setTimeout(() => {
      timer = null;
      if (trailing && lastArgs) fn(...lastArgs);
      lastArgs = null;
    }, delay);
    if (callNow) fn(...args);
  };
}

Timer Lifecycle

Leading edge: The first invocation is synchronous — no timer needed. The timer only exists to enforce the cooldown.
Trailing edge: Each call resets the timer via clearTimeout + setTimeout. The callback sits in the macro-task queue until the delay elapses.

Micro-task vs Macro-task Nuance

A leading-edge fire is synchronous (runs in the current micro-task turn). A trailing-edge fire is a macro-task (setTimeout). This means leading fires before any pending promises resolve in that turn.

Performance Consideration

Leading edge gives perceived instant response (good for button clicks). Trailing edge batches work (good for network calls). Using both is common for "instant feedback + final sync" patterns.

Q: Give a real-world use case for leading-edge debounce.

A "Submit Order" button — you want the first click to fire immediately, then ignore rapid repeated clicks to prevent duplicate orders.

Q: How does Lodash _.debounce handle maxWait?

maxWait sets an upper bound: even if calls keep coming, the function will fire after maxWait ms. This is effectively a throttle layered on top of debounce.

Q: How would you test a debounced function?

Use fake timers (jest.useFakeTimers()), call the function N times, advance time with jest.advanceTimersByTime(delay), and assert the inner function was called exactly once (or twice for both-edge mode).

Q: What happens if leading=false and trailing=false?

The function never fires — it's a no-op. Lodash guards against this, but a naive implementation would silently discard all calls.
