Production debugging — you can't use local DevTools

Debugging production is fundamentally different from local: no direct DevTools access, code is minified, bugs only reproduce under specific conditions (race conditions, specific user data, geographic edge cases). Tools: source maps (map minified → original), feature flags (narrow repro scope), structured logs + correlation IDs, session replay, and feature branches with extra debug logging. Senior engineers know how to diagnose without reproducing locally.

The debugger's toolkit
1. Sentry — error + stack trace (source-mapped)
2. Logs — structured JSON with context
3. Session replay — watch what the user saw
4. Feature flag — roll back suspect code to 0%
5. Network tab archive — HAR file from user
6. Canary deploy — enable extra debug logs for 1%
DEBUG flag pattern
Ship a hidden debug mode: ?debug=1 or localStorage.setItem('debug','true') — enables verbose logging, slower but more observable code paths. Never enabled by default. This is used at SAP to help support engineers reproduce customer issues.

⚠ Source maps must NOT be publicly served (exposes original code). Upload to Sentry/Datadog then delete from deploy artifact. Use hidden-source-map in webpack or nosources-source-map.

Debug mode + HAR export helper + conditional verbose logging

// ─── Debug mode activated via URL param or localStorage ───
const DEBUG = new URLSearchParams(location.search).has('debug') ||
              localStorage.getItem('debug') === 'true';

export const debugLog = DEBUG
  ? (...a: any[]) => console.log('[DEBUG]', ...a)
  : () => {}; // no-op in production

// ─── Verbose state logging in debug mode ───
function useDebugStore<T>(name: string, store: T) {
  useEffect(() => {
    if (DEBUG) debugLog(`Store [${name}] changed:`, store);
  }, [store]);
}

// ─── HAR file collection helper ───
// Instruct user: DevTools → Network → Right-click → "Save all as HAR"
// Then send the file to support. HAR contains all request/response data.

// ─── Vite: hidden source maps (not publicly accessible) ───
export default {
  build: {
    sourcemap: 'hidden', // generates .map files but no //# sourceMappingURL comment
  },
  plugins: [sentryVitePlugin({ authToken: process.env.SENTRY_AUTH_TOKEN })
  // ^^ uploads maps to Sentry, then Sentry deletes them from server
  ]
};
