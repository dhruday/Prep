Cache the permission set, not individual checks

❌ Cache individual checks (exponential)
perm:user1:invoice:read  = true
perm:user1:invoice:write = false
perm:user1:report:read   = true
// N users × M permissions = too many keys
✅ Cache permission SET (linear)
perm:org_abc:user1 = ["invoice:read","report:read"]
// 1 key per user, O(1) Set.has() check in-memory
// TTL: 5 minutes
Key naming rule
perm:tenantId:userId — tenantId prevents cross-tenant cache collisions

Redis permission cache with event-driven invalidation

class PermissionCacheService {
  private key(t:string, u:string) { return `perm:${t}:${u}`; }

  async get(userId:string, tenantId:string): Promise<Set<string>> {
    const cached = await redis.get(this.key(tenantId, userId));
    if (cached) return new Set(JSON.parse(cached));

    const perms = await permRepo.load(userId, tenantId);
    await redis.setex(this.key(tenantId, userId), 300, JSON.stringify([...perms]));
    return perms;
  }

  // Called by role-change event handler
  async invalidate(userId:string, tenantId:string) {
    await redis.del(this.key(tenantId, userId));
  }
}
