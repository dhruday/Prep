The over-globalisation anti-pattern

Putting everything in global state (Redux/Zustand) causes: unnecessary re-renders across the entire tree, tight coupling between unrelated components, hard-to-trace bugs, and bloated store. The principle of co-location: state should live as close to where it's needed as possible.

Re-render impact — over-global vs colocated

Every time local state updates, only the owning component should re-render. Global state change triggers all subscribers.

State co-location patterns

// ❌ Over-global — modal state in Zustand
const useStore = create()(set => ({
  isModalOpen: false,  // should NOT be here
  cart: [],              // OK to be here
  openModal: () => set({ isModalOpen: true }),
}));

// ✅ Local state for modal
const OrdersPage = () => {
  const [isModalOpen, setModalOpen] = useState(false);
  return (
    <>
      <Button onClick={() => setModalOpen(true)}>New Order</Button>
      {isModalOpen && <OrderModal onClose={() => setModalOpen(false)} />}
    </>
  );
};

// ✅ Rules of thumb for global state:
// 1. Used by ≥2 sibling feature subtrees
// 2. Persisted across route changes (cart, auth)
// 3. Reset explicitly (not on component unmount)
// ✅ Everything else → local or lifted state
