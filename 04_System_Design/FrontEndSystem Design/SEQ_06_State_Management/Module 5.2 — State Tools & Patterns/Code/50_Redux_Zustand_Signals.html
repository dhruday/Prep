Three state management philosophies

🏛️ Redux
Single store, strict unidirectional flow. Actions → Reducers → State. Predictable via devtools time-travel. Verbose but explicit.
🐻 Zustand
Minimal store, no boilerplate. Direct mutation via immer (optional). React hook as selector. Best for medium-complexity apps.
⚡ Signals
Fine-grained reactivity. Only components subscribed to a signal re-render. No VDOM diffing — directly propagates changes. Angular 17+, Preact, SolidJS.

All three patterns in TypeScript

// ─── Zustand (minimal, preferred for New React) ───
import { create } from 'zustand';
interface CounterStore { count: number; inc(): void; dec(): void }
const useCounter = create<CounterStore>()((set) => ({
  count: 0,
  inc: () => set(s => ({ count: s.count + 1 })),
  dec: () => set(s => ({ count: s.count - 1 })),
}));

// ─── Redux Toolkit (action-reducer pattern) ───
import { createSlice } from '@reduxjs/toolkit';
const counterSlice = createSlice({
  name: 'counter',
  initialState: { count: 0 },
  reducers: {
    inc: s => { s.count++ },
    dec: s => { s.count-- },
  }
});
export const { inc, dec } = counterSlice.actions;

// ─── Angular Signals (Angular 17+) ───
import { signal, computed } from '@angular/core';
const count = signal(0);
const doubled = computed(() => count() * 2); // auto-tracks
count.update(c => c + 1); // only re-renders consumers of count
