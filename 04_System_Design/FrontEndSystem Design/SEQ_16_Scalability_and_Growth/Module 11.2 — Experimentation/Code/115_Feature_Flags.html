Feature flags: decouple deployment from release — ship code dark, turn on features without deploying

Feature flags are runtime configuration that can change feature availability without redeployment. They enable: (1) trunk-based development (no long-lived feature branches), (2) canary releases (enable for 1% → 10% → 100%), (3) killswitches (instant rollback without redeploy), (4) A/B testing (different UX for different users). SAP uses Feature Toggle Service (FTS) across its BTP suite for exactly this pattern.

Benefits
✅ Instant rollback (no git revert)
✅ Reduce PR review risk
✅ Test in production safely
✅ Gradual rollout by percentage
✅ Target specific users / orgs
Risks
⚠️ Flag debt (stale flags never cleaned)
⚠️ Combinatorial explosion (2^n flags)
⚠️ Performance if flags not cached
⚠️ Leaking unreleased features in bundle
⚠️ Testing burden (flag ON + flag OFF)

React useFeatureFlag hook + TypeScript flag registry

// ─── Flag registry with strong typing ───
type Flags = {
  new_checkout_flow: boolean;
  ai_recommendations: boolean;
  max_search_results: number; // multivariate flag
};

// ─── LaunchDarkly-style hook ───
function useFeatureFlag<K extends keyof Flags>(key: K): Flags[K] {
  const flags = useContext(FlagContext);
  return flags[key];
}

// ─── Usage in component ───
function CheckoutPage() {
  const newFlow = useFeatureFlag('new_checkout_flow');
  return newFlow
    ? <NewCheckout />
    : <LegacyCheckout />;
}

// ─── Provider bootstraps flags from remote ───
async function bootstrapFlags(userId: string): Promise<Flags> {
  const res = await fetch(`/api/flags?user=${userId}`);
  return res.json(); // server evaluates rules, sends resolved values
}
