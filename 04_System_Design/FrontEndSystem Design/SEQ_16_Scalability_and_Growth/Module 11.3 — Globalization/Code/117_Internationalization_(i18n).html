i18n vs l10n: separate structure (i18n) from locale-specific content (l10n)

Internationalization (i18n) = designing the app so it CAN be adapted. Localization (l10n) = providing the actual translations. Key areas: (1) string extraction to message catalogs, (2) date/number/currency formatting via Intl API, (3) plural rules (English: 1 item / N items; Arabic has 6 forms), (4) RTL layout support, (5) font and character set handling. SAP ships products in 40+ languages — i18n is foundational to every UI5/Fiori component.

What to externalize
All UI strings
Date format (MM/DD vs DD/MM)
Number format (1,000.00 vs 1.000,00)
Currency symbol position
Plural forms
Sort order (collation)
What changes per locale
Text direction (LTR ↔ RTL)
Layout mirroring (Arabic, Hebrew)
Image/icon localization
Legal text per country
Color meaning (red = danger in West; luck in China)

// ─── i18n config (i18next) ───
i18next.init({
  lng: 'en', fallbackLng: 'en',
  resources: {
    en: { translation: {
      greeting: 'Hello, {{name}}!',
      items: '{{count}} item',
      items_other: '{{count}} items',
    }},
    de: { translation: {
      greeting: 'Hallo, {{name}}!',
      items: '{{count}} Artikel',
      items_other: '{{count}} Artikel',
    }}
  }
});

// ─── In React component ───
const { t } = useTranslation();
// Plural award resolution, variable interpolation
<p>{t('items', { count: cart.length })}</p>

// ─── Currency/Number with Intl ───
const formatCurrency = (amount: number, locale: string, currency: string) =>
  new Intl.NumberFormat(locale, { style: 'currency', currency }).format(amount);

formatCurrency(1234.5, 'de-DE', 'EUR'); // "1.234,50 €"
formatCurrency(1234.5, 'en-US', 'USD'); // "$1,234.50"
