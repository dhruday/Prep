Monolithic Frontend — Definition

A monolithic frontend is a single deployable unit where all UI code, business logic, routing, and state live in one application. One codebase, one build, one deployment.

✅ Strengths
Simple toolchain
Easy E2E testing
Unified type safety
Shared UI components
Lower ops overhead
Good for small teams
❌ Weaknesses
Slow builds at scale
Deploy everything for 1 change
Team coordination friction
Shared style leakage
Hard to adopt new tech
Single point of failure

Hruday's SAP Context

SAP Fiori started as a monolith — one Angular app with 200+ features. Build time hit 18 minutes. Any hotfix to one module required full re-deploy. Migrating to Module Federation (Webpack 5) brought it to 3 modules independently deployable, with build time down to 4 minutes per module.

Typical Monolith Folder Structure

src/
├── components/       // Shared UI — often becomes tightly coupled
│   ├── Button.tsx
│   ├── Modal.tsx
│   └── DataTable.tsx
├── pages/            // Route components
│   ├── Dashboard.tsx
│   ├── Orders.tsx
│   └── Analytics.tsx
├── store/            // Global Redux/Zustand — one big store
│   ├── userSlice.ts
│   ├── ordersSlice.ts
│   └── analyticsSlice.ts
├── services/         // API clients — no boundary enforcement
├── utils/
└── App.tsx           // Single root — everything wires HERE
When monolith is correct: Team < 5 devs, early product, single domain, fast iteration needed. Don't prematurely split.
