Session Fixation Attack

// Session Fixation: Attacker sets the session ID BEFORE the user logs in

// Step 1: Attacker gets a valid session ID
// Visit the site → receive session cookie: sid=ATTACKER_SESSION

// Step 2: Attacker tricks victim into using that session
// Via URL: https://bank.com/login?sid=ATTACKER_SESSION
// Via XSS: document.cookie = "sid=ATTACKER_SESSION"
// Via meta tag: <meta http-equiv="Set-Cookie" content="sid=ATTACKER_SESSION">

// Step 3: Victim logs in with the attacker's session ID
// The server associates ATTACKER_SESSION with the victim's account

// Step 4: Attacker uses ATTACKER_SESSION → logged in as victim!

Session Hijacking Attack

// Session Hijacking: Attacker steals an EXISTING valid session

// Methods:
// 1. XSS → document.cookie → steal session cookie (if no HttpOnly)
// 2. Network sniffing → intercept session cookie (if no HTTPS/Secure)
// 3. Man-in-the-Middle → intercept/modify traffic
// 4. Malware → browser credential theft
// 5. Shoulder surfing → physical observation

// Session Replay: Reuse a captured session/token
// Even expired sessions may work if server doesn't validate expiry

Defense Matrix

// PREVENTION — Session Fixation:
// 1. Regenerate session ID on login
app.post('/login', (req, res) => {
  if (validCredentials) {
    req.session.regenerate(() => { // ← NEW session ID!
      req.session.user = authenticatedUser;
      res.redirect('/dashboard');
    });
  }
});

// 2. Regenerate on privilege change
// Password change, role change, 2FA verification

// PREVENTION — Session Hijacking:
// 1. HttpOnly cookies — block XSS theft
// 2. Secure flag — block network sniffing
// 3. Session binding — tie to IP + User-Agent
// 4. Short session lifetime — reduce exposure window
// 5. Absolute timeout — force re-auth after X hours
// 6. Concurrent session limits — detect hijacking

// PREVENTION — Session Replay:
// 1. Short-lived tokens (JWT exp claim)
// 2. Token rotation on each use (refresh tokens)
// 3. Nonce-based requests (one-time use tokens)

Google Senior Frontend — Session Security

Q: Design a session management system that detects and prevents hijacking in real-time.

1. Session metadata: Store IP, User-Agent, geolocation, device fingerprint with each session. 2. Anomaly detection: If request comes from a different IP/country than session creation, trigger step-up authentication (re-enter password or MFA). 3. Concurrent session monitoring: If same user is active from 2 different IPs simultaneously, alert and optionally invalidate the suspicious session. 4. Device tracking: Register known devices via a persistent secure cookie. New device = mandatory MFA. 5. Session activity log: Visible to user (like Google's "Security" → "Recent security activity"). Google adds: risk scoring based on typing patterns, mouse movement, and interaction timing to detect bot-driven session abuse.
