Q: Why are passkeys better than TOTP for preventing phishing?

TOTP codes are transferable — a user on a fake login page will type their 6-digit code, and the attacker relays it to the real site. Passkeys (WebAuthn) are origin-bound: the cryptographic challenge includes the origin (e.g., google.com). A fake site (g00gle.com) gets a different origin → the authentication fails automatically. The user doesn't need to verify the URL — the browser/credential does it cryptographically. This is why Google mandated FIDO security keys for all 85,000+ employees in 2017, reducing phishing to zero.

Q: How do you handle MFA recovery without compromising security?

Recovery codes: 10 single-use codes, hashed in DB, shown once during setup. Backup device: Register multiple WebAuthn devices. Trusted contacts: Similar to Facebook's trusted contacts (requires social verification). Hardware backup: Recommend users have 2 security keys. Never use: SMS recovery, security questions (easily researched). Google's approach: Combination of backup codes + backup security key + account recovery flow with identity verification (takes 3-5 business days for security).
