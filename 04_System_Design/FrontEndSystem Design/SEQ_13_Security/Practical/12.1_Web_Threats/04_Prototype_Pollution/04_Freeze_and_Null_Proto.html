Object.freeze(Object.prototype)

// The nuclear option — prevents ALL modifications to Object.prototype

// Before freeze:
Object.prototype.evil = 'yes'; // ✅ works

// After freeze:
Object.freeze(Object.prototype);
Object.prototype.evil = 'yes'; // ❌ silently fails (sloppy mode)
// OR TypeError (strict mode)

// Also freezes:
Object.freeze(Array.prototype);   // prevent Array pollution
Object.freeze(String.prototype);  // prevent String pollution

// When to use:
// ✅ New projects with no legacy polyfills
// ✅ Security-critical applications (payments, auth)
// ❌ Avoid if using libraries that extend prototypes

Object.create(null) — Prototype-less Objects

// Regular object inherits from Object.prototype:
const obj = {}; // obj.__proto__ → Object.prototype
obj.toString;   // [Function: toString] (inherited)

// Null-prototype object has NO prototype:
const safe = Object.create(null);
safe.__proto__;     // undefined
safe.toString;      // undefined
safe.constructor;   // undefined
safe.hasOwnProperty; // undefined

// Perfect for dictionaries/lookup tables:
const cache = Object.create(null);
cache['__proto__'] = 'value'; // Just a regular key! No pollution!
cache['constructor'] = 'value'; // Just a regular key!

// Used in Node.js for require cache, Express locals, etc.

Google Senior Frontend — Object Security

Q: When should you use Map vs Object?

Use Map when: (1) keys are user-supplied (prevents prototype pollution), (2) keys are not strings (Map supports any key type), (3) you need ordered iteration (Map preserves insertion order), (4) you need .size (Object requires Object.keys().length). Use Object when: (1) you need JSON serialization directly, (2) you're defining known-shape data (records/structs), (3) property access syntax is important. In Google's security-sensitive code: Map for caches and lookup tables, Object for typed data.

Q: How does V8 optimize null-prototype objects differently?

V8 doesn't need to check the prototype chain for null-prototype objects. Property lookup stops at the object itself — there's no prototype to walk. This makes property access faster for "miss" cases (when the key doesn't exist). V8's hidden class for Object.create(null) has a null transition target, so the JIT-compiled code knows to skip prototype chain walking. In practice, the performance difference is negligible for small objects but measurable for hot paths with Map/dictionary lookups.
