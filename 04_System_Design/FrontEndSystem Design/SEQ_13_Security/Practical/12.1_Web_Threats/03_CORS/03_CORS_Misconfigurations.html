Origin Reflection Attack

// VULNERABLE server code:
app.use((req, res, next) => {
  res.setHeader('Access-Control-Allow-Origin', req.headers.origin);
  res.setHeader('Access-Control-Allow-Credentials', 'true');
  next();
});

// Attacker on evil.com:
const res = await fetch('https://api.bank.com/account', {
  credentials: 'include'  // sends victim's cookies
});
const data = await res.json(); // ← CAN read response because ACAO matches!
// Sends victim's account data to attacker's server

Secure CORS Configuration

// CORRECT: Explicit allowlist with exact match
const ALLOWED_ORIGINS = new Set([
  'https://app.example.com',
  'https://admin.example.com',
  'https://staging.example.com'
]);

app.use((req, res, next) => {
  const origin = req.headers.origin;
  if (ALLOWED_ORIGINS.has(origin)) {
    res.setHeader('Access-Control-Allow-Origin', origin);
    res.setHeader('Access-Control-Allow-Credentials', 'true');
    res.setHeader('Vary', 'Origin'); // CRITICAL for CDN caching
  }
  // If origin not in allowlist → no ACAO header → browser blocks
  next();
});

// IMPORTANT: Always set Vary: Origin when ACAO changes per request
// Without it, CDNs may cache one origin's ACAO and serve it to others

Google Senior Frontend — CORS Misconfig

Q: During a security review, you find a service echoing the Origin header. How do you escalate?

Severity: Critical if credentials are used. Demonstrate the attack: create an HTML page on any domain that fetches the API with credentials:include and reads the response. Show that any attacker-controlled domain can steal user data. Fix: replace origin reflection with an explicit allowlist. Interim mitigation: remove Access-Control-Allow-Credentials. Permanent: add CORS validation at the API gateway layer.

Q: Why must you set "Vary: Origin" with dynamic ACAO?

Without Vary: Origin, a CDN may cache the response with ACAO: https://app.com and serve that cached response to a request from https://other.com. Other.com would then be able to read the response (the cached ACAO doesn't match their origin, so the browser would actually block it — but worse: a request from app2.com might get a cached response with the wrong ACAO). The Vary header tells caches to store separate entries per Origin value.
