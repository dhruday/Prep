Transport Layer Security

// HTTPS = HTTP + TLS
// TLS provides: Encryption, Integrity, Authentication

// TLS 1.3 (current standard):
// - 1 round-trip handshake (vs 2 in TLS 1.2)
// - 0-RTT resumption (subsequent connections)
// - Removed unsafe ciphers: RC4, 3DES, SHA-1
// - Perfect Forward Secrecy mandatory

// What HTTPS protects:
// ✅ Data in transit (encrypted)
// ✅ Man-in-the-middle attacks (certificate verification)
// ✅ Cookie theft on network (Secure flag requires HTTPS)
// ✅ Required for: Service Workers, WebAuthn, Geolocation, etc.

// What HTTPS does NOT protect:
// ❌ Data at rest (server/client storage)
// ❌ XSS, CSRF, SQL injection (application-layer attacks)
// ❌ DNS-level tracking (use DoH/DoT for that)

🧪 Connection Security Check

HSTS (HTTP Strict Transport Security)

// HSTS tells browsers: "Always use HTTPS for this domain"

// Server header:
Strict-Transport-Security: max-age=63072000; includeSubDomains; preload

// max-age: 2 years (in seconds)
// includeSubDomains: applies to all *.example.com
// preload: eligible for browser preload list

// HSTS Preload List:
// Hardcoded in browsers (Chrome, Firefox, Safari, Edge)
// Submit at: https://hstspreload.org
// Even the FIRST visit uses HTTPS (no HTTP → redirect)

// Without HSTS:
// 1. User types example.com → browser sends HTTP
// 2. Server redirects to HTTPS
// 3. MITM can intercept during step 1 (SSL stripping)

// With HSTS:
// 1. Browser knows to use HTTPS directly
// 2. No HTTP request ever sent → no interception window

Google Senior Frontend — Transport Security

Q: Your app loads an image over HTTP on an HTTPS page. What happens?

This is "mixed content." Browsers handle it differently by type: (1) Passive mixed content (images, video, audio): Chrome shows a warning but loads it. Firefox/Safari may block. The padlock icon is downgraded. (2) Active mixed content (scripts, stylesheets, iframes, fetch): BLOCKED by all modern browsers. No fallback. Your JS/CSS simply won't load. Fix: (1) Use protocol-relative URLs (//cdn.example.com) or always https://. (2) Set Content-Security-Policy: upgrade-insecure-requests — tells the browser to automatically upgrade HTTP to HTTPS. (3) Audit with: document.querySelectorAll('[src^="http:"]') to find HTTP resources. (4) For third-party content: if they don't support HTTPS, find an alternative. Never downgrade your security for a third-party resource.
