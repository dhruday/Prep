Webpack SRI Integration

// Install: npm install webpack-subresource-integrity

// webpack.config.js
const { SubresourceIntegrityPlugin } = require('webpack-subresource-integrity');

module.exports = {
  output: {
    crossOriginLoading: 'anonymous', // Required!
  },
  plugins: [
    new SubresourceIntegrityPlugin({
      hashFuncNames: ['sha384'],
      enabled: process.env.NODE_ENV === 'production',
    }),
  ],
};

// What it does:
// 1. After Webpack emits chunks, computes SHA-384 of each file
// 2. Injects integrity attributes into HTML (via HtmlWebpackPlugin)
// 3. For dynamic imports: patches __webpack_require__ to include integrity

// Generated HTML:
<script
  src="/static/js/main.a1b2c3.js"
  integrity="sha384-autogenerated_hash"
  crossorigin="anonymous"
></script>

// For async chunks loaded via import():
// The runtime includes integrity map: chunkId → hash
// Dynamic <script> tags get integrity set automatically

Vite & Next.js SRI

// ═══ Vite ═══
// vite.config.js — built-in SRI support (Vite 4+)
export default defineConfig({
  build: {
    // Not built-in — use plugin:
  },
  plugins: [
    sriPlugin({ algorithm: 'sha384' }),
  ],
});

// Or manual postbuild script:
// 1. Build normally
// 2. Run generate-sri.js (from Lab 02)
// 3. Inject integrity attrs into index.html

// ═══ Next.js ═══
// next.config.js
module.exports = {
  // Next.js has experimental SRI support:
  experimental: {
    sri: {
      algorithm: 'sha384',
    },
  },
};

// What Next.js does:
// 1. Computes hashes of all generated chunks
// 2. Adds integrity attr to <script> and <link> tags
// 3. Works with both Pages Router and App Router
// 4. Supports streaming SSR (hashes pre-computed at build)

// ═══ Create React App ═══
// No built-in SRI. Options:
// 1. Eject and add webpack-subresource-integrity
// 2. Use react-app-rewired with SRI config override
// 3. Manual postbuild script

CI/CD Pipeline for SRI

# GitHub Actions example
name: Build with SRI

on: push

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install dependencies
        run: npm ci

      - name: Build
        run: npm run build

      - name: Generate SRI manifest
        run: |
          # generate-sri.sh
          for file in dist/assets/*.{js,css}; do
            hash=$(openssl dgst -sha384 -binary "$file" | openssl base64 -A)
            echo "$file: sha384-$hash"
          done > dist/sri-manifest.txt

      - name: Verify SRI in HTML
        run: |
          # Check that every <script> and <link> has integrity attr
          if grep -E '<(script|link).*src=.*cdn' dist/index.html \
             | grep -v 'integrity='; then
            echo "ERROR: CDN resources missing SRI!"
            exit 1
          fi
          echo "✅ All CDN resources have SRI"

      - name: Deploy
        run: # deploy to CDN/server

# Also add to renovate/dependabot config:
# When dependencies update, SRI hashes must be regenerated
# Automated tests should verify SRI hashes match

Google Senior Frontend — Build Integration

Q: What are the operational challenges of SRI at scale?

At Google/FAANG scale: (1) Hash staleness: Deploy HTML and JS separately (common in microservices). New JS deployed → old HTML has old hash → SRI breaks for users between deploys. Fix: Atomic deploys, or manifest service. (2) CDN cache invalidation: CDN serves old file with old hash, then new hash arrives in HTML. SRI mismatch. Fix: Deploy assets first, wait for CDN propagation, then deploy HTML. (3) Multi-region: Different CDN PoPs may serve different versions during rollout. Fix: Blue-green deploy with CDN purge confirmation. (4) A/B testing: Different experiments serve different JS bundles. Each needs unique SRI hash. Fix: SRI manifest per experiment variant. (5) Third-party scripts: Marketing tags (GTM, analytics) change without your knowledge → breaks SRI. Fix: Self-host or don't use SRI for these. Monitor with CSP reporting. (6) Monitoring: Track SRI failure rate in RUM (Real User Monitoring). Alert if SRI failures spike → possible compromise OR deploy issue. Correlate with deploy events to distinguish.
