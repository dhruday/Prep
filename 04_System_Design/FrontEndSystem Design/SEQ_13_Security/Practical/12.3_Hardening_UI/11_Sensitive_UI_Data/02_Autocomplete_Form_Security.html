Autocomplete Attack Vectors

// 1. HIDDEN FIELD AUTOFILL
// Attacker creates hidden fields with autocomplete names:
<input type="hidden" autocomplete="cc-number">
<input type="hidden" autocomplete="cc-exp">
// Browser may fill these with saved credit card data!
// Attacker submits form → steals card info

// 2. SHARED COMPUTER LEAKAGE
// User fills sensitive form on shared computer
// Browser saves: name, email, address, CC number
// Next user sees previous user's data in autocomplete

// 3. BROWSER EXTENSION AUTOFILL
// Password managers may aggressively fill forms
// Could fill credentials into wrong forms
// Or phishing pages that mimic real forms

// "off" — request browser NOT to autocomplete (not always honored)

Form Security Checklist

// ✅ Sensitive financial fields: autocomplete="off"
// ✅ New passwords: autocomplete="new-password"
// ✅ OTP fields: autocomplete="one-time-code"
// ✅ Use type="password" for CVV and sensitive numbers
// ✅ Clear sensitive fields on page unload
window.addEventListener('beforeunload', () => {
  document.querySelectorAll('input[type="password"]')
    .forEach(i => i.value = '');
});

// ✅ Use inputmode for mobile keyboards
// inputmode="numeric" for card numbers
// inputmode="tel" for phone numbers

// ✅ Prevent copy/paste on CVV
input.addEventListener('copy', e => e.preventDefault());
input.addEventListener('cut', e => e.preventDefault());

// ⚠️ autocomplete="off" is a REQUEST, not a command
// Chrome may still autofill if it recognizes the field
// Workaround: use random name attributes

Google Senior Frontend — Form Security

Q: Chrome ignores autocomplete="off" on some fields. How do you prevent autofill?

Chrome intentionally ignores autocomplete="off" for login forms (they believe password managers improve security). Workarounds: (1) Use autocomplete="new-password" for password fields you don't want filled. (2) For non-password fields: use a random/non-standard autocomplete value like autocomplete="nope" or autocomplete="do-not-autofill". (3) Use readonly + onfocus to delay: the field starts readonly, onfocus removes readonly. Chrome won't autofill readonly fields. (4) For credit card fields in PCI-compliant apps: use an iframe from the payment processor (Stripe Elements). The iframe is cross-origin, so the parent page's autofill doesn't reach it. This is also why payment iframes exist — browser autofill isolation.
