Frontend Data Leak Prevention Checklist

// ═══ URL & REFERRER ═══
☐ No sensitive data in URLs (tokens, PII, API keys)
☐ Referrer-Policy: strict-origin-when-cross-origin
☐ no-referrer on password reset and sensitive pages
☐ history.replaceState to clean URLs after token consumption
☐ rel="noreferrer noopener" on external links

// ═══ STORAGE ═══
☐ No tokens in localStorage (use memory or HttpOnly cookies)
☐ Logout clears: localStorage, sessionStorage, IndexedDB
☐ Logout clears: Service Worker caches, cookies
☐ No PII in console.log in production
☐ Blob URLs revoked after use

// ═══ NETWORK ═══
☐ HTTPS everywhere (no mixed content)
☐ Cache-Control: no-store on authenticated responses
☐ No sensitive data in GET request parameters
☐ postMessage: validate origin, specific target
☐ fetch: credentials:'same-origin' by default

// ═══ UI ═══
☐ Input type="password" for sensitive fields
☐ autocomplete="off" where appropriate
☐ Data masking for SSN, credit cards in UI
☐ Copy protection on sensitive data (user.select disabled)

// ═══ ERRORS ═══
☐ No stack traces in production error responses
☐ No DB queries or internal IPs in error messages
☐ Generic error messages for auth failures

Monitoring for Data Leaks

// Proactive leak monitoring:

// 1. CSP violation reports
//    Detect unauthorized data exfiltration attempts
Content-Security-Policy: connect-src 'self'; report-uri /csp-report

// 2. Audit logging
//    Log all data access on the server
//    Detect: unusual volumes, off-hours access, bulk exports

// 3. Network monitoring
//    Performance Observer API to monitor requests:
const observer = new PerformanceObserver((list) => {
  list.getEntries().forEach(entry => {
    if (!isTrustedDomain(entry.name)) {
      reportSuspiciousRequest(entry);
    }
  });
});
observer.observe({ type: 'resource', buffered: true });

Google Senior Frontend — Data Leak Prevention

Q: Design a comprehensive data leak prevention strategy for a healthcare app.

Healthcare (HIPAA compliance) requires strictest DLP: (1) Data classification: Tag all data as PHI, PII, or public. Different handling per classification. (2) Transport: HTTPS only. HSTS preloaded. Certificate pinning for mobile. No data in URLs. (3) Storage: No PHI in localStorage/sessionStorage. In-memory only for display. IndexedDB encrypted (via Web Crypto) if offline mode needed. (4) Display: Data masking on patient lists (only initials). Full detail behind explicit click (audit logged). Auto-lock screen after 2 min inactivity. (5) Printing/Export: Watermark with logged-in user's ID. Export generates audit trail. Screenshot detection (Page Visibility API overlay). (6) Logout: Aggressive cleanup — all storage, all caches, replace history entries with blank. (7) Access control: Role-based — nurse vs doctor vs admin see different fields. Column-level encryption in database. (8) Monitoring: All data access logged. Anomaly detection: doctor accessing 100 patient records in an hour. Real-time alerts.
