1. What is Clickjacking?

// Clickjacking = UI redressing attack
// Attacker loads your site in an invisible iframe
// Overlays their own decoy UI on top
// User thinks they're clicking on the decoy → actually clicking your site
//
// Example attack:
// 1. evil.com embeds: <iframe src="https://bank.com/transfer" style="opacity:0">
// 2. Positions "Win a Prize!" button exactly over bank's "Confirm Transfer"
// 3. User clicks "Win a Prize!" → actually clicks "Confirm Transfer"
// 4. Bank processes the transfer (user is logged in, cookie sent)
//
// Variants:
// - Likejacking: Click "Play video" → actually "Like" on Facebook
// - Cursorjacking: Move cursor offset to misalign clicks
// - Drag-and-drop: User drags content into hidden iframe
// - Double-click: First click opens real UI, second clicks within it

2. Defense: X-Frame-Options (Legacy)

// HTTP response header — tells browser whether page can be framed

X-Frame-Options: DENY           // Never allow framing
X-Frame-Options: SAMEORIGIN     // Allow framing only from same origin

// Limitations:
// ❌ Only two values (DENY or SAMEORIGIN) — no specific origin allow
// ❌ Inconsistent browser handling with nested iframes
// ❌ Being superseded by CSP frame-ancestors
//
// Still set it as fallback for older browsers

3. Defense: CSP frame-ancestors (Modern)

// More powerful than X-Frame-Options

Content-Security-Policy: frame-ancestors 'none'
// Same as X-Frame-Options: DENY — no framing at all

Content-Security-Policy: frame-ancestors 'self'
// Same as SAMEORIGIN — only same origin can frame

Content-Security-Policy: frame-ancestors 'self' https://trusted.com
// Allow specific origins to frame — not possible with X-Frame-Options!

// Advantages over X-Frame-Options:
// ✅ Can specify multiple trusted origins
// ✅ Consistent behavior across browsers
// ✅ Part of the CSP standard (one header for many policies)
// ✅ Works with nested iframes correctly
Set BOTH headers for maximum compatibility: X-Frame-Options: DENY and CSP frame-ancestors 'none'. The CSP directive takes precedence in modern browsers.

JavaScript Frame-Busting (Fallback)

// Legacy defense: detect if you're in an iframe and break out

// Simple (easily defeated):
if (window.top !== window.self) {
  window.top.location = window.self.location;
}

// Problem: attacker can prevent navigation:
// window.onbeforeunload = () => false;
// Or use sandbox="allow-forms" without "allow-top-navigation"

// Better: hide content until verified not in iframe
<style>body { display: none !important; }</style>
<script>
  if (self === top) {
    document.body.style.display = 'block';
  } else {
    top.location = self.location; // Try to break out
  }
</script>

// ⚠️ JS frame-busting is NOT reliable — always use headers
// Headers (CSP frame-ancestors) are enforced by the browser
// before the page even loads

FAANG Interview Questions

Q1: What is clickjacking and how do you prevent it?
Clickjacking is a UI redressing attack where the attacker embeds your site in a transparent iframe, overlays a decoy UI, and tricks users into clicking elements on your site (like "Delete Account" or "Transfer Funds"). The user sees the decoy and doesn't realize they're interacting with your site through the invisible iframe. Prevention: (1) CSP frame-ancestors 'none' — modern, powerful, supports specific origin whitelisting. (2) X-Frame-Options: DENY — legacy, still set for older browser compat. (3) Both headers together for defense in depth. For apps that NEED to be framed (widget, embed): use frame-ancestors 'self' https://trusted-partner.com to whitelist specific embedders. Don't rely on JavaScript frame-busting — it can be bypassed via sandbox attribute or beforeunload handlers.
Follow-up: How does the double-click clickjacking variant work?
Q2: Your app needs to be embedded in a partner's website. How do you allow this safely?
Controlled framing with strict boundaries: (1) Set CSP frame-ancestors to only the partner's origin: frame-ancestors 'self' https://partner.com. Not a wildcard. (2) Use postMessage for cross-origin communication between the iframe and parent — validate the origin of every message: if (event.origin !== 'https://partner.com') return. (3) Add the sandbox attribute on the partner's side to restrict what the embedded content can do: sandbox="allow-scripts allow-same-origin" (but NOT allow-top-navigation). (4) Scope the embedded content — create a separate, minimal page for embedding rather than framing your full app. Reduce the attack surface. (5) Monitor: log embed usage (check Referer header) to detect if unauthorized sites are framing you. (6) Consider window.frameElement check on load to verify the framing context.
Follow-up: What's the difference between CSP frame-ancestors and sandbox?

1. Express Security Headers (Helmet)

import helmet from 'helmet';

app.use(helmet({
  frameguard: { action: 'deny' }, // X-Frame-Options: DENY
  contentSecurityPolicy: {
    directives: {
      frameAncestors: ["'none'"],  // CSP frame-ancestors 'none'
    },
  },
}));

// For embeddable widget pages:
app.use('/embed', helmet({
  frameguard: false, // Disable X-Frame-Options
  contentSecurityPolicy: {
    directives: {
      frameAncestors: ["'self'", 'https://partner.com'],
    },
  },
}));

2. Secure postMessage Communication

// Parent page (partner.com):
const iframe = document.querySelector('iframe');
iframe.contentWindow.postMessage(
  { type: 'INIT', data: {} },
  'https://your-app.com' // ALWAYS specify target origin
);

// Iframe (your-app.com):
window.addEventListener('message', (event) => {
  // CRITICAL: validate origin
  if (event.origin !== 'https://partner.com') return;

  // Validate message structure
  if (typeof event.data !== 'object') return;
  if (!event.data.type) return;

  switch (event.data.type) {
    case 'INIT': handleInit(event.data); break;
    default: break; // Ignore unknown messages
  }
});

Clickjacking Prevention Checklist

✅ Set Content-Security-Policy: frame-ancestors 'none' (default)
✅ Set X-Frame-Options: DENY (legacy browsers)
✅ For embeddable pages: frame-ancestors with specific origins only
✅ Validate postMessage origin (never use '*' for sensitive data)
✅ Don't rely solely on JS frame-busting (bypassable)
✅ Sensitive actions: require re-authentication or confirmation dialog
✅ Test: try framing your pages in an iframe → should be blocked
✅ Monitor Referer logs for unauthorized embedding attempts
✅ Use sandbox attribute when embedding third-party content
✅ Double-click protection: add delay between clicks on critical actions
