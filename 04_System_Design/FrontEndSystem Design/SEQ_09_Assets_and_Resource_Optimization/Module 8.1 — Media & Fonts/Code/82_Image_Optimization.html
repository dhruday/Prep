Image optimization — the biggest quick win on most pages

Images account for ~50-60% of average webpage bytes. At SAP Fiori, switching uncompressed PNGs to WebP with lazy loading cut page weight from 3.8 MB → 900 KB and improved LCP from 4.1 s → 1.6 s.

Format hierarchy (2024)
  • 1. AVIF — 50% smaller than WebP, perfect color. Limited older browser support.
  • 2. WebP — 30% smaller than JPEG/PNG. Near-universal support.
  • 3. JPEG/PNG (fallback) — use only when WebP unavailable.
  • 4. SVG — icons, logos, illustrations. Infinitely scalable, tiny.
Core techniques
  • 📐 Intrinsic sizing — serve right dimensions per device
  • 😴 Lazy loading — loading="lazy" or IntersectionObserver
  • 🎨 Compression — Squoosh, ImageMagick, Sharp
  • ☁️ CDN transforms — Cloudinary, imgix URL API
  • 📦 Sprite sheets — combine small icons

Modern image patterns — HTML + Next.js

<!-- HTML: picture with AVIF → WebP → JPEG fallback -->
<picture>
  <source srcset="hero.avif" type="image/avif">
  <source srcset="hero.webp" type="image/webp">
  <img src="hero.jpg" alt="Dashboard" width="1200" height="800"
       loading="lazy" decoding="async">
</picture>

// ─── Next.js Image component (auto-optimised) ───
import Image from 'next/image';

<Image
  src="/hero.jpg"
  alt="SAP dashboard hero"
  width={1200} height={800}
  priority    // LCP image — no lazy loading
  placeholder="blur"
  blurDataURL={blurPlaceholder}
  sizes="(max-width: 768px) 100vw, 50vw"
/>

// ─── Sharp — server-side image processing ───
import sharp from 'sharp';
await sharp('input.jpg')
  .resize(800, 600, { fit: 'cover' })
  .webp({ quality: 80 })
  .toFile('output.webp');

// ─── IntersectionObserver lazy load ───
const io = new IntersectionObserver((entries) => {
  entries.filter(e => e.isIntersecting).forEach(e => {
    const img = e.target as HTMLImageElement;
    img.src = img.dataset.src!;
    io.unobserve(img);
  });
});
document.querySelectorAll('img[data-src]').forEach(img => io.observe(img));
