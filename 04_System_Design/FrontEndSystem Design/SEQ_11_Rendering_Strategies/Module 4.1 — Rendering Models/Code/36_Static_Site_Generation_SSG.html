SSG — Build-time HTML Generation

Build
npm run build — Next.js/Gatsby/Astro fetches all data and renders every page to static HTML files
Deploy
Static HTML/CSS/JS uploaded to CDN — no server needed at runtime
Request
User requests /blog/post-1 → CDN returns pre-built post-1.html instantly — TTFB < 50ms
Hydrate
JS bundle downloads and attaches interactivity — page is already visible
Best TTFB possible — CDN cache hit. No DB, no server compute per request.
Limitation — data is stale until next build. Not suitable for real-time or user-specific content.

SSG Pros & Cons

✅ Advantages
Fastest possible load (CDN edge)
Zero server cost per request
Unbeatable SEO (full HTML)
Highly secure (no server runtime)
Great Core Web Vitals scores
❌ Disadvantages
Stale data until rebuild
Long build times at scale (10k+ pages)
Can't personalise per user
Needs rebuild pipeline on content change
Not for dynamic/auth content

Use case fit

Marketing sites, documentation (SAP Help Portal), blogs, product landing pages. SAP's developer.sap.com is built on static generation with a CMS-driven rebuild pipeline.

Next.js App Router — SSG with generateStaticParams

// app/blog/[slug]/page.tsx
import { notFound } from 'next/navigation';

// Tell Next.js which slugs to pre-build at build time
export async function generateStaticParams() {
  const posts = await getAllPosts();
  return posts.map((p) => ({ slug: p.slug }));
}

// Page is statically rendered at build time
export default async function BlogPost({ params }) {
  const post = await getPost(params.slug);
  if (!post) notFound();
  return <article>{post.content}</article>;
}

// Force static — this is already the default for pages with
// generateStaticParams, but explicit for clarity:
export const dynamic = 'force-static';
