1. The Problem scheduler.postTask Solves

// Before scheduler.postTask, we had:
//
// setTimeout(fn, 0)     → No priority control, 4ms clamp
// requestAnimationFrame → Only for animation-sync work
// requestIdleCallback   → Only for idle-time work, no urgency
// queueMicrotask        → Too eager (blocks rendering)
//
// Missing: "Run this task with MEDIUM priority"
// "Run this task with LOW priority, but abort if user navigates"
// "Run this AFTER user interactions but BEFORE idle work"
//
// scheduler.postTask provides:
// ✓ Three explicit priority levels
// ✓ Returns a Promise (awaitable)
// ✓ Supports AbortSignal for cancellation
// ✓ Dynamic priority changes via TaskController
// ✓ Browser can INTERLEAVE user events between tasks
//
// Status: Chrome 94+ (Oct 2021), Edge 94+
// NOT in Firefox or Safari (use polyfill or feature detect)

// Feature detection:
if ('scheduler' in window && 'postTask' in scheduler) {
  // Use scheduler.postTask
} else {
  // Fallback to setTimeout
}

2. Basic API Usage

// scheduler.postTask(callback, options?) → Promise

// Simple usage:
const result = await scheduler.postTask(() => {
  return expensiveComputation();
}, { priority: 'background' });

// With AbortSignal (cancellation):
const controller = new AbortController();
try {
  const result = await scheduler.postTask(
    () => fetchAndProcess(),
    { priority: 'user-blocking', signal: controller.signal }
  );
} catch (e) {
  if (e.name === 'AbortError') console.log('Task cancelled');
}
// Cancel: controller.abort();

// With timeout:
await scheduler.postTask(
  () => doWork(),
  {
    priority: 'background',
    signal: AbortSignal.timeout(5000), // Cancel after 5s
  }
);

Three Priority Levels

// 1. "user-blocking" — HIGHEST priority
//    • Work that blocks user interaction
//    • Must complete for the UI to be usable
//    • Examples: rendering visible content, input validation
scheduler.postTask(() => renderCriticalUI(), {
  priority: 'user-blocking'
});

// 2. "user-visible" — MEDIUM priority (DEFAULT)
//    • Visible to user but not blocking interaction
//    • Examples: rendering below-fold content, updating secondary UI
scheduler.postTask(() => loadBelowFoldImages(), {
  priority: 'user-visible'
});

// 3. "background" — LOWEST priority
//    • User doesn't perceive this work
//    • Examples: analytics, prefetching, cache warming
scheduler.postTask(() => sendAnalytics(), {
  priority: 'background'
});

Pattern: Priority-Based Page Load

// Orchestrate page load with explicit priorities

// Critical: render above-the-fold content
await scheduler.postTask(() => {
  renderHero();
  renderNavigation();
}, { priority: 'user-blocking' });

// Visible: render below-fold content
scheduler.postTask(() => {
  renderProductGrid();
  renderRecommendations();
}, { priority: 'user-visible' });

// Background: non-visible work
scheduler.postTask(() => initAnalytics(), { priority: 'background' });
scheduler.postTask(() => prefetchNextPage(), { priority: 'background' });
scheduler.postTask(() => warmServiceWorkerCache(), { priority: 'background' });

Pattern: Dynamic Priority with TaskController

// TaskController: change priority AFTER scheduling

const controller = new TaskController({ priority: 'background' });

// Schedule prefetch at background priority
const prefetchTask = scheduler.postTask(
  () => prefetchProductDetails(productId),
  { signal: controller.signal }
);

// User hovers over the product → boost priority!
productCard.addEventListener('mouseenter', () => {
  controller.setPriority('user-blocking');
  // The queued task is now user-blocking priority
  // It will run before other background/visible tasks
});

// User scrolls past → cancel it
observer.observe(productCard, (entries) => {
  if (!entries[0].isIntersecting) {
    controller.abort();
  }
});

FAANG Interview Questions

Q1: How does scheduler.postTask improve over existing scheduling APIs?
scheduler.postTask provides three things missing from existing APIs: (1) Priority control — setTimeout and MessageChannel have no concept of priority; all tasks go to the same queue. postTask offers three explicit levels (user-blocking, user-visible, background) that the browser respects, interleaving user interactions between background tasks. (2) Cancellation — postTask accepts AbortSignal, letting you cancel queued work when it's no longer needed (user navigated away, component unmounted). With setTimeout you can call clearTimeout, but there's no standard cancellation for promises or rAF chains. (3) Dynamic priority — TaskController lets you change a task's priority after scheduling. Example: prefetch data at background priority, but if the user hovers over the link, boost to user-blocking. No other API supports this. The Promise-based return value also makes it composable with async/await, unlike the callback-only APIs. The main limitation is browser support — Chrome/Edge only as of now.
Follow-up: How would you polyfill scheduler.postTask for unsupported browsers?
Q2: Design a task scheduling system for a complex SPA that handles analytics, prefetching, and UI updates without blocking user interactions.
I'd build a three-tier scheduling layer: Tier 1 (user-blocking): input handlers, critical UI updates, form validation. These run immediately via direct execution or scheduler.postTask with "user-blocking" priority. Tier 2 (user-visible): below-fold content rendering, secondary data fetching, chart rendering. Use "user-visible" priority — they run after Tier 1 but before Tier 3. Tier 3 (background): analytics beacons, prefetching next routes, cache warming, error logging. Use "background" priority with AbortSignal for cleanup on navigation. For browsers without postTask, I'd use a custom scheduler: maintain three queues (arrays), process items via MessageChannel yield. Before each item, check if higher-priority queue has work. For analytics specifically: batch events and flush via requestIdleCallback or "background" postTask. For prefetching: use Intersection Observer to trigger, TaskController to boost priority on hover, abort on scroll-away. All background tasks get AbortSignal.timeout() to prevent stale work from accumulating.

Quick Reference

scheduler.postTask(callback, options?)
  options.priority: 'user-blocking' | 'user-visible' | 'background'
  options.signal: AbortSignal (for cancellation/timeout)
  options.delay: number (ms delay before scheduling)
  Returns: Promise<T>

TaskController:
  new TaskController({ priority })
  controller.setPriority(newPriority)  // Change priority
  controller.abort()                    // Cancel task
  controller.signal                     // Pass to postTask

scheduler.yield() (Chrome 129+):
  await scheduler.yield()  // Yield, keep priority

Priority order:
  user-blocking > user-visible > background

Browser support: Chrome 94+, Edge 94+
Polyfill: https://github.com/nicolo-ribaudo/tc39-proposal-scheduling-apis
