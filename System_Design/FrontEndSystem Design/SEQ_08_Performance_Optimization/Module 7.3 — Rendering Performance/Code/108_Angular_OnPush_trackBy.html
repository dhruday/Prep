Angular Change Detection: Default vs OnPush

By default, Angular's zone.js-based change detection checks EVERY component on EVERY async event (click, setTimeout, HTTP response, any microtask). In a tree of 200 components getting 10 events/second = 2000 checks/second regardless of whether data changed. OnPush limits checks to only when: an @Input reference changes, an Observable from async pipe emits, or markForCheck() is called explicitly.

Default CD — Every async event checks everything
Any async event → zone.js patches it → NgZone.run() → CD triggered from root
→ All 200 components checked even if nothing changed
→ Expensive with large trees, frequent events (WebSocket, scroll)
OnPush — Only 3 triggers
① @Input reference changes (immutable updates)
② Observable via async pipe emits
③ Manual markForCheck() / detectChanges()
→ 80–95% fewer checks in real applications

trackBy — why *ngFor re-creates DOM elements without it

Without trackBy, Angular identifies list items by object identity. Fetch the same data again from the API → new array → new object references → Angular destroys and recreates all DOM nodes. With trackBy returning a stable ID, Angular keeps existing DOM nodes and only updates changed ones.

Without trackBy
API refresh → 50 DOM nodes destroyed → 50 recreated → layout thrashing, animations reset, focus lost
With trackBy
API refresh → Angular traces by ID → unchanged items reused → only modified items updated

OnPush component with WebSocket (Bosch dashboard pattern)

@Component({
  selector: 'app-machine-status',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `
    <div *ngFor="let machine of machines; trackBy: trackById">
      {{ machine.name }}: {{ machine.status }}
    </div>
  `
})
export class MachineStatusComponent implements OnInit {
  machines: Machine[] = [];
  
  constructor(
    private ws: WebSocketService,
    private cdr: ChangeDetectorRef,
    private ngZone: NgZone
  ) {}
  
  ngOnInit(): void {
    // WebSocket runs outside zone — must manually trigger CD
    this.ws.machines$.pipe(takeUntilDestroyed()).subscribe(machines => {
      this.machines = machines;           // Immutable replace (not push!)
      this.cdr.markForCheck();            // Schedules CD for this subtree
    });
  }
  
  // trackBy: stable ID → DOM nodes reused on list refresh
  trackById(index: number, machine: Machine): string {
    return machine.id;
  }
}

// Preferred: use async pipe — automatically handles markForCheck
// template: <div *ngFor="let m of machines$ | async; trackBy: trackById">
