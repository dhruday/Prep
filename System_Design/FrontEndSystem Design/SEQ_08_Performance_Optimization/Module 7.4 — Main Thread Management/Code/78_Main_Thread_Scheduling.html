The single-threaded browser — why scheduling matters

JavaScript runs on a single main thread shared by: script execution, style/layout calculation, paint, compositing, and input event handling. A 200 ms synchronous task blocks ALL of these — user clicks feel frozen. At SAP a 300-row data-grid initialising synchronously blocked input for 400 ms on every filter change.

setTimeout(fn, 0)
Pushes macrotask to end of queue. Non-blocking but lowest priority — paint + I/O go first. Good for deferring non-urgent work.
requestIdleCallback
Runs only when the browser is idle (after paint). deadline.timeRemaining() tells you how much time is left. Ideal for analytics, preload, background tasks. No iOS Safari support.
scheduler.postTask
Chromium Scheduler API (2023). Three priorities: user-blocking, user-visible, background. Supports signal-based cancellation. React 18 concurrent mode uses similar internals.

Scheduling APIs — priority ladder

user-blocking (highest) — input handlers, animations. Must complete in <100ms to avoid INP regression.
user-visible — rendering work that the user can see but hasn't triggered directly. React schedules most state updates here in concurrent mode.
background — analytics, cache warming, prefetch. Runs during idle periods. Can be cancelled cheaply via AbortSignal.
Web Workers — true parallelism off the main thread. No DOM access. Ideal for: JSON parse, image processing, search indexing. Communicate via postMessage.

Scheduling patterns in TypeScript

// ─── scheduler.postTask (Chromium) ───
declare const scheduler: { postTask: (fn: ()=>void, opts?: { priority: string, signal?: AbortSignal }) => Promise<void> };

const controller = new TaskController({ priority: 'background' });
scheduler.postTask(() => warmCache(), { signal: controller.signal });
// Cancel if user navigates away
controller.abort();

// ─── requestIdleCallback with deadline ───
requestIdleCallback((deadline) => {
  while (queue.length > 0 && deadline.timeRemaining() > 1) {
    const task = queue.shift()!;
    processAnalyticsEvent(task);
  }
  if (queue.length > 0) requestIdleCallback(arguments[0]); // reschedule
}, { timeout: 2000 }); // fallback deadline

// ─── Chunked work with yield (async generator) ───
async function* processInChunks<T>(items: T[], fn: (item: T) => void, chunkSize = 10) {
  for (let i = 0; i < items.length; i += chunkSize) {
    items.slice(i, i + chunkSize).forEach(fn);
    yield new Promise(r => setTimeout(r, 0)); // yield to browser
  }
}

// ─── Web Worker for heavy computation ───
const worker = new Worker(new URL('./search.worker.ts', import.meta.url));
worker.postMessage({ type: 'SEARCH', query, documents });
worker.onmessage = (e) => setResults(e.data.results);
