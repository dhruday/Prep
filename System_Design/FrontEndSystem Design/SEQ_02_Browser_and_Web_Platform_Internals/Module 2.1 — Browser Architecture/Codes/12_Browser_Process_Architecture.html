🔒 Site Isolation — Post-Spectre Defence

After Spectre (2018), Chrome defaults to same-process only for same-origin iframes. Cross-origin iframes get isolated renderer processes.

📡 IPC Flow — How Processes Communicate

// When a renderer process needs to fetch a URL:
Renderer → (IPC/Mojo) → Network Service → Internet
Network Service → (IPC/Mojo) → Renderer (response data)

// When rendering is complete:
Renderer → (IPC compositor commands) → GPU Process
GPU Process → (OpenGL/Vulkan) → Screen pixels

// When JS accesses localStorage:
Renderer JS → (IPC) → Storage Service
Storage Service → (file I/O) → disk
Storage Service → (IPC) → Renderer (result)

// postMessage between cross-origin iframes:
iframe1 Renderer → postMessage() → Browser Process
Browser Process → validates origin → iframe2 Renderer

🎯 SAP Micro-Frontend Implications

// At SAP Labs: portal embeds multiple MFE iframes
// Each cross-origin MFE = separate renderer process

// Problem: 10 MFE iframes × 75MB = 750MB overhead
// Solution: Lazy-load off-screen iframes

const observer = new IntersectionObserver(
  (entries) => {
    entries.forEach(entry => {
      if (entry.isIntersecting) {
        const container = entry.target;
        const src = container.dataset.src;
        container.innerHTML =
          `<iframe src="${src}" ...></iframe>`;
        observer.unobserve(container);
      }
    });
  },
  { rootMargin: '200px' }
);

// Cross-frame messaging (replaces direct DOM access)
// Always validate origin in production!
window.addEventListener('message', (e) => {
  if (e.origin !== 'https://trusted-mfe.sap.com') return;
  handleMFEMessage(e.data);
});
