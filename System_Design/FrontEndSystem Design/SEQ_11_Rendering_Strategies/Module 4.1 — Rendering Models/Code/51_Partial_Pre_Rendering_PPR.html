PPR — Static Shell + Dynamic Holes

PPR (Next.js 14+ experimental) splits a single page into a static shell (CDN-cached, delivered instantly) and dynamic holes (streamed in after server-side rendering). This gives you SSG-like TTFB for the shell, plus SSR freshness for dynamic parts — all in the same page, zero config per route.

Old world
Choose SSG or SSR per route. Can't mix on same page.
PPR ✅
Static shell + Suspense boundaries = best of both per component.
Result
FCP from CDN cache. Dynamic data streamed in. No layout shift.

E-commerce Product Page — PPR anatomy

STATIC SHELL — CDN cached
🖼 Product images (from SSG params)
📝 Product title, description, spec table
DYNAMIC — streamed per request
💰 Price (live, currency aware)
🛒 Inventory / Add to cart state
⭐ Review scores (real-time)
STATIC — pre-rendered
📦 Related products (SSG pre-rendered)
DYNAMIC — per user
❤️ Personalised recommendations (auth context)
Each Suspense boundary is a "hole" — static shell streams first (~20ms TTFB), dynamic holes stream in as server resolves them.

Next.js 14 — PPR with Suspense

// next.config.js — enable PPR (experimental)
const nextConfig = {
  experimental: { ppr: true },
};

// app/products/[id]/page.tsx
import { Suspense } from 'react';
import { ProductDetail, DynamicPrice, Recommendations } from './components';

export const experimental_ppr = true; // opt-in per page

export default async function ProductPage({ params }) {
  // Static data — part of shell
  const product = await getProductStatic(params.id);

  return (
    <>
      {/* Static — in CDN shell */}
      <ProductDetail product={product} />

      {/* Dynamic hole — streamed per request */}
      <Suspense fallback={<PriceSkeleton />}>
        <DynamicPrice productId={params.id} />
      </Suspense>

      {/* Dynamic hole — personalised */}
      <Suspense fallback={<RecsSkeleton />}>
        <Recommendations userId={await getUserId()} />
      </Suspense>
    </>
  );
}
