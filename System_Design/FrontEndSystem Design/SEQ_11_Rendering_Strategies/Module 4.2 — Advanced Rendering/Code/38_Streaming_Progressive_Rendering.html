What is Streaming?

Traditional SSR blocks the entire response until all data is fetched and all HTML is rendered. Streaming uses HTTP chunked transfer encoding to send HTML in pieces as soon as each piece is ready. The browser renders each chunk progressively — the user sees content sooner.

❌ Blocking SSR
Wait → Wait → Wait → Send ALL HTML
User sees blank screen until slowest API resolves
✅ Streaming SSR
Shell → Nav → Hero → Sidebar → Feed (each chunk as ready)
User sees something in ~200ms, rest fills in
React 18's renderToPipeableStream + Next.js App Router + <Suspense> = out-of-the-box streaming. Each Suspense boundary becomes a chunk boundary.

Streaming chunks arriving progressively

React Suspense as streaming boundaries

Each <Suspense> wrapping an async component becomes a streaming boundary. The fallback is sent first. When data resolves, the real component HTML is streamed in — React swaps it on client without full page re-render.

What streams immediately (0ms)
✦ HTML shell <head></head>
✦ Navigation bar
✦ Page layout/skeleton
✦ Critical above-fold text
What streams later (async)
✦ Comments list (DB query)
✦ User profile sidebar
✦ Product recommendations
✦ Analytics widgets

Next.js App Router — streaming with Suspense

// app/dashboard/page.tsx — streaming layout
import { Suspense } from 'react';

export default function Dashboard() {
  // Shell renders + streams immediately (no awaits here)
  return (
    <main>
      <header>SAP Fiori Header</header>  {/* instant */}

      {/* NavBar streams first — fast DB read */}
      <Suspense fallback={<NavSkeleton />}>
        <Nav />
      </Suspense>

      {/* Analytics slow — streams last */}
      <Suspense fallback={<AnalyticsSkeleton />}>
        <Analytics />  {/* async server component */}
      </Suspense>
    </main>
  );
}

// Analytics.tsx — server component, async
async function Analytics() {
  const data = await fetchAnalytics(); // slow: 800ms
  return <AnalyticsWidget data={data} />;
  // Streams in after 800ms — shell already visible
}
