Design System Versioning

SAP Fundamental-Styles follows semver. Breaking changes (token renames, API changes) need major bumps. Teams pin to a major version and upgrade on a schedule.
Breaking change protocol at SAP:
1. Deprecation notice in v3.x (console.warn)
2. Migration guide published
3. Breaking change in v4.0
4. Design system team provides codemods for automated migration

Design System folder structure

design-system/
  tokens/
    colors.json        // Raw token values — sync with Figma
    spacing.json
    typography.json
  // Style Dictionary generates CSS vars, SCSS, JS constants
  build/
    css/tokens.css     // --color-primary: #60a5fa
    scss/_tokens.scss
    js/tokens.ts
  components/
    Button/
      Button.tsx
      Button.styles.ts  // Uses token constants
      Button.stories.tsx
      Button.test.tsx
    Input/
    Modal/
  docs/                 // Storybook — living documentation
  CHANGELOG.md          // Semver + breaking changes
// Token usage in component (TypeScript + CSS-in-JS)
import { tokens } from '@sap/ds-tokens';

const ButtonStyles = {
  background: tokens.color.primary,         // '#60a5fa'
  padding: `${tokens.space.sm} ${tokens.space.md}`,
  borderRadius: tokens.radius.base,
  // Changing tokens.color.primary updates ALL consumers
};
