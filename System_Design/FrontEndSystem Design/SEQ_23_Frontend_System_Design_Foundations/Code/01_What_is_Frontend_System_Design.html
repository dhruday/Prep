🏗️ What is Frontend System Design?

Architecture Thinking · Component Boundaries · State · Data Flow · Trade-offs

🗂️ The Frontend System Design Stack — Click Each Layer

🌐 Browser & Platform Layer

Network, rendering pipeline, JS engine, storage APIs

HTML parsing → CSSOM → Render Tree → Layout → Paint → Composite. JS runs on V8 (single-threaded). Network fetched via Service Workers / HTTP cache. This layer constrains everything above it — and is what FAANG interviewers probe deepest.

📦 Asset & Build Layer

Webpack/Vite, code splitting, tree shaking, CDN delivery

Bundles, chunks, and HTTP/2 multiplexing. A senior engineer controls what goes in each chunk, how it's cached via Cache-Control, and how CDN serves it. Bundle size directly impacts LCP and TTI on mobile devices.

🏛️ Architecture & Rendering Layer

SPA / SSR / SSG / ISR / Islands — rendering strategy selection

The rendering strategy determines: initial HTML delivery time, hydration cost, SEO characteristics, and edge caching potential. Choosing SSR vs CSR is a system design decision with measurable performance, infrastructure cost, and UX trade-offs.

🧠 State & Data Layer

State management, data fetching, caching, synchronisation

Where does data live? Who owns it? When is it stale? How are updates propagated? State management is the #1 source of bugs and complexity in large-scale frontend applications. Senior engineers design clear ownership boundaries: server state vs client state vs URL state vs computed state.

🧩 Component & UX Layer

Component decomposition, design systems, accessibility, interactions

How components are split, composed, and communicate. A design system defines the contract between design and engineering. Accessibility is a layer constraint — not an afterthought. Component boundaries determine re-render scope and code-splitting granularity.
