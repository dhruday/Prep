⚠️ Architecture Decisions by Device

📦 Bundle: Lazy-load all non-critical routes. Keep initial to <150 KB.
🖼️ Images: srcset + WebP. Lazy-load below fold. 80% bandwidth saving on mobile.
📜 Lists: Virtualise at 50+ items. Each DOM node ≈ 1KB memory.
⚙️ Compute: Web Workers for anything >50ms. Don't block main thread.
💾 Cache: Service Worker pre-cache critical assets. Offline-first for slow networks.
🎨 CSS: content-visibility: auto skips off-screen rendering. 60% style recalc saving.

⚡ Rendering Throttle Decision

Without throttle:
2,500 WS messages/sec → 2,500 React renders/sec → main thread 100% blocked
With 16ms batching:
60 batched renders/sec × 16ms = exactly 60fps budget
With 200ms debounce:
5 renders/sec — acceptable for dashboard state, low CPU cost
Decision rule: Use 16ms batching for visualisations (chart, topology). Use 200ms debounce for status/count updates. Use long-polling for <1 msg/min scenarios.
Cisco pattern: Webex uses delta-sync — only send changed fields, not full state. A topology change in 1 router sends 200 bytes, not the full 10,000-node topology. Then batch-apply to state every 200ms.
