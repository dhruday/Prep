Messages often arrive out-of-order on real networks

Even over WebSockets (which guarantee order on a single connection), out-of-order delivery happens when: multiple WS connections are used, events come from different microservices at different latencies, the client reconnects and misses events, or messages are batched and re-ordered. At SAP, order status events from different services could arrive: "Shipped" before "Processing" confirmed. A sequence number in each message solves this.

❌ No ordering guarantee
  • Events processed as received
  • Status: "Shipped" then shows "Processing"
  • UI shows wrong state intermittently
✅ Sequence number ordering
  • Each event has seq: N
  • Buffer out-of-order events
  • Process in seq order — consistent UI

Sequence number reorder buffer

// ─── Message ordering buffer ───
class OrderedMessageQueue {
  private nextSeq = 1;
  private buffer = new Map<number, Message>();
  onMessage(msg: Message & { seq: number }) {
    if (msg.seq === this.nextSeq) {
      this.process(msg);
      this.nextSeq++;
      // drain buffer for consecutive messages
      while (this.buffer.has(this.nextSeq)) {
        this.process(this.buffer.get(this.nextSeq)!);
        this.buffer.delete(this.nextSeq);
        this.nextSeq++;
      }
    } else if (msg.seq > this.nextSeq) {
      this.buffer.set(msg.seq, msg); // out-of-order — buffer it
    }
    // seq < nextSeq = duplicate, discard
  }
}

// ─── Server: include sequence number in every event ───
let seq = 0;
broadcastEvent({ type: 'order-update', seq: ++seq, payload });
