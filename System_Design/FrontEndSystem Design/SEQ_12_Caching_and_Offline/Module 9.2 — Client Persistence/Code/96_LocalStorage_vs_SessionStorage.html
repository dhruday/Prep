Web Storage API — scoped, synchronous, string-only

Both localStorage and sessionStorage share the same Web Storage API surface (getItem/setItem/removeItem/clear) but differ in persistence scope. At SAP, we use localStorage for user theme preferences and savedColumns, and sessionStorage for in-flight form wizard step so refreshing a tab preserves the draft but closing clears it.

localStorage
  • 📌 Persists across tabs AND browser restart
  • 🔑 Scoped to origin (scheme+host+port)
  • 📡 Tab A writes → Tab B reads immediately (via storage event)
  • 📏 ~5 MB limit
  • ✅ Best for: theme, preferences, user settings
sessionStorage
  • 🕐 Cleared when tab/window closes
  • 🔒 Scoped to tab (not shared between tabs)
  • 🛡️ New tab from same origin = empty sessionStorage
  • 📏 ~5 MB limit
  • ✅ Best for: form wizard steps, OTP state, temp search filter

Typed wrapper + cross-tab sync

// ─── Typed localStorage helper (SAP pattern) ───
type StorageSchema = {
  theme: 'light' | 'dark';
  'saved-columns': string[];
  language: string;
};
const storage = {
  get<K extends keyof StorageSchema>(key: K): StorageSchema[K] | null {
    const raw = localStorage.getItem(key);
    return raw ? JSON.parse(raw) : null;
  },
  set<K extends keyof StorageSchema>(key: K, value: StorageSchema[K]) {
    localStorage.setItem(key, JSON.stringify(value));
  },
};

// ─── Cross-tab sync ───
window.addEventListener('storage', (e: StorageEvent) => {
  if (e.key === 'theme') applyTheme(e.newValue as 'light' | 'dark');
});

// ─── sessionStorage form wizard ───
const WizardStorage = {
  saveStep(step: number, data: unknown) {
    sessionStorage.setItem(`wizard-step-${step}`, JSON.stringify(data));
  },
  getStep<T>(step: number): T | null {
    const raw = sessionStorage.getItem(`wizard-step-${step}`);
    return raw ? JSON.parse(raw) : null;
  },
  clear() {
    [1, 2, 3].forEach(s => sessionStorage.removeItem(`wizard-step-${s}`));
  },
};
