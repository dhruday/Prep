1. X-Content-Type-Options: nosniff

// Without this: browser may "sniff" the content type
// Example: upload malicious.html as image/png
// Browser sees HTML content → renders as HTML → XSS!
//
// With nosniff: browser strictly uses the declared Content-Type
// If Content-Type says image/png, browser treats it as an image
// Even if the content looks like HTML → no XSS
//
// Also blocks: loading non-script MIME types as scripts
// <script src="file.txt"> → blocked if nosniff and wrong MIME

2. Permissions-Policy (formerly Feature-Policy)

// Controls which browser features your page can use
// Even if third-party scripts try to access them → blocked

Permissions-Policy:
  camera=(),                    // Disable camera for all
  microphone=(),                // Disable microphone for all
  geolocation=(self),           // Only same-origin can use
  payment=(self "https://pay.stripe.com"),  // Specific origins
  usb=(),
  bluetooth=(),
  fullscreen=(self),
  autoplay=(self)

// Why this matters:
// Malicious third-party script can't secretly enable camera
// Even if XSS happens, attacker can't access geolocation
// Reduces browser's attack surface for your page

3. Cross-Origin Isolation (COOP + COEP + CORP)

// These three headers work together to enable cross-origin isolation
// Required for: SharedArrayBuffer, high-resolution timers
// Protects against: Spectre-class side-channel attacks
//
// COOP (Cross-Origin-Opener-Policy): same-origin
//   → Your page can't be accessed via window.opener from cross-origin
//   → Prevents: cross-origin window reference attacks
//
// COEP (Cross-Origin-Embedder-Policy): require-corp
//   → All cross-origin resources must explicitly opt-in via CORP header
//   → Prevents: loading resources that didn't consent to being embedded
//
// CORP (Cross-Origin-Resource-Policy): same-origin | same-site | cross-origin
//   → Resource declares who can load it
//   → Set on CDN assets: cross-origin (allow embedding)
//   → Set on API responses: same-origin (don't allow cross-site loading)
//
// Check: crossOriginIsolated === true → all three are correctly set

What Each Header Prevents

MIME Sniffing Attack

// 1. Attacker uploads file.html disguised as file.txt to a CDN
// 2. Server serves with Content-Type: text/plain
// 3. Without nosniff: browser sniffs content → "looks like HTML!"
// 4. Renders as HTML → JavaScript executes → XSS
// With X-Content-Type-Options: nosniff → browser keeps it as text/plain

Spectre-Class Attack

// Spectre exploits CPU speculative execution
// In browser: malicious page uses SharedArrayBuffer as high-res timer
// Times cache access patterns to read cross-origin memory
//
// Defense: COOP + COEP enable cross-origin isolation
// Process isolation: each origin gets its own process
// Cross-origin data never in the same memory space
// SharedArrayBuffer only available after isolation (prevents timing)

Referrer Leakage

// User on: https://app.com/reset-password?token=abc123
// Clicks external link, or page loads third-party analytics
// Without Referrer-Policy: full URL sent as Referer header
// → Third party sees the password reset token!
//
// With strict-origin-when-cross-origin:
// Cross-origin: sends only https://app.com (no path/query)
// Same-origin: sends full URL (safe)

FAANG Interview Questions

Q1: What security headers would you add to a production web app? Walk through each one.
The essential set: (1) HSTS (max-age=1yr, includeSubDomains, preload) — enforces HTTPS, prevents downgrade. (2) CSP with nonces and strict-dynamic — prevents XSS, controls resource loading. (3) X-Content-Type-Options: nosniff — prevents MIME sniffing attacks where uploaded files are executed as scripts. (4) X-Frame-Options: DENY + frame-ancestors 'none' — prevents clickjacking. (5) Referrer-Policy: strict-origin-when-cross-origin — prevents URL data leakage to third parties. (6) Permissions-Policy: disable unused APIs (camera, microphone, geolocation) — reduces attack surface even if XSS succeeds. (7) COOP: same-origin — prevents cross-origin window reference attacks. For APIs specifically: also add Cache-Control: no-store on sensitive endpoints. I'd use Helmet.js in Express for a sensible default and customize per-route. Test with securityheaders.com which grades your headers A through F.
Follow-up: Which headers can break existing functionality if added carelessly?
Q2: Explain cross-origin isolation (COOP + COEP) and when you'd need it.
Cross-origin isolation puts your page in a separate OS process, preventing Spectre-class side-channel attacks where malicious code reads cross-origin data via CPU cache timing. You need it to use SharedArrayBuffer (for WASM multi-threading, Web Workers with shared memory) and high-resolution timers (performance.now with microsecond precision). To enable: set COOP: same-origin (your page can't be opened as a popup from cross-origin) and COEP: require-corp (all resources you load must explicitly consent via CORP headers). The catch: every cross-origin resource (CDN images, fonts, scripts) must set Cross-Origin-Resource-Policy: cross-origin. If a third-party resource doesn't set CORP, COEP blocks it. Alternatives: use credentialless mode for images or use COEP: credentialless (less strict). Check: if (crossOriginIsolated) tells you if it's working. Most sites don't need this unless using WASM or SharedArrayBuffer.
Follow-up: How does this relate to Site Isolation in Chrome?

1. Full Helmet.js Configuration

import helmet from 'helmet';
import crypto from 'crypto';

app.use((req, res, next) => {
  res.locals.nonce = crypto.randomBytes(16).toString('base64');
  next();
});

app.use((req, res, next) => {
  helmet({
    contentSecurityPolicy: {
      directives: {
        defaultSrc: ["'self'"],
        scriptSrc: [`'nonce-${res.locals.nonce}'`, "'strict-dynamic'"],
        styleSrc: ["'self'", `'nonce-${res.locals.nonce}'`],
        imgSrc: ["'self'", 'data:', 'https://cdn.example.com'],
        connectSrc: ["'self'", 'https://api.example.com'],
        fontSrc: ["'self'", 'https://fonts.gstatic.com'],
        objectSrc: ["'none'"],
        frameAncestors: ["'none'"],
        baseUri: ["'self'"],
        formAction: ["'self'"],
      },
    },
    strictTransportSecurity: {
      maxAge: 31536000,
      includeSubDomains: true,
      preload: true,
    },
    referrerPolicy: { policy: 'strict-origin-when-cross-origin' },
    crossOriginOpenerPolicy: { policy: 'same-origin' },
    crossOriginResourcePolicy: { policy: 'same-origin' },
    permissionsPolicy: {
      camera: [], microphone: [], geolocation: [],
      payment: ['self'], usb: [], bluetooth: [],
    },
  })(req, res, next);
});

2. Nginx Security Headers

# /etc/nginx/conf.d/security-headers.conf

add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-Frame-Options "DENY" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Cross-Origin-Opener-Policy "same-origin" always;
add_header Cross-Origin-Resource-Policy "same-origin" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;

# CSP with nonce requires dynamic generation (use app server)
# Or use nginx's sub_filter to inject nonce into HTML

Production Headers Checklist

✅ Strict-Transport-Security (HSTS) with preload
✅ Content-Security-Policy with nonces
✅ X-Content-Type-Options: nosniff
✅ X-Frame-Options: DENY  (+ CSP frame-ancestors)
✅ Referrer-Policy: strict-origin-when-cross-origin
✅ Permissions-Policy: disable unused browser features
✅ Cross-Origin-Opener-Policy: same-origin
✅ Cross-Origin-Resource-Policy: same-origin (API) / cross-origin (CDN)
✅ Cache-Control: no-store on sensitive API responses
✅ Remove Server, X-Powered-By headers (info leakage)
✅ Test with securityheaders.com → aim for A+ grade
✅ Monitor CSP reports for violations
