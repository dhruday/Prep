Token storage is the most debated security decision in SPA development

Three options: (1) localStorage — simple but XSS-vulnerable; (2) sessionStorage — cleared on tab close, still XSS-vulnerable; (3) HttpOnly cookie — JS cannot read it (XSS-safe) but needs CSRF protection. There is no perfect option. The OWASP recommendation is: if you have XSS protection (DOMPurify + strict CSP), memory (JS variable) is safest for access tokens; use HttpOnly refresh-token cookie for persistence.

Recommended pattern: Store access token in memory (module-level variable). Store refresh token in HttpOnly+Secure+SameSite=Strict cookie. On page refresh, use the refresh token to silently get a new access token via a hidden iframe or BFF.

BFF (Backend for Frontend) pattern

The most secure modern pattern: token exchange happens in a BFF server. SPA only holds a session cookie (HttpOnly); never touches raw tokens. BFF holds tokens and proxies API calls.

Browser SPA → BFF (POST /auth): get HttpOnly session cookie
BFF exchanges PKCE code → stores access + refresh tokens server-side
SPA calls BFF API → BFF adds Authorization header from its token store
Result: SPA never holds tokens. XSS cannot steal what doesn't exist in browser.

Token service pattern (memory store + silent refresh)

// ─── In-memory token store (best for access tokens) ───
let _accessToken: string | null = null;
let _tokenExpiry: number = 0;

export const tokenService = {
  set(token: string, expiresIn: number) {
    _accessToken = token;
    _tokenExpiry = Date.now() + expiresIn * 1000 - 30_000; // 30s buffer
  },
  get(): string | null {
    if (Date.now() < _tokenExpiry) return _accessToken;
    return null; // expired — trigger silent refresh
  },
  clear() { _accessToken = null; _tokenExpiry = 0; }
};

// ─── Axios interceptor: add token, refresh if expired ───
axios.interceptors.request.use(async cfg => {
  let token = tokenService.get();
  if (!token) token = await silentRefresh(); // uses HttpOnly refresh cookie
  cfg.headers['Authorization'] = `Bearer ${token}`;
  return cfg;
});
