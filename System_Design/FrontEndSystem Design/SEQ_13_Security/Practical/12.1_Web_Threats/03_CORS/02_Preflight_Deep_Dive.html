When Does Preflight Happen?

// Preflight (OPTIONS request) is triggered when ANY of these are true:

// 1. Non-simple method:
await fetch(url, { method: 'PUT' });     // PUT, DELETE, PATCH → preflight

// 2. Non-simple Content-Type:
await fetch(url, {
  headers: { 'Content-Type': 'application/json' }  // JSON → preflight
});

// 3. Custom headers:
await fetch(url, {
  headers: { 'Authorization': 'Bearer token' }  // custom header → preflight
});

// NO preflight (simple request):
await fetch(url);                            // GET, no custom headers
await fetch(url, { method: 'POST',        // POST with form content-type
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' }
});

Preflight Performance Impact

// Every preflight adds an extra round-trip:
// Request 1: OPTIONS /api/data (preflight) → 50ms
// Response 1: 204 + CORS headers
// Request 2: POST /api/data (actual) → 100ms
// Total: 150ms instead of 100ms

// Optimization: Access-Control-Max-Age
Access-Control-Max-Age: 86400  // cache preflight for 24h
// Browser caches: (origin, URL, method) → allowed headers
// Subsequent requests to same endpoint skip preflight

// Chrome limit: max 7200s (2 hours)
// Firefox limit: max 86400s (24 hours)
// Safari limit: max 604800s (7 days)

// Other optimizations:
// 1. Use simple requests when possible (avoid custom headers)
// 2. Batch API calls to reduce total preflight count
// 3. Use same-origin proxy to avoid CORS entirely

Google Senior Frontend — Preflight Questions

Q: How do you optimize preflight performance for a micro-frontend architecture with many API domains?

1. API Gateway: Route all API calls through a single same-origin gateway — eliminates CORS entirely for the frontend. 2. Max-Age: Set aggressive Access-Control-Max-Age (2h for Chrome). 3. Avoid unnecessary custom headers on read operations. 4. GraphQL: Single endpoint means one preflight covers all queries. At Google: ESF (Extensible Service Framework) acts as a CORS-handling gateway at the edge.

Q: Why doesn't the browser cache preflight across different URLs on the same domain?

The preflight cache key is (origin, URL, request method). Different URLs might have different CORS policies (e.g., /public allows *, /admin allows only internal origins). Caching across URLs would create security vulnerabilities. Chrome DevTools doesn't show cached preflights in the Network tab — use chrome://net-internals/#events to verify caching.
