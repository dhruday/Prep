Why DOMPurify?

DOMPurify is the gold-standard HTML sanitization library. It uses the browser's own DOM parser to parse the input, then walks the resulting DOM tree and removes dangerous elements/attributes while keeping safe HTML formatting. It's used by Google, Mozilla, and Wikipedia.

HTML Encoding (escaping)
Converts ALL HTML to text: < → &lt;
Result: no HTML renders. Safe but loses ALL formatting.
Sanitization (DOMPurify)
Removes DANGEROUS tags/attrs, keeps SAFE ones.
Result: <b>bold</b> renders, <script> is stripped.

Interview Q&A — Sanitization at Google Scale

    

      
Q: When should you use sanitization vs encoding?

      
Encoding when you want to display text (user names, labels) — use textContent or template auto-escaping. Sanitization when you need to render user-supplied HTML (rich text editor, markdown preview, CMS content). Never roll your own sanitizer — use DOMPurify or the browser's Sanitizer API.

      
Q: Can DOMPurify be bypassed?

      
DOMPurify has very few CVEs given its widespread use. Bypasses are discovered occasionally (mXSS / mutation XSS) where the parser interprets HTML differently during sanitization vs rendering. DOMPurify mitigates this by sanitizing twice internally. Keep it updated — npm audit.
