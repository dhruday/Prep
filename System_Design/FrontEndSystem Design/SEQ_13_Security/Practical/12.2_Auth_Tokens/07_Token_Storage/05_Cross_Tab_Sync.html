The Cross-Tab Problem

// With in-memory tokens, each tab has its own token copy
// Problems:
// 1. Tab A refreshes token → Tab B still has old (expired) token
// 2. Tab A logs out → Tab B is still "logged in"
// 3. Multiple tabs race to refresh simultaneously
// 4. Login in one tab should propagate to all tabs

// Solutions:
// 1. BroadcastChannel API — modern, clean, same-origin
// 2. localStorage 'storage' event — works everywhere, hacky
// 3. Service Worker as token broker — most sophisticated
// 4. SharedWorker — shared state across tabs

// Best practice: BroadcastChannel for auth events
// + leader election for token refresh coordination

Full Implementation with Leader Election

// auth-sync.ts — Cross-tab auth synchronization

const channel = new BroadcastChannel('auth-sync');
let isLeader = false;

// Leader election: only ONE tab refreshes tokens
const electLeader = () => {
  const id = crypto.randomUUID();
  localStorage.setItem('leader-candidate', id);
  setTimeout(() => {
    isLeader = localStorage.getItem('leader-candidate') === id;
  }, 100); // Last writer wins
};

// Listen for auth events from other tabs
channel.onmessage = (event) => {
  switch (event.data.type) {
    case 'LOGIN':
      auth.setToken(event.data.token);
      updateUI('logged-in');
      break;
    case 'LOGOUT':
      auth.clearToken();
      updateUI('logged-out');
      window.location.href = '/login';
      break;
    case 'TOKEN_REFRESHED':
      auth.setToken(event.data.token);
      break;
  }
};

// Only leader tab refreshes tokens
const refreshToken = async () => {
  if (!isLeader) return; // non-leaders wait for broadcast
  const res = await fetch('/api/refresh', { credentials: 'include' });
  const { token } = await res.json();
  auth.setToken(token);
  channel.postMessage({ type: 'TOKEN_REFRESHED', token });
};

Google Senior Frontend — Cross-Tab Auth

Q: How do you handle logout across 20 open tabs?

Use BroadcastChannel to send a LOGOUT event to all tabs. Each tab clears its in-memory token and redirects to login. For Safari support (BroadcastChannel only supported since Safari 15.4): fallback to localStorage write + storage event listener. The storage event fires in ALL OTHER tabs when localStorage changes. Clear the refresh cookie on the server side to prevent any tab from re-authenticating. Google implements this: open Gmail in many tabs, logout from one → all tabs go to the login page.

Q: What about race conditions when multiple tabs try to refresh tokens simultaneously?

Use leader election: only one tab (the "leader") performs token refresh. Other tabs wait for the broadcast. If the leader tab closes, a new leader is elected via BroadcastChannel heartbeat or localStorage timestamp check. Alternatively, use a refresh token lock: the first tab to call /api/refresh gets the new token and the server invalidates the old refresh token. Other tabs get a 401, trigger re-auth. The BroadcastChannel approach is preferred because it avoids unnecessary network calls.
