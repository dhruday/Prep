Cross-Origin Headers Explained

// ═══ Cross-Origin-Opener-Policy (COOP) ═══
Cross-Origin-Opener-Policy: same-origin
// Controls window.opener relationships
// same-origin: windows opened from other origins can't access you
// Prevents: window.open() + postMessage attacks
// Values: unsafe-none, same-origin-allow-popups, same-origin

// ═══ Cross-Origin-Embedder-Policy (COEP) ═══
Cross-Origin-Embedder-Policy: require-corp
// Requires all embedded resources to explicitly opt-in
// Resources must have CORP or CORS headers
// Values: unsafe-none, require-corp, credentialless

// ═══ Cross-Origin-Resource-Policy (CORP) ═══
Cross-Origin-Resource-Policy: same-origin
// Controls who can load your resources
// Prevents cross-origin reads of your images/scripts/etc.
// Values: same-site, same-origin, cross-origin

// ═══ Cross-Origin Isolation ═══
// When COOP: same-origin + COEP: require-corp are BOTH set:
// → crossOriginIsolated = true
// → Enables: SharedArrayBuffer, performance.measureUserAgentSpecificMemory()
// → Prevents: Spectre-style side-channel attacks

Spectre & Cross-Origin Isolation

// Spectre (2018): CPU vulnerability
// Attacker can read arbitrary memory through timing side-channels

// In browsers: Process isolation isn't enough
// SharedArrayBuffer enables high-precision timers
// → Can measure cache timing → read cross-origin data

// Browser response:
// 1. Disabled SharedArrayBuffer (Feb 2018)
// 2. Reduced timer precision (performance.now())
// 3. Site Isolation (Chrome: one process per origin)
// 4. Cross-Origin Isolation (re-enables SharedArrayBuffer safely)

// To use SharedArrayBuffer safely:
// Server must set COOP + COEP headers
// This guarantees no cross-origin data in your process
// Then SharedArrayBuffer is safe to use

// Who needs this:
// - WebAssembly apps (threads use SharedArrayBuffer)
// - Video processing (FFmpeg.wasm)
// - Game engines (Unity, Unreal WebGL)
// - Scientific computing

Google Senior Frontend — COOP/COEP

Q: Your app uses SharedArrayBuffer for video processing. How do you enable cross-origin isolation?

Steps: (1) Set headers: Cross-Origin-Opener-Policy: same-origin AND Cross-Origin-Embedder-Policy: require-corp. (2) All cross-origin resources must opt in: Images/scripts from CDNs need Cross-Origin-Resource-Policy: cross-origin. Or use CORS: <img crossorigin src="..."> with Access-Control-Allow-Origin. (3) Challenge: Third-party content. Ads, analytics, social widgets often DON'T set CORP headers. Solution: COEP: credentialless (Firefox/Chrome) — loads cross-origin resources without credentials instead of blocking them. Or: Load third-party content in a cross-origin iframe with COEP exempt. (4) Test: window.crossOriginIsolated === true. (5) SharedArrayBuffer + Atomics now available. Site Isolation ensures process separation. Common pain point: Google Fonts, CDN images breaking. Fix: Add crossorigin attribute to resource tags or proxy through your origin.
