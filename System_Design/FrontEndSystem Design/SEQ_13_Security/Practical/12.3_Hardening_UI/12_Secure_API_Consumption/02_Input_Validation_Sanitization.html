Q: How do you handle URL validation to prevent SSRF and open redirects?

URL validation is tricky. Steps: (1) Parse with new URL() — rejects malformed URLs. (2) Check protocol: only allow https: (block javascript:, data:, ftp:). (3) For redirects: allowlist of permitted domains. Never redirect to user-supplied URLs without validation. (4) For SSRF prevention (server-side): Block private IPs (127.0.0.1, 10.x, 172.16.x, 192.168.x), block DNS rebinding (resolve DNS, check IP before connecting), use a dedicated egress proxy. (5) Beware of URL encoding tricks: %2F for /, unicode normalization, IDN homograph attacks (аpple.com with Cyrillic 'а'). At Google: URL validation is a centralized library. No team rolls their own.
