Browser Storage Security Risks

// Data left behind after logout = security risk

// localStorage:
// ❌ Persists after tab close, browser restart, even logout
// ❌ Accessible by any JavaScript on the same origin (XSS)
// ❌ No encryption — plaintext on disk
// ❌ No expiry mechanism

// sessionStorage:
// ✅ Cleared when tab closes
// ❌ Still accessible by XSS during the session
// ❌ Duplicated when tab is duplicated (Ctrl+Shift+T)

// IndexedDB:
// ❌ Persists until explicitly cleared
// ❌ Can contain large amounts of sensitive data
// ❌ Often forgotten during logout cleanup

// Service Worker Cache:
// ❌ Persists after logout
// ❌ May contain cached API responses with user data

// Cookies (without Secure/HttpOnly):
// ❌ Readable by JavaScript (XSS)
// ❌ Sent with every request (including to attackers via CSRF)

// Memory:
// JavaScript variables, closures, event listeners
// ❌ Sensitive data in strings persists until GC
// ❌ No way to force memory clearing in JS

Complete Secure Logout

async function secureLogout() {
  // 1. Revoke tokens server-side
  await fetch('/api/auth/logout', {
    method: 'POST',
    credentials: 'same-origin',
  });

  // 2. Clear all browser storage
  localStorage.clear();
  sessionStorage.clear();

  // 3. Clear IndexedDB
  const dbs = await indexedDB.databases();
  dbs.forEach(db => indexedDB.deleteDatabase(db.name));

  // 4. Clear Service Worker caches
  if ('caches' in window) {
    const names = await caches.keys();
    await Promise.all(names.map(n => caches.delete(n)));
  }

  // 5. Unregister Service Workers
  if (navigator.serviceWorker) {
    const regs = await navigator.serviceWorker.getRegistrations();
    regs.forEach(r => r.unregister());
  }

  // 6. Clear cookies (client-accessible ones)
  document.cookie.split(';').forEach(c => {
    const name = c.split('=')[0].trim();
    document.cookie = `\${name}=;expires=Thu, 01 Jan 1970;path=/`;
  });

  // 7. Broadcast logout to other tabs
  new BroadcastChannel('auth').postMessage({ type: 'LOGOUT' });

  // 8. Clear in-memory state
  // Reset Redux/Zustand store, React context, etc.

  // 9. Redirect to login (clears navigation state)
  window.location.replace('/login');
}

Google Senior Frontend — Storage Security

Q: How do you handle sensitive data in a shared computer scenario?

Shared/public computers (libraries, hotels, kiosks): (1) Prefer sessionStorage over localStorage — auto-clears on tab close. (2) Keep tokens in memory only — never persist sensitive tokens. (3) Implement inactivity timeout — auto-logout after 5 minutes of inactivity. (4) Thorough logout — clear ALL storage, caches, service workers (as shown in Lab). (5) No "Remember Me" — disable persistent login on shared devices. Detect? Not reliably, but offer "Public computer" checkbox. (6) HTTP-only secure cookies with short expiry — even if user forgets to log out, session expires quickly. (7) Warning on login — "You're signing in on a device. Make sure to sign out when done." (8) Content isolation — use history.replaceState to prevent back-button data access. Set Cache-Control: no-store on all authenticated pages. Google: "Security checkup" feature lets users view/revoke active sessions from any device.
