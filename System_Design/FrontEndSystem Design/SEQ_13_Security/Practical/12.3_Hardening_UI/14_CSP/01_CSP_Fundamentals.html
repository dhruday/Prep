Content Security Policy

// CSP = Allowlist of trusted content sources
// Tells the browser: "Only load resources from THESE origins"

// Delivered as HTTP header:
Content-Security-Policy: default-src 'self'; script-src 'self' https://cdn.example.com

// Or as meta tag (limited — no frame-ancestors, report-uri):
<meta http-equiv="Content-Security-Policy"
  content="default-src 'self'; img-src *">

// What CSP protects against:
// ✅ XSS — blocks inline scripts, eval(), unauthorized script sources
// ✅ Data exfiltration — blocks fetch/XHR to unauthorized origins
// ✅ Clickjacking — frame-ancestors directive
// ✅ Mixed content — block-all-mixed-content
// ✅ Protocol downgrade — upgrade-insecure-requests

// How it works:
// 1. Server sends CSP header with response
// 2. Browser parses the policy
// 3. For every resource load, browser checks: "Is this allowed?"
// 4. Blocked resources → console error + optional violation report

CSP Directives

// ═══ Fetch Directives (what resources to load) ═══
default-src   Fallback for all other directives
script-src    JavaScript sources
style-src     CSS sources
img-src       Image sources
font-src      Font file sources
connect-src   fetch, XHR, WebSocket, EventSource targets
media-src     Audio/video sources
object-src    Plugin sources (Flash, Java — always set to 'none')
frame-src     Sources for iframes I embed
worker-src    Web Worker, SharedWorker, ServiceWorker scripts
manifest-src  Web manifest sources

// ═══ Document Directives ═══
base-uri      Restricts <base> element URLs
sandbox       Applies sandbox restrictions (like iframe sandbox)

// ═══ Navigation Directives ═══
frame-ancestors  WHO can embed this page (clickjacking defense)
form-action      Where forms can submit to
navigate-to      Where page can navigate (experimental)

// ═══ Reporting ═══
report-uri    URL to send violation reports (deprecated)
report-to     Reporting API group name (modern)

Source Values

// Source keywords (must be quoted!):
'none'              Block everything
'self'              Same origin only
'unsafe-inline'     Allow inline scripts/styles (defeats CSP!)
'unsafe-eval'       Allow eval(), Function(), setTimeout("code")
'strict-dynamic'    Trust scripts loaded by trusted scripts
'unsafe-hashes'     Allow specific inline event handlers

// Source URLs:
https://cdn.example.com     Specific origin
*.example.com               Wildcard subdomain
https:                      Any HTTPS origin
data:                       data: URLs (images)
blob:                       blob: URLs

// Nonces and hashes:
'nonce-abc123'      Allow script with matching nonce attribute
'sha256-...'        Allow script matching this hash

// Example policies:
// Strict (recommended):
Content-Security-Policy:
  default-src 'none';
  script-src 'self';
  style-src 'self';
  img-src 'self';
  connect-src 'self';
  font-src 'self';
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self'

Google Senior Frontend — CSP

Q: Walk through implementing CSP for a production React app.

Step 1: Start with Report-Only mode. Content-Security-Policy-Report-Only: default-src 'self'; report-uri /csp-reports. Monitor what breaks. Step 2: Identify all sources — your CDN, analytics (Google Analytics), fonts (Google Fonts), API endpoints. Step 3: Build policy: default-src 'none'; script-src 'self' 'nonce-{random}'; style-src 'self' 'unsafe-inline' (React CSS-in-JS may need this); img-src 'self' data: https://images.yourcdn.com; connect-src 'self' https://api.yourapp.com; font-src 'self' https://fonts.gstatic.com; frame-ancestors 'none'; base-uri 'self'; form-action 'self'. Step 4: Handle inline scripts — use nonces. Server generates random nonce per request, injects into CSP header and script tags. React SSR: pass nonce to __NEXT_DATA__ script. Step 5: Enforce after monitoring shows no false positives. Step 6: Iterate — add strict-dynamic for dynamically loaded scripts.
