Production-Safe Logging

// Create a logger that strips sensitive data in production
const logger = {
  log(...args) {
    if (process.env.NODE_ENV === 'development') {
      console.log(...args);
    }
    // In production: send to server-side logging (Datadog, etc.)
  },
  error(msg, error) {
    // Always log errors, but sanitize
    const sanitized = sanitizeError(error);
    console.error(msg, sanitized);
    sendToErrorTracking(msg, sanitized);
  }
};

// Webpack: Remove console.* in production
// terser options:
{
  compress: {
    drop_console: true,      // remove ALL console.*
    drop_debugger: true,     // remove debugger statements
    pure_funcs: ['console.log', 'console.debug'] // selective
  }
}

// Source maps: Upload to error tracker, don't serve publicly
// webpack.config.js:
devtool: isProduction ? 'hidden-source-map' : 'eval-source-map'

Google Senior Frontend — DevTools Security

Q: How do you prevent sensitive data from appearing in memory heap snapshots?

You can't fully prevent it — any data in JavaScript memory is visible in heap snapshots. But you can minimize exposure: (1) Zero-out sensitive variables after use: token = null; password = ''. In practice, V8 may not immediately GC the old value, but it reduces the window. (2) Use short-lived closures for sensitive operations — the data is GC'd when the closure completes. (3) For crypto keys: use the Web Crypto API's CryptoKey objects. These are opaque — the key material isn't accessible via JavaScript, so it won't appear in heap dumps. (4) Avoid storing decrypted data longer than needed. Process → display → discard. (5) For extremely sensitive apps: consider using WebAssembly for crypto operations (memory is more isolated, though not perfectly).
