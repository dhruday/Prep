Key Takeaways

The Problem

When 5 independent components mount and each calls fetch('/api/rest/products'), the browser fires 5 identical network requests — wasting bandwidth and server resources.

Promise Map Solution

A promise map (also called an inflight map) stores the pending promise keyed by URL. If a request for a key already exists, we return the same promise instead of starting a new fetch. Once resolved, the entry is removed so future calls get fresh data.

Result: 5 callers → 1 network request → all 5 receive the same response.

Flow Diagram

Component A ─┐
Component B ─┤
Component C ─┼─► promiseMap.has(key)?
Component D ─┤       ├─ YES → return existing promise
Component E ─┘       └─ NO  → fetch(), store in map, return promise
                                   └─► on settle → delete from map

dedupFetch.js

const inflightMap = new Map();

async function dedupFetch(url, options = {}) {
  const key = url + JSON.stringify(options);

  if (inflightMap.has(key)) {
    // Return the already-inflight promise
    return inflightMap.get(key);
  }

  const promise = fetch(url, options)
    .then(r => r.json())
    .finally(() => inflightMap.delete(key));

  inflightMap.set(key, promise);
  return promise;
}

Usage — 5 Components

// All 5 calls share one network request
const [a, b, c, d, e] = await Promise.all([
  dedupFetch('/api/rest/products'),
  dedupFetch('/api/rest/products'),
  dedupFetch('/api/rest/products'),
  dedupFetch('/api/rest/products'),
  dedupFetch('/api/rest/products'),
]);
// a === b === c === d === e  (same reference)

When to Use

• Multiple UI components that mount simultaneously and need the same data.
• SPA route transitions where shared data is fetched by independent modules.
• Micro-frontend architectures where separate apps query the same API.

Gotchas

• The key must include method + body for POST dedup (be careful with mutable bodies).
• Only works within a single page context — cross-tab needs Service Workers.
• If one caller needs different headers, the key diverges and dedup won't apply.
• Always clean up on .finally() to avoid stale entries on errors.
