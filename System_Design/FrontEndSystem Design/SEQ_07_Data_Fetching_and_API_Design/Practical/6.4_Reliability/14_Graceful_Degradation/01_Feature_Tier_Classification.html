Feature Tier Pyramid

Not all features are equal. Classify each by business impact to decide failure behavior:

CRITICAL Auth, checkout, core data — failure = error page + block interaction
CORE Dashboard stats, user profile — failure = show cached data + warning banner
ENRICHMENT Recommendations, activity feed — failure = subtle notice, hide section
OPTIONAL Ads, analytics, social widgets — failure = silently hide, no user impact
The tier determines how aggressively you retry, what fallback UI to show, and whether the user should be notified at all.

Tier Classification Engine

const TIERS = {
  CRITICAL:    { retry: 3, fallback: 'error_page',  notify: true  },
  CORE:        { retry: 2, fallback: 'cached_data', notify: true  },
  ENRICHMENT:  { retry: 1, fallback: 'hide_notice', notify: false },
  OPTIONAL:    { retry: 0, fallback: 'silent_hide', notify: false },
};

const WIDGET_MAP = {
  auth:           'CRITICAL',
  accountBalance: 'CRITICAL',
  dashStats:      'CORE',
  userProfile:    'CORE',
  recommendations:'ENRICHMENT',
  activityFeed:   'ENRICHMENT',
  ads:            'OPTIONAL',
  socialShare:    'OPTIONAL',
};

async function loadWidget(name, fetchFn) {
  const tier = TIERS[WIDGET_MAP[name]];
  for (let i = 0; i <= tier.retry; i++) {
    try { return await fetchFn(); }
    catch(e) { if (i === tier.retry) return applyFallback(name, tier); }
  }
}

Key Points

• Classify features before building — tier determines error handling strategy

• CRITICAL failures block the user; OPTIONAL failures are invisible

• Cache strategy scales with tier: CRITICAL=fresh only, CORE=stale-while-revalidate, OPTIONAL=no cache needed

• Retry budget is proportional to tier importance

• Monitor tier-specific error rates separately in production

Interview tip: "We classify features into tiers so a failing ad widget never takes down the checkout flow."
