What is CLS?

Cumulative Layout Shift measures unexpected movement of visible content. A good CLS score is < 0.1.

Layout shift happens when elements appear and push existing content down or aside. This is jarring — users might click the wrong button.

How Skeletons Prevent CLS

Without Skeleton
Empty → content pops in → pushes everything below it down → CLS = 0.15+
With Skeleton
Skeleton reserves space → content fills same space → nothing moves → CLS ≈ 0

Measuring CLS with PerformanceObserver

let clsScore = 0;

const observer = new PerformanceObserver((list) => {
  for (const entry of list.getEntries()) {
    if (!entry.hadRecentInput) {
      clsScore += entry.value;
      console.log(`CLS shift: ${entry.value.toFixed(4)}`);
      console.log(`Total CLS: ${clsScore.toFixed(4)}`);
    }
  }
});

observer.observe({
  type: 'layout-shift',
  buffered: true,
});

// Good: CLS < 0.1
// Needs improvement: 0.1 – 0.25
// Poor: > 0.25

Key Points

• CLS < 0.1 is "good" — skeleton loaders are the primary tool to achieve this

• Use PerformanceObserver with type: 'layout-shift' to measure CLS

• Filter out hadRecentInput shifts — user-initiated shifts don't count

• Reserve space with explicit dimensions: min-height, aspect-ratio

• Images: always set width/height attributes or use aspect-ratio

Interview tip: "We use shape-matched skeletons and PerformanceObserver to keep CLS below 0.1 on all routes."
