ARIA Attributes for Loading States

Skeleton loaders are visual — screen readers need explicit ARIA attributes:

aria-busy="true" — tells assistive tech the region is loading, defer reading

aria-live="polite" — announce when content finishes loading (without interrupting)

aria-hidden="true" — hide the skeleton shapes themselves (they're decorative)

role="status" — semantic role for live status updates

prefers-reduced-motion

Vestibular disorders can be triggered by animations. Always provide a static fallback for shimmer effects using @media (prefers-reduced-motion: reduce).

Accessible Skeleton Markup

<!-- Container: aria-busy + aria-live -->
<section
  aria-busy="true"
  aria-live="polite"
  aria-label="Dashboard content"
>
  <!-- Skeleton: hidden from screen readers -->
  <div class="skeleton" aria-hidden="true">
    <div class="skel-line"></div>
    <div class="skel-line"></div>
  </div>

  <!-- Screen reader only announcement -->
  <div class="sr-only" role="status">
    Loading dashboard content...
  </div>
</section>

<!-- After loading: -->
<section
  aria-busy="false"
  aria-live="polite"
>
  <!-- Real content — screen reader reads it -->
  <h2>Revenue: $42,381</h2>
</section>

Key Points

• aria-busy="true" on the container — screen reader defers reading until false

• aria-live="polite" — announces new content without interrupting current speech

• aria-hidden="true" on skeleton shapes — they're decorative, not content

• Add a .sr-only text "Loading..." for screen readers during skeleton state

• prefers-reduced-motion → disable shimmer, show static gray

• Never use aria-live="assertive" for loading — it's too aggressive

Interview tip: "Our skeletons use aria-busy on the container, aria-hidden on shapes, and polite live regions for load completion."
