useDebounce — Debounced Value Hook

function useDebounce(value, delay) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);  // cleanup on re-render
  }, [value, delay]);

  return debounced;
}
Returns a debounced copy of the value. The API call is triggered in a separate useEffect that depends on debouncedValue.

useThrottle — Throttled Value Hook

function useThrottle(value, limit) {
  const [throttled, setThrottled] = useState(value);
  const lastRan = useRef(Date.now());

  useEffect(() => {
    const handler = setTimeout(() => {
      if (Date.now() - lastRan.current >= limit) {
        setThrottled(value);
        lastRan.current = Date.now();
      }
    }, limit - (Date.now() - lastRan.current));
    return () => clearTimeout(handler);
  }, [value, limit]);

  return throttled;
}

useDebouncedCallback — Debounced Function Hook

function useDebouncedCallback(fn, delay) {
  const fnRef = useRef(fn);
  fnRef.current = fn;  // always latest — avoids stale closure

  const timerRef = useRef();
  return useCallback((...args) => {
    clearTimeout(timerRef.current);
    timerRef.current = setTimeout(() => fnRef.current(...args), delay);
  }, [delay]);
}

The ref pattern is critical in React — without it, your debounced callback sees the state from the render it was created in, not the latest state.

Closures & the Scope Chain

When React creates an effect callback, it captures variables via closure. On the next render, a new closure is created with updated values. The old timer still references the old closure — that's the stale closure.

Why useRef Fixes It

useRef returns a mutable object ({ current: … }) that persists across renders. All closures reference the same object, so reading ref.current always gives the latest value.

Cleanup & Effect Timing

// React effect lifecycle
render #1 → effect runs → sets timer A
render #2 → cleanup runs → clearTimeout(A)
            → effect runs → sets timer B
// Only timer B fires — no stale invocation

The cleanup function returned from useEffect is crucial — it cancels the previous timer before setting a new one.

Memory: Multiple Timers

Without cleanup, every keystroke leaks a pending timer. With 50 keystrokes, 49 timers fire with stale data. The cleanup ensures at most 1 active timer.

Q: useDebounce value vs useDebouncedCallback — when to use which?

useDebounce(value): When you want a debounced derived value (e.g., debounced search term).
useDebouncedCallback(fn): When you need a stable debounced function reference (e.g., onChange handler passed to a child).

Q: How do you cancel debounce on unmount?

useEffect(() => {
  return () => clearTimeout(timerRef.current);
}, []);  // cleanup on unmount

Without this, the timer fires after the component unmounts, causing "setState on unmounted component" warnings.

Q: Explain the stale closure bug in an interview.

"Each render creates a new closure that captures the current state. A debounced callback from render N still sees render N's state. When it fires later, state may be at render N+5. Using a ref ensures the callback always reads the latest value."

Q: Should you memoize the debounced function?

Yes — wrap with useCallback (or useMemo) keyed on delay. Otherwise, every render creates a new debounce instance, resetting the timer and breaking the debounce entirely.
