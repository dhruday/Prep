Why performance is a UX choice, not just a technical metric

Every UX decision carries a performance cost. Animations, rich images, instant search, real-time updates, and heavy fonts all come at a price. At FAANG-tier companies the performance budget is treated as a design constraint from day 1 — just as a designer works within a color palette, a frontend architect works within a JS/CSS/image budget. The key skill interviewers probe: can you make the UX feel fast even when it technically isn't?

UX desires that hurt perf
  • Hero images / video backgrounds
  • Custom web fonts (FOUT/FOIT)
  • Instant search (debounce vs real-time)
  • Page transitions / shared element anim
  • Rich skeleton loaders with animation
  • Heavy analytics SDKs (GA4, Segment)
Perf techniques that feel worse
  • Lazy loading images → pop-in below fold
  • Code-split route → blank then paint
  • SSR with no hydration → dead UI
  • Aggressive cache → stale data shown
  • Reducing JS → less interactivity
  • deferring fonts → FOUT flash

Perceived performance techniques — make it feel fast

Skeleton screens
Show content shape before data arrives — reduces perceived wait vs blank spinners. Reduces anxiety (user sees structure).
Optimistic updates
Update UI instantly on user action, roll back on API error. Feels native — like tapping a like button with no delay.
Progress indication
Even fake progress (NProgress) reduces perceived wait. Users tolerate 2x longer waits if they see a moving indicator.
Prefetch on hover
On link or button hover (175ms), prefetch the next route's data and code. Converts anticipated wait to actual 0ms navigation.

Optimistic update + prefetch on hover

// ─── Optimistic like button (React + TanStack Query) ───
const mutation = useMutation({
  mutationFn: () => api.post(`/posts/${id}/like`),
  onMutate: async () => {
    await queryClient.cancelQueries(['post', id]);
    const prev = queryClient.getQueryData(['post', id]);
    queryClient.setQueryData(['post', id], old => ({
      ...old, likes: old.likes + 1, liked: true
    }));
    return { prev };
  },
  onError: (_err, _vars, ctx) => {
    queryClient.setQueryData(['post', id], ctx.prev); // rollback
  },
  onSettled: () => queryClient.invalidateQueries(['post', id])
});

// ─── Prefetch on hover (React Router v6) ───
function NavLink({ to, children }) {
  const navigate = useNavigate();
  const timer = useRef(null);
  const onEnter = () => {
    timer.current = setTimeout(() => {
      queryClient.prefetchQuery({ queryKey: [to], queryFn: () => fetch(to) });
    }, 100); // 100ms intent threshold
  };
  return <a onMouseEnter={onEnter} onMouseLeave={() => clearTimeout(timer.current)} href={to}>{children}</a>;
}
