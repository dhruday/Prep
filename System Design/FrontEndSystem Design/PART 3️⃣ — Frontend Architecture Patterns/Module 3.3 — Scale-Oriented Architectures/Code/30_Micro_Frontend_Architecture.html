Hruday's SAP Implementation

SAP Fiori was one Angular monolith — 18-minute builds, any change deployed everything. Using Webpack 5 Module Federation, Hruday split it into 3 micro-frontends:
  • Shell: routing, auth, shared design system
  • Procurement MFE: purchase orders, suppliers
  • Analytics MFE: dashboards, reports
Result: 4-minute builds per MFE, 3 teams deploy independently, zero cross-team coordination for releases.

Module Federation — Webpack 5

// Orders MFE — webpack.config.js (exposes components)
new ModuleFederationPlugin({
  name: 'orders',
  filename: 'remoteEntry.js',
  exposes: {
    './OrderList': './src/components/OrderList',
    './OrderDetail': './src/components/OrderDetail',
  },
  shared: { react: { singleton: true }, 'react-dom': { singleton: true } },
});

// Shell — webpack.config.js (consumes remotes)
new ModuleFederationPlugin({
  name: 'shell',
  remotes: {
    orders: 'orders@https://orders.sap.example.com/remoteEntry.js',
    analytics: 'analytics@https://analytics.sap.example.com/remoteEntry.js',
  },
  shared: { react: { singleton: true }, 'react-dom': { singleton: true } },
});

// Shell usage — lazy loads Orders MFE at runtime
const OrderList = lazy(() => import('orders/OrderList'));

// Orders MFE can be deployed WITHOUT redeploying the shell

Micro-Frontend Tradeoffs

✅ Wins
Independent deployments
Team autonomy (own codebase)
Tech stack flexibility
Fault isolation
Incremental migration
Faster CI per team
⚠️ Costs
Bundle duplication (React × N)
Cross-MFE communication complexity
Shared state management hard
CSS isolation needed
Version mismatch risk
Ops overhead (N deploy pipelines)
Rule of thumb: Micro-frontends are right when you have 4+ independent teams working on the same UI. Below that, the coordination overhead exceeds the benefits. A monorepo with feature modules is often simpler.
