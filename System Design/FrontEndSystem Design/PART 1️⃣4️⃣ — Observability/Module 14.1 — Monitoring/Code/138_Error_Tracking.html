Error tracking turns production crashes into actionable GitHub issues

Without error tracking, production bugs are invisible until users report them. Error tracking tools (Sentry, Datadog RUM, Rollbar) automatically: (1) capture unhandled exceptions and promise rejections, (2) attach source maps to show real line numbers instead of minified code, (3) group similar errors into "issues", (4) add breadcrumbs (recent user actions), (5) alert via Slack/PagerDuty. SAP uses Dynatrace across its BTP frontend fleet.

JS Exception
TypeError, ReferenceError, SyntaxError — caught by window.onerror or window.addEventListener('error')
Promise Rejection
Uncaught promise rejections — caught by unhandledrejection event. Common for async/await without try/catch
React Error Boundary
Catches errors in render tree. componentDidCatch reports to Sentry. Without boundaries — entire tree unmounts.

Sentry setup + React Error Boundary + source maps

// ─── Sentry initialization ───
Sentry.init({
  dsn: process.env.SENTRY_DSN,
  environment: process.env.NODE_ENV,
  release: `myapp@${process.env.COMMIT_SHA}`,
  tracesSampleRate: 0.1,     // 10% of sessions traced
  integrations: [new Sentry.BrowserTracing()],
  beforeSend: (event) => {
    // Strip PII from captured data
    delete event.user?.email;
    return event;
  }
});

// ─── React Error Boundary ───
class ErrorBoundary extends React.Component {
  componentDidCatch(error: Error, info: React.ErrorInfo) {
    Sentry.captureException(error, {
      contexts: { react: { componentStack: info.componentStack } }
    });
  }
  render() {
    return this.state.hasError
      ? <ErrorFallback /> : this.props.children;
  }
}

// ─── source maps: vite.config.ts ───
import { sentryVitePlugin } from '@sentry/vite-plugin';
export default {
  build: { sourcemap: true },  // generate source maps
  plugins: [sentryVitePlugin({ org: 'my-org', project: 'frontend' })]
  // Plugin uploads maps to Sentry & deletes from deploy artifact
};
