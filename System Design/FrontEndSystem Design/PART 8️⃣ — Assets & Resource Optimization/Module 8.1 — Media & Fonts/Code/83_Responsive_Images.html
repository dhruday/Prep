Why responsive images? — the 4x overserve problem

A 1920×1080 image sent to a 360px mobile screen downloads 5.3× more pixels than needed. At 2× device pixel ratio (Retina), you need 720px wide — still 2.7× smaller than the desktop image. Responsive images let the browser pick the right file for each screen.

srcset + sizes (resolution switching)
Same image, different dimensions. Browser picks best fit based on viewport and DPR. Use when only the size changes, not the composition.
picture element (art direction)
Different crops/photographs for different viewports. Use when composition must change (e.g., full-width landscape on desktop → portrait crop on mobile).

DPR tip: Always generate 1×, 1.5×, and 2× variants. A Retina Mac requesting a 400px-wide image needs the 800px variant for sharp rendering. Use the w descriptor (physical pixels) not x descriptor for fluid layouts.

Art direction vs resolution switching — decision guide

Use srcset (resolution switching) when:
  • Same image, different sizes (product photo)
  • Performance-only concern (not composition)
  • CSS background-image alternative exists
Use <picture> (art direction) when:
  • Different crop/composition per breakpoint (hero banner)
  • Format fallback needed (AVIF → WebP → JPEG)
  • Orientation-specific images (landscape desktop, portrait mobile)
CDN-based approach (Cloudinary / imgix):
Generate variants on-the-fly via URL parameters. No build step needed. e.g., https://res.cloudinary.com/demo/image/upload/w_800,f_auto,q_auto/hero.jpg — auto picks format + quality + width.

Responsive image HTML + Next.js patterns

<!-- Resolution switching with srcset + sizes -->
<img
  srcset="
    /img/hero-400.webp  400w,
    /img/hero-800.webp  800w,
    /img/hero-1200.webp 1200w"
  sizes="
    (max-width: 600px)  100vw,
    (max-width: 1200px) 50vw,
    1200px"
  src="/img/hero-1200.webp"
  alt="SAP dashboard"
  width="1200" height="800"
  loading="lazy" />

<!-- Art direction: different crops per breakpoint -->
<picture>
  <source media="(min-width:1024px)" srcset="hero-landscape.webp 1x, hero-landscape@2x.webp 2x">
  <source media="(min-width:600px)"  srcset="hero-tablet.webp 1x, hero-tablet@2x.webp 2x">
  <img src="hero-mobile.webp" alt="Dashboard" width="400" height="600" loading="lazy">
</picture>

// ─── Next.js: sizes drives srcset generation ───
<Image
  src="/hero.jpg" alt="Dashboard"
  fill  // fills parent container
  sizes="(max-width: 768px) 100vw, 50vw"
  style={{ objectFit: 'cover' }}
/>

// ─── Generate responsive variants with Sharp ───
const widths = [400, 800, 1200, 1920];
await Promise.all(widths.map(w =>
  sharp('hero.jpg').resize(w).webp({ quality: 80 }).toFile(`hero-${w}.webp`)
));
