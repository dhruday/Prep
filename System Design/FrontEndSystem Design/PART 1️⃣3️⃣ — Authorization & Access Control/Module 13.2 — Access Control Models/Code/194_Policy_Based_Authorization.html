Policy-Based Authorization: separate policy from code

Core principle: declare WHAT you want, not HOW to check it
❌ Authorization in business logic
if user.role === 'admin'
  || (user.dept === doc.dept
  && user.level >= 2)
  && !doc.archived {
  // allow
}
✅ Policy-based declaration
can(ability, 'update', 'Document',
  { department: user.dept,
    archived: false })
OPA (Open Policy Agent)
Sidecar/service model. Policies in Rego language. Language-agnostic. Netflix, Cloudflare, Kubernetes. Best for microservices mesh, infrastructure policy.
CASL (JS)
Embedded library. Isomorphic — same policy rules run on both frontend and backend. Perfect for Angular/React + Node.js full-stack TypeScript projects.

CASL isomorphic policy — shared frontend + backend

// abilities.ts — shared between Angular/React and Node.js
import { AbilityBuilder, PureAbility } from '@casl/ability';

type Actions = 'read' | 'update' | 'delete' | 'approve';
type Subjects = 'Document' | 'Invoice' | 'all';
export type AppAbility = PureAbility<[Actions, Subjects]>;

export function defineAbilitiesFor(user: User): AppAbility {
  const { can, cannot, build } = new AbilityBuilder<AppAbility>(PureAbility);

  if (user.role === 'admin') {
    can('manage', 'all');
  } else if (user.role === 'manager') {
    can('read', 'Document');
    can('update', 'Document', { department: user.department });
    can('approve', 'Invoice', { department: user.department, amount: { $lt: 50000 } });
  } else {
    can('read', 'Document', { department: user.department });
    cannot('delete', 'Document');
  }
  return build();
}
