Reading profiler flame graphs — the mental model

The React DevTools Profiler records every render during a "commit". The flame graph shows the component tree where width = render time and color intensity = how much it slowed down. Grey = didn't render this commit. Yellow/orange = rendered and was slow. The key insight: a narrow yellow bar deep in the tree is fine; a wide yellow bar at the top means that subtree has a systemic re-render problem.

Width
Time spent rendering. Wide = expensive. The total width of a branch = total cost of that subtree.
Color
Orange/red = slow relative to sibling commits. Grey = skipped render (good! React.memo or PureComponent worked).
Depth
Deep nesting of same-colored blocks = cascading re-renders. Fix: memoize intermediate components or lift state.

5 things to look for in every flame graph

1. Wide top-level yellow bar — root re-rendering everything; global state change
2. Tall orange stack in one branch — one component subtree is expensive; candidate for memoization
3. Grey blocks — React.memo/useMemo is working, skipping render successfully
4. Repeated identical renders in the "commits" bar — same data re-rendering unnecessarily; check useEffect deps
5. "Why did this render?" — DevTools shows the prop/state that changed; 99% of over-renders are due to new object/array references

React.memo + useCallback — correct pattern

// PROBLEM: List re-renders every item when any item changes
function TaskList({ tasks }: { tasks: Task[] }) {
  const [filter, setFilter] = useState('');
  
  // ❌ New function reference every render → children always re-render
  const handleDelete = (id: string) => deleteTask(id);
  
  return tasks.map(task =>
    <TaskItem key={task.id} task={task} onDelete={handleDelete} />
  );
}

// ✅ FIXED: Stable callback + memoized child
function TaskList({ tasks }: { tasks: Task[] }) {
  const [filter, setFilter] = useState('');
  
  // useCallback = stable function reference across renders
  const handleDelete = useCallback((id: string) =>
    deleteTask(id), []   // Empty deps: function never changes
  );
  
  return tasks.map(task =>
    <TaskItem key={task.id} task={task} onDelete={handleDelete} />
  );
}

// React.memo prevents re-render if props are shallowly equal
const TaskItem = React.memo(function TaskItem({ task, onDelete }) {
  // Only re-renders if task object reference OR onDelete reference changes
  // With useCallback above: only re-renders when task itself changes ✅
  return <li>{task.title} <button onClick={() => onDelete(task.id)}>Delete</button></li>;
});
