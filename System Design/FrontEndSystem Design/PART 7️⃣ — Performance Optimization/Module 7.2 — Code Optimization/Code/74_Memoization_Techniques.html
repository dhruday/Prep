Memoization — cache results to skip redundant work

Memoization caches the result of a computation and returns the cached value if the inputs haven't changed. In frontend development this means: skip re-renders (React.memo), skip recomputation (useMemo), and stabilise function references (useCallback).

React.memo
HOC that wraps a component. Skips re-render if props are shallowly equal. Parent re-renders do NOT cascade to this child.
Use on: stable, pure components with expensive renders
useMemo
Memoises the result of an expensive computation. Only recomputes when deps array changes. Returns cached value otherwise.
Use on: expensive filter/sort/transform, derived state
useCallback
Memoises a function reference. Returns the same function identity unless deps change. Prevents React.memo bypass when callbacks are passed as props.
Use on: callbacks passed to memo'd children

useMemo vs useCallback — when to use which

useMemo(fn, deps) → memoised VALUE
Use when: expensive derivation (filter + sort 10k items), selector function, complex object that needs stable reference for React.memo children. 
const filtered = useMemo(() =>
  items.filter(i => i.status === filter).sort(...),
  [items, filter]
);
useCallback(fn, deps) → memoised FUNCTION
Use when: callback passed as prop to React.memo child — stabilises function identity so memo's shallow comparison doesn't see a "new" function every render. 
const handleDelete = useCallback((id: string) => {
  dispatch(removeItem(id));
}, [dispatch]); // stable reference
❌ Over-memoizing
useMemo and useCallback themselves have overhead (closure allocation, dep comparison). Don't apply to cheap computations or components with constantly changing props — the memo check costs more than skipping it.

Memoization patterns in TypeScript

// ─── React.memo with custom comparator ───
const OrderRow = React.memo(
  ({ order }: { order: Order }) => <tr>...</tr>,
  (prev, next) => prev.order.id === next.order.id
    && prev.order.status === next.order.status   // custom equality
);

// ─── useMemo for expensive derivation ───
const sortedOrders = useMemo(() =>
  orders
    .filter(o => o.status === activeFilter)
    .sort((a, b) => new Date(b.date).getTime() - new Date(a.date).getTime()),
  [orders, activeFilter]   // recomputes only when these change
);

// ─── useCallback to stabilise event handler ───
const OrderList = ({ userId }: Props) => {
  const dispatch = useDispatch();
  const handleApprove = useCallback(
    (id: string) => dispatch(approveOrder(id)),
    [dispatch]   // dispatch is stable from Redux
  );
  return orders.map(o => <OrderRow key={o.id} order={o} onApprove={handleApprove} />);
};

// ─── Angular: OnPush ChangeDetectionStrategy ───
@Component({ changeDetection: ChangeDetectionStrategy.OnPush })
class OrderRowComponent {
  // Only re-renders when @Input reference changes or event fires
  @Input() order!: Order;
}
