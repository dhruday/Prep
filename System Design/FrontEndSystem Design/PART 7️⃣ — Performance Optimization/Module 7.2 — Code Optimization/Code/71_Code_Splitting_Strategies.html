Code splitting — ship only what the user needs now

Without code splitting, all JS ships in one giant bundle. The browser must parse and compile ALL of it before the page becomes interactive — even code for routes the user may never visit. Code splitting breaks the bundle into smaller chunks loaded on demand.

Route-based splitting
Each page/route = separate chunk. Most impactful. Dashboard code not loaded on login page.
✅ Default in Next.js/React Router
Component-based splitting
Heavy components (charts, editors, PDF viewer) loaded dynamically. Visible on demand.
✅ React.lazy(), dynamic import()
Vendor splitting
Third-party libs (React, lodash) in separate chunk. Long-term caching — doesn't change on deploys.
✅ Webpack SplitChunksPlugin
SAP context: SAP Fiori dashboard initial bundle was 2.4MB. Route-based code splitting + lazy-loading Chart.js reduced initial load to 380KB. TTI improved from 8.2s → 2.1s on 4G.

Code splitting patterns

// ─── React: Route-based (React.lazy + Suspense) ───
const Dashboard = React.lazy(() => import('./pages/Dashboard'));
const Analytics = React.lazy(() => import('./pages/Analytics'));

<Suspense fallback={<PageSkeleton />}>
  <Routes>
    <Route path="/dashboard" element={<Dashboard />} />
    <Route path="/analytics" element={<Analytics />} />
  </Routes>
</Suspense>

// ─── Component-based: heavy modal ───
const ChartModal = React.lazy(() => import('./ChartModal'));
{showChart && <Suspense fallback={null}><ChartModal /></Suspense>}

// ─── Dynamic import with prefetch ───
// Webpack magic comment — prefetches during browser idle
const { default: Chart } = await import(
  /* webpackPrefetch: true */
  './Chart'
);

// ─── Next.js dynamic ───
import dynamic from 'next/dynamic';
const HeavyEditor = dynamic(() => import('./Editor'), {
  loading: () => <Skeleton />,
  ssr: false,   // don't SSR the code-split chunk
});
