An operation is idempotent if applying it multiple times gives the same result as once

Frontend idempotency matters because: (1) button clicks may fire twice due to double-click or laggy network delay, (2) offline queued mutations may be replayed on reconnect, (3) optimistic update + server confirmation can double-apply. At SAP, a "Submit Purchase Order" button that isn't idempotent could create two POs worth €50,000 each — critical defect. The fix: idempotency key (UUID per submission form load).

✅ Idempotent operations
  • SET status = "approved" (any n times → same)
  • PUT /orders/123 body (replace, not append)
  • Toggle with explicit target state (setTheme('dark'))
  • Cache invalidation (idempotent by nature)
❌ Non-idempotent operations
  • POST /orders (each call creates a new order)
  • balance += 100 (increments with each call)
  • Toggle without state (toggleTheme → unknown result)
  • Append to list without dedup

Idempotency key pattern + button disable

// ─── Generate idempotency key once per form ───
function useIdempotencyKey() {
  const [key] = useState(() => crypto.randomUUID());
  return key;
}
function SubmitOrder() {
  const idemKey = useIdempotencyKey();
  const [submitting, setSubmitting] = useState(false);
  const submit = async () => {
    if (submitting) return; // guard
    setSubmitting(true);
    await fetch('/api/orders', {
      method: 'POST',
      headers: { 'Idempotency-Key': idemKey }, // server deduplicates
      body: JSON.stringify(orderData),
    });
    // don't re-enable — force new form instance for new order
  };
  return <button disabled={submitting} onClick={submit}>Submit Order</button>;
}

// ─── Server: check idempotency ───
app.post('/api/orders', async (req, res) => {
  const key = req.headers['idempotency-key'];
  const existing = await redis.get(`idem:${key}`);
  if (existing) return res.json(JSON.parse(existing)); // replay cached response
  const order = await createOrder(req.body);
  await redis.setex(`idem:${key}`, 86400, JSON.stringify(order));
  res.json(order);
});
