In distributed real-time systems, partial failures are the norm

A real-time application pulls data from multiple services. If one service is slow or down, the UI must degrade gracefully — showing partial data with stale indicators rather than failing completely. At SAP, the order management dashboard fetched from 3 microservices: if the analytics service was slow, the order list still rendered with an "analytics unavailable" banner rather than blocking everything.

Circuit Breaker
After N failures, stop calling the failing service. Return fallback instantly. Half-open after timeout.
Fallback / graceful degrade
Show cached/stale data or placeholder when a service fails. App remains usable.
Timeout + Abort
Set a deadline on every fetch. If exceeded, AbortController cancels and fallback kicks in.

Promise.allSettled + AbortController pattern

// ─── Fetch from multiple services, degrade gracefully ───
async function loadDashboard() {
  const ac = new AbortController();
  const timeout = setTimeout(() => ac.abort(), 5000);
  const [orders, analytics, inventory] = await Promise.allSettled([
    fetch('/api/orders',    { signal: ac.signal }).then(r => r.json()),
    fetch('/api/analytics', { signal: ac.signal }).then(r => r.json()),
    fetch('/api/inventory', { signal: ac.signal }).then(r => r.json()),
  ]);
  clearTimeout(timeout);
  return {
    orders:    orders.status    === 'fulfilled' ? orders.value    : null,
    analytics: analytics.status === 'fulfilled' ? analytics.value : cachedAnalytics,
    inventory: inventory.status === 'fulfilled' ? inventory.value : null,
    degraded: [orders, analytics, inventory]
      .filter(r => r.status === 'rejected').length,
  };
}

// ─── React Error Boundary for widget isolation ───
class WidgetBoundary extends React.Component {
  state = { error: null };
  static getDerivedStateFromError(error) { return { error }; }
  render() {
    return this.state.error
      ? <div className="widget-error">Analytics unavailable</div>
      : this.props.children;
  }
}
