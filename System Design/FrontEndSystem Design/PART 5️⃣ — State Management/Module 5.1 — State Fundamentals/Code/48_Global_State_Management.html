Global State — shared across the tree

Global state is state that multiple unrelated components need access to. It lives outside any single component and is accessible anywhere in the component tree. Examples: authenticated user, theme, shopping cart, notifications, permissions.

❌ Without global state
Pass user down 6 levels (prop drilling). Every intermediate component takes a prop it doesn't need. Hard to refactor.
✅ With global state
Any component reads user from store directly. Component decoupled from parent. No drilling.
Candidates for global state: auth user, theme/dark mode, language locale, cart/basket, global notifications, feature flags, online/offline status.

Zustand global store (SAP cart)

// store/cartStore.ts
import { create } from 'zustand';

interface CartItem { id: string; name: string; price: number }
interface CartStore {
  items: CartItem[];
  addItem: (item: CartItem) => void;
  removeItem: (id: string) => void;
  total: () => number;
}

export const useCartStore = create<CartStore>()((set, get) => ({
  items: [],
  addItem: (item) => set(state => ({ items: [...state.items, item] })),
  removeItem: (id) => set(state => ({ items: state.items.filter(i => i.id !== id) })),
  total: () => get().items.reduce((s, i) => s + i.price, 0),
}));

// NavBar — subscribes to ONLY item count (no re-render on price change)
const { CartBadge } = () => {
  const count = useCartStore(state => state.items.length);
  return <Badge>{count}</Badge>;
};

// Checkout — subscribes to total
const { OrderSummary } = () => {
  const total = useCartStore(state => state.total());
  return <p>Total: {total}</p>;
};
