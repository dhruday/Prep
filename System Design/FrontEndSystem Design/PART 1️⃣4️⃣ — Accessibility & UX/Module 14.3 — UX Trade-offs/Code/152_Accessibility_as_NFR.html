Why accessibility belongs in your definition of done

Most teams treat accessibility as a last-mile concern: "we'll audit and fix before launch." This approach consistently fails because (1) fixing deep structural issues (wrong heading hierarchy, missing semantic HTML, broken focus flows) late is extremely expensive, and (2) it creates a recurring technical debt cycle. Adobe, Microsoft, and SAP treat a11y the same way they treat performance: a hard quality gate that blocking merges. WCAG AA is a legal requirement in many jurisdictions under ADA, Section 508, and EN 301 549 (EU).

Design phase
Contrast tokens enforced in Figma. ARIA patterns designed before component build. Focus order annotated in specs.
Dev phase
eslint-plugin-jsx-a11y catches issues at keystroke. Storybook a11y addon checks every story. axe-core in unit tests.
CI/CD
axe-playwright or cypress-axe on PR. Lighthouse CI a11y score gate (e.g., <90 fails PR). Automated regression on critical user paths.

✦ "Accessibility Annotations Kit" for focus order, ARIA labels, landmark regions — shared with devs.
✦ Headings hierarchy reviewed in every page spec.
② Editor / Local Dev
✦ eslint-plugin-jsx-a11y: catches missing alt, wrong role, no label, onClick without keyboard handler AT KEYSTROKE.
✦ axe DevTools browser extension installed on all dev machines.
✦ Storybook a11y addon: every story shows a11y violations panel.
③ Unit / Component Tests
✦ @testing-library/react: query by role (getByRole) — forces semantic markup.
✦ jest-axe: axe.run() in snapshot tests catches tree-level violations.
✦ toHaveNoViolations() assertion in every component test suite.
④ PR / CI Gate
✦ axe-playwright (or cypress-axe): runs axe on every page in E2E suite.
✦ Lighthouse CI a11y score threshold: fail PR if score < 90.
✦ ZAP / Deque WorldSpace for full WCAG 2.2 AA automated audit on PR.
✦ GitHub Actions matrix: test across NVDA+Chrome, VoiceOver+Safari.
⑤ Production Monitoring
✦ Periodic axe-core against production URL (weekly cron).
✦ Bug bounty program includes a11y issues.
✦ User feedback channel for AT (assistive tech) users.
✦ VPAT (Voluntary Product Accessibility Template) maintained quarterly.

CI a11y gate — GitHub Actions + axe-playwright + jest-axe

# .github/workflows/a11y.yml
- name: Run a11y tests
  run: npx playwright test --project=a11y

// ─── playwright/tests/a11y.spec.ts ───
import { test, expect } from '@playwright/test';
import { injectAxe, checkA11y } from 'axe-playwright';

test('homepage has no critical a11y violations', async ({ page }) => {
  await page.goto('http://localhost:3000');
  await injectAxe(page);
  await checkA11y(page, null, {
    axeOptions: { runOnly: { type: 'tag', values: ['wcag2a', 'wcag2aa'] } },
    violationCallback: violations =>
      violations.filter(v => v.impact === 'critical')
  });
});

// ─── jest-axe in component test ───
import { axe, toHaveNoViolations } from 'jest-axe';
expect.extend(toHaveNoViolations);

it('Button is accessible', async () => {
  const { container } = render(<Button>Save</Button>);
  const results = await axe(container);
  expect(results).toHaveNoViolations();
});
