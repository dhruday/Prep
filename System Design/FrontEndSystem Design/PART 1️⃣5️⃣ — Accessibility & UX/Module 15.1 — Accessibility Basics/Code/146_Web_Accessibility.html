Accessibility — building for 1.3 billion people with disabilities

Web accessibility ensures people with visual, motor, hearing, and cognitive disabilities can use your product. WCAG (Web Content Accessibility Guidelines) defines the standard. In enterprises, accessibility is a legal requirement (ADA, EN 301 549, BITV). SAP Fiori Design System has built-in WCAG 2.1 AA compliance — every component ships accessible by default. Microsoft evaluates accessibility compliance heavily in all frontend interviews.

Who benefits from accessibility
• 2.2% — blindness or low vision
• 8% — color blindness (red-green alone)
• 15% — some form of disability globally
• Situational: bright sunlight, one hand free
• Aging users (larger text, higher contrast needs)
• Screen reader + switch access + eye tracking users
The business case
• Legal: ADA Title III lawsuits cost $25K–$100K per case
• Market: 1.3B people = $490B spending power
• SEO: semantic HTML improves search ranking
• Quality: accessible code = better structured code
• Procurement: EU public sector requires WCAG 2.1 AA
• Brand: accessibility signals quality and inclusion

WCAG POUR principles — the 4 pillars

👁
Perceivable
Info must be presentable in ways users can perceive. Alt text for images. Captions for video. Color isn't the only indicator.
⌨️
Operable
All UI must be operable via keyboard. No keyboard traps. Skip navigation links. Sufficient time to complete tasks.
💬
Understandable
Text readable. UI predictable behavior. Clear error messages. Labels for all inputs.
🔧
Robust
Content interpretable by current and future assistive technologies. Valid HTML. ARIA correctly used.

WCAG conformance levels

Level Description Requirement
A (minimum)25 criteria — absolute basics (alt text, no keyboard traps)Legal floor in most jurisdictions
AA (standard)38 criteria — includes contrast 4.5:1, resize text, focus visibleEnterprise target. ADA, EN 301 549, BITV 2.0 require AA
AAA (enhanced)28 additional criteria — contrast 7:1, sign language, extended audioNot required for full sites — apply where feasible
WCAG 2.1 vs 2.2 key additions
2.1 added: Reflow (no horizontal scroll at 320px), Non-text contrast (icons/borders), Text spacing override
2.2 added: Focus Appearance (AA), Dragging Movements (AA), Redundant Entry (AA), Accessible Authentication (AA)

Accessible component patterns — images, forms, modals

// ─── Images: always meaningful alt or empty ───
<img src="chart.png" alt="Monthly revenue chart showing 23% growth in Q4" />
<img src="decoration.png" alt="" /> // decorative: empty alt = screen reader skips
<img src="logo.svg" role="img" aria-label="SAP Logo" />

// ─── Form: always associate label with input ───
// BAD — placeholder only
<input type="text" placeholder="Email" />

// GOOD — explicit label
<label htmlFor="email">Email address</label>
<input id="email" type="email" autoComplete="email"
       aria-required="true" aria-describedby="email-error" />
<span id="email-error" role="alert">{errors.email}</span>

// ─── Modal: focus trap + ARIA ───
function Modal({ open, onClose }) {
  const ref = useRef();
  useEffect(() => { if (open) ref.current?.focus(); }, [open]);
  return open && (
    <div role="dialog" aria-modal="true" aria-labelledby="modal-title"
         ref={ref} tabIndex={-1} onKeyDown={e => e.key==='Escape' && onClose()}>
      <h2 id="modal-title">Confirm Delete</h2>
      <FocusTrap> ... </FocusTrap>
    </div>
  );
}
