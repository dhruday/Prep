"There are only two hard things in CS: cache invalidation and naming things" — Phil Karlton

Cache invalidation is deciding WHEN and HOW to remove or refresh stale cached data. Get it wrong and users see outdated order statuses, stale prices, or gone-missing data. At SAP, the procurement catalog uses content-hash filenames for immutable assets and short-TTL + background-revalidate for API data.

TTL-based
Cache expires after N seconds. Simple but data may be stale until expiry. Used with max-age.
Event-based
Cache purged on specific events (mutation, webhook, pub/sub). Accurate but complex plumbing.
Content-hash
Cache key includes file hash. New version = new URL. Old URL cached forever safely (immutable).

React Query / TanStack Query invalidation + HTTP cache headers

// ─── React Query — invalidate on mutation ───
const queryClient = useQueryClient();
const mutation = useMutation({
  mutationFn: updateOrder,
  onSuccess: () => {
    // exact invalidation
    queryClient.invalidateQueries({ queryKey: ['orders'] });
    // or optimistically update without refetch
    queryClient.setQueryData(['orders', 'ORD-001'], updatedOrder);
  },
});

// ─── HTTP cache: immutable hashed assets ───
// nginx config
location ~* \.(js|css|woff2)$ {
  add_header Cache-Control "public, max-age=31536000, immutable";
}
location = /index.html {
  add_header Cache-Control "no-cache"; // always revalidate HTML
}

// ─── SWR (next.js) revalidateOnMutate ───
const { data, mutate } = useSWR('/api/orders', fetcher, {
  revalidateOnFocus: false,
  dedupingInterval: 60000,
});
async function submitOrder(data) {
  await postOrder(data);
  mutate(); // trigger revalidation
}
