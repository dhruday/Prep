Design for offline as the default, not the exception

Offline-first means the app loads and functions from local data (IndexedDB + CacheStorage) first, syncing to the server when connectivity is available. At SAP, field engineers inspecting assets in underground facilities need SAP Field Service Management to work without signal. Offline-first reduces dependency on network latency, giving instant loads even online.

❌ Online-first approach
  • Fetch from network → if fail → show error
  • App broken when offline
  • Every action requires round-trip
  • Poor mobile experience
✅ Offline-first approach
  • Read from local first → sync in background
  • App works without network
  • Mutations queued, synced later
  • Instant loads — feels like native

Offline-first architecture layers

Layer 1 — App Shell

HTML skeleton + CSS + minimal JS cached via Service Worker on first install. App loads instantly on next visit even without network. Navigation works offline.

Layer 2 — Local data store (IndexedDB)

API responses stored locally. Reads always hit IDB first. Writes queued if offline. On reconnect, background sync drains the queue in order.

Layer 3 — Background Sync (Service Worker)

SW listens for online event + Background Sync API fires sync event. Processes queued mutations with retry + exponential backoff.

Layer 4 — Conflict Resolution

When offline changes collide with server changes: last-write-wins (simple), version vectors (robust), or user-prompted merge (most flexible — CRDTs for collaborative apps).

Background Sync + IndexedDB mutation queue

// ─── Service Worker: background sync ───
self.addEventListener('sync', (event: SyncEvent) => {
  if (event.tag === 'pending-mutations') {
    event.waitUntil(drainQueue());
  }
});
async function drainQueue() {
  const db = await openDB('sap-queue', 1);
  const items = await db.getAll('mutations');
  for (const item of items) {
    await fetch(item.url, { method: item.method, body: item.body });
    await db.delete('mutations', item.id);
  }
}

// ─── Client: queue mutation ───
async function safePost(url: string, data: unknown) {
  if (navigator.onLine) {
    return fetch(url, { method: 'POST', body: JSON.stringify(data) });
  }
  // offline: queue it
  const db = await openDB('sap-queue', 1);
  await db.add('mutations', { id: crypto.randomUUID(), url, method: 'POST', body: JSON.stringify(data) });
  await navigator.serviceWorker.ready.then(sw =>
    sw.sync.register('pending-mutations')
  );
}
