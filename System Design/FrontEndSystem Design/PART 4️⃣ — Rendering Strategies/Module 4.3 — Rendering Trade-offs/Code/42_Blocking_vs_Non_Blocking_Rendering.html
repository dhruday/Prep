Blocking vs Non-Blocking Rendering

🔴 Blocking
Render tree is built synchronously. Browser's main thread is occupied. User input is ignored. Janky scrolling/clicks during long renders.
✅ Non-Blocking (Concurrent)
React 18 Concurrent Mode splits render work into units. Can pause, interrupt, resume. High-priority updates (typing) preempt low-priority (data render).
React 18 APIs enabling non-blocking: startTransition, useDeferredValue, useTransition, Suspense. These mark updates as "non-urgent" so React can yield to input events.

startTransition vs useDeferredValue

// startTransition — wrap the setter, keep typing responsive
import { startTransition, useTransition } from 'react';

function SearchPage() {
  const [isPending, startTransition] = useTransition();
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);

  function handleChange(val: string) {
    setQuery(val); // urgent — updates input immediately
    startTransition(() => {
      setResults(heavyFilter(val)); // deferred — can be interrupted
    });
  }
  return (
    <>
      <input value={query} onChange={e => handleChange(e.target.value)} />
      {isPending && <Spinner />}
      <Results data={results} />
    </>
  );
}

// useDeferredValue — defer a value, not a callback
function SearchPage2({ query }) {
  const deferredQuery = useDeferredValue(query);
  // deferredQuery lags behind query — renders with stale data
  // while new render is in progress
  return <HeavyList filter={deferredQuery} />;
}
