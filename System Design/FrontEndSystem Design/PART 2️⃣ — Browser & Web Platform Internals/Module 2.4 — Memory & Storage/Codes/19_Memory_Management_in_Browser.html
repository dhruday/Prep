🔄 V8 GC Algorithm Steps

1
Mark (Roots): Start from GC roots (global vars, stack). Mark all reachable objects.
2
Mark (Object Graph): Traverse the object reference graph. Any reachable = alive.
3
Sweep: Reclaim memory of all UNMARKED objects. They're unreachable = garbage.
4
Compact: (Optional) Move live objects together to reduce fragmentation.
5
Minor GC: Scavenge the "new space" (short-lived objects). Fast — runs frequently.

How to detect leaks:
Chrome DevTools → Memory tab → Take Heap Snapshot. Compare two snapshots over time. Look for growing Detached DOM trees or closure arrays in the retainer path.

🕳 Common Memory Leak Patterns

PatternWhy it LeaksFix
globalLeak = [] Global vars never GC'd — root objects live forever Use let/const in function scope
Event listener not removed Listener holds ref to element; element can't be GC'd element.removeEventListener()
setInterval never cleared Callback closure keeps scope alive forever clearInterval(id)
Detached DOM nodes JS reference to removed DOM element persists Set references to null
Closure over large data Inner function prevents outer scope from GC Set unused data to null in closure
Growing Map/Set as cache Cache never evicts → unbounded growth Use WeakMap/WeakSet

🔮 WeakRef & WeakMap Demo

WeakRef holds a "weak" reference — GC can collect the object if no other strong ref exists. WeakMap keys are weakly held — entries auto-removed when key object is GC'd.
// WeakRef — won't prevent GC
let obj = { data: "big chunk" };
const ref = new WeakRef(obj);
obj = null; // strong ref gone
// GC can now collect it
ref.deref(); // may return undefined after GC

// WeakMap — auto-evicts when key is GC'd
const cache = new WeakMap();
cache.set(domElement, expensiveData);
// When domElement is removed → entry auto-cleared
When to use WeakMap: Attaching metadata to DOM nodes without preventing their cleanup. Perfect for component data stores that should auto-cleanup when the element is removed.
