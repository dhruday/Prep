What are supply chain attacks?

A supply chain attack targets the tools, libraries, and infrastructure that your code depends on rather than your own code directly. Attackers inject malicious code into popular packages, CDNs, or build pipelines that then get distributed to thousands of apps automatically — giving them access to all downstream users.

📦
NPM Compromise
Maintainer takeover, typosquatting, semver hijack
🌐
CDN Compromise
Injecting scripts on cdn.jsdelivr.net, unpkg, etc.
🔧
Build Pipeline
GitHub Actions, CI scripts, webpack plugins poisoned
Famous real-world incidents
🔴 event-stream (2018) — maintainer access given to attacker, added copay bitcoin wallet stealer
🔴 ua-parser-js (2021) — npm account hijacked, malware shipped in 3 versions
🔴 node-ipc (2022) — maintainer intentionally added destructive payload (protestware)
🔴 SolarWinds (2020) — build pipeline injection, US government compromised
🔴 Polyfill.io (2024) — domain bought by Chinese firm, started injecting malware

Supply chain hardening patterns

// 1. Subresource Integrity (SRI) — verify CDN scripts haven't changed
<script
  src="https://cdn.jsdelivr.net/npm/react@18/umd/react.production.min.js"
  integrity="sha384-Zug+QiDoJOrZ5t4lssLdxGhVrurbmBWoR1Km2zxZAim7zcEtdJYCiBQ4iE8wv/J"
  crossorigin="anonymous"
></script>
// If CDN content changes → browser blocks load, no silent hijack

// 2. Lock exact versions — never use ^ or ~ in production
// package.json (bad):
{ "react": "^18.2.0" }  // ← could get 18.3 automatically
// package.json (good):
{ "react": "18.2.0" }    // ← pinned
// Commit package-lock.json (npm) or yarn.lock to ensure reproducible installs

// 3. npm audit CI step — fail build on high severity
// .github/workflows/security.yml
- name: Audit dependencies
  run: npm audit --audit-level=high

// 4. Snyk / Dependabot automated PR on CVE detection
// .github/dependabot.yml
updates:
  - package-ecosystem: "npm"
    directory: "/"
    schedule:
      interval: "weekly"
    open-pull-requests-limit: 5

// 5. .npmrc — private registry + disallow public fallback
registry=https://registry.npmjs.org/
@mycompany:registry=https://my-private-registry.com/
# Prevents dependency confusion attacks

// 6. Pin GitHub Actions to full SHA
# Bad — mutable tag:
uses: actions/checkout@v4
# Good — immutable SHA:
uses: actions/checkout@692973ef  # refs/tags/v4.1.7

// 7. Content Security Policy — restrict script sources
Content-Security-Policy: script-src 'self' 'sha256-abc123';
// Only scripts with matching hash can execute
