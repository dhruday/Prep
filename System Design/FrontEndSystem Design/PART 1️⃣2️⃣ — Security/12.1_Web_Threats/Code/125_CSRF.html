CSRF: tricks authenticated users into making unintended requests to your app

CSRF exploits the fact that browsers automatically send cookies with cross-origin requests. An attacker hosts a page with a hidden form or image that POSTs to your bank — when a logged-in user visits the attacker's page, the browser sends their session cookie, and the bank processes the request. CSRF doesn't steal data — it abuses state-changing actions. Mitigation: CSRF tokens, SameSite cookies, Origin header validation.

Attack conditions required
✗ App uses cookie-based auth (not JWT in Authorization header)
✗ No CSRF token on state-changing endpoints
✗ SameSite=None or not set
✗ No Origin/Referer validation
Why modern SPAs are safer
✅ JWT in Authorization header (custom header = CORS preflight)
✅ fetch() with custom headers → triggers CORS
✅ browser won't auto-send Authorization header cross-origin

CSRF attack flow step-by-step

Step 1: User logs in to bank.com → session cookie set with HttpOnly (auto-sent on all requests)
Step 2: Attacker sends phishing email with link to evil.com/csrf-attack.html
Step 3: evil.com page contains: <form action="https://bank.com/transfer" method="POST"> with hidden fields (amount=10000&to=attacker). Auto-submitted with JS.
Step 4: Browser sends POST to bank.com WITH user's session cookie (same-origin cookie rules apply). Bank.com processes transfer as authenticated action.
Prevention: CSRF token in form (attacker can't read it cross-origin). SameSite=Strict/Lax cookie stops cross-site sends.

CSRF token + SameSite cookie patterns

// ─── CSRF Token in form (server renders nonce) ───
// Server: generate token, store in session
const csrfToken = crypto.randomBytes(32).toString('hex');
req.session.csrfToken = csrfToken;
// Inject into HTML form:
`<input type="hidden" name="_csrf" value="${csrfToken}">`

// Server: validate on state-changing requests
if (req.body._csrf !== req.session.csrfToken) {
  return res.status(403).json({ error: 'Invalid CSRF token' });
}

// ─── SameSite cookie (best practice) ───
res.cookie('session', token, {
  httpOnly: true,
  secure: true,       // HTTPS only
  sameSite: 'strict', // blocks all cross-site sends
  maxAge: 3600_000
});

// ─── SPA best practice: JWT in Authorization header ───
// No cookies → no CSRF by design
axios.defaults.headers.common['Authorization'] = `Bearer ${getToken()}`;
