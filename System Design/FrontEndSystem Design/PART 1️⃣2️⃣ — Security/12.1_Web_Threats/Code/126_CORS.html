CORS is not a security vulnerability — it's a browser safety mechanism that restricts cross-origin reads

The Same-Origin Policy (SOP) prevents JavaScript on app.com from reading responses from api.other.com. CORS lets servers explicitly whitelist which origins can read their responses by setting response headers. CORS only restricts browser JS — curl, Postman, server-to-server calls are unaffected. Common misconception: "CORS prevents attacks" — it does NOT prevent CSRF. It prevents cross-origin reads, not cross-origin sends.

Simple requests (no preflight)
GET, HEAD, POST
Content-Type: text/plain, form-data, x-www-form-urlencoded
No custom headers
Preflighted requests (OPTIONS first)
PUT, PATCH, DELETE
Content-Type: application/json
Any custom header (e.g., Authorization)

⚠️ Security: NEVER use Access-Control-Allow-Origin: * with credentials. Never reflect Origin header blindly — validate against allowlist.

Express CORS middleware + secure config

// ─── Secure CORS with allowlist ───
const allowedOrigins = [
  'https://app.sap.com',
  'https://portal.sap.com'
];

app.use((req, res, next) => {
  const origin = req.headers.origin;
  if (origin && allowedOrigins.includes(origin)) {
    res.setHeader('Access-Control-Allow-Origin', origin); // exact match, not *
    res.setHeader('Vary', 'Origin'); // critical for CDN caching
  }
  res.setHeader('Access-Control-Allow-Methods', 'GET, POST, PUT, DELETE');
  res.setHeader('Access-Control-Allow-Headers', 'Authorization, Content-Type');
  res.setHeader('Access-Control-Allow-Credentials', 'true');
  res.setHeader('Access-Control-Max-Age', '86400'); // cache preflight 24h
  if (req.method === 'OPTIONS') return res.sendStatus(204);
  next();
});

// ─── React fetch with credentials ───
fetch('https://api.sap.com/data', {
  credentials: 'include',  // send cookies cross-origin
  headers: { 'Authorization': `Bearer ${token}` }
});
