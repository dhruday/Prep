Auth flows: choose based on app type, trust level, and user experience requirements

Modern auth has standardized on OAuth 2.0 / OIDC as the protocol of choice. The "flow" determines HOW the token is obtained. Wrong choice = security risk: Authorization Code Flow (PKCE) is correct for SPAs; Implicit Flow is deprecated and vulnerable to token leakage in URL fragments. SAP BTP uses OIDC with Authorization Code + PKCE for all its Fiori app logins.

Auth Code + PKCE
✅ SPA, mobile apps. No client secret needed. Code verifier prevents code injection.
Client Credentials
✅ Server-to-server M2M. No user involved. Client ID + secret.
Device Flow
✅ CLI tools, smart TVs. Device shows code, user auths on phone.
Implicit Flow ❌
Deprecated. Token in URL fragment — leaked in history, logs, referrer.

PKCE flow implementation

// ─── Generate PKCE code verifier + challenge ───
async function generatePKCE() {
  const verifier = base64url(crypto.getRandomValues(new Uint8Array(32)));
  const hash = await crypto.subtle.digest('SHA-256', new TextEncoder().encode(verifier));
  const challenge = base64url(new Uint8Array(hash));
  sessionStorage.setItem('pkce_verifier', verifier); // save for token exchange
  return { verifier, challenge };
}

// ─── Step 1: redirect to IdP ───
const { challenge } = await generatePKCE();
const authUrl = new URL('https://idp.sap.com/authorize');
authUrl.searchParams.set('response_type', 'code');
authUrl.searchParams.set('code_challenge', challenge);
authUrl.searchParams.set('code_challenge_method', 'S256');
location.assign(authUrl);
