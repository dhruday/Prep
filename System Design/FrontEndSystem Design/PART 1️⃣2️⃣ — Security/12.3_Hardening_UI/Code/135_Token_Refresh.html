Why token refresh matters for security

Short-lived access tokens (15-60 min) reduce the blast radius of token theft. When expired, a refresh token (longer-lived) silently obtains a new access token. The challenge: multiple concurrent requests all 401 → only one refresh, others queue and retry. At SAP BTP, XSUAA tokens expire every 12 hours; the UI SDK uses a proactive refresh 5 minutes before expiry.

Proactive refresh
Refresh X seconds before expiry. No user-visible latency; requires watching token exp claim. ✅ Best UX
Reactive refresh (401)
Wait for 401, then refresh, then replay. Simple but causes latency spikes under concurrent calls. Queue all waiters.
Silent iframe refresh
Legacy SPA approach (auth0 checkSession). Hidden iframe does redirect. Blocked by 3rd-party cookie restrictions in modern browsers.

Reactive token refresh flow — single refresh with request queue

1
API call with access token
3 concurrent requests fired: GET /user, GET /orders, GET /products — all include Access-Token: Bearer eyJ...
2
401 Unauthorized — token expired
All three requests return 401. Axios interceptor catches first 401 and sets isRefreshing = true. Others see flag and queue their resolve.
3
Single refresh call
POST /auth/token with refresh_token → returns new Access-Token. Only one refresh fired, even for N concurrent 401s.
4
Drain the queue
New token stored in memory. All queued request promises resolve with new token and are retried automatically.
5
All requests retry — succeed
GET /user, /orders, /products all succeed. User sees no error. isRefreshing = false for future calls.

Refresh token rotation (security must-have)
Every refresh consumes the RT and issues a new RT + AT. If a leaked RT is used, the legit RT is invalidated too — triggering a "token reuse" alert. OAuth 2.1 requires this.

Axios 401 interceptor with request queue + proactive timer

// ─── Reactive: Axios 401 interceptor with queue ───
let isRefreshing = false;
let waiters: ((token: string) => void)[] = [];

api.interceptors.response.use(
  res => res,
  async err => {
    const orig = err.config;
    if (err.response?.status !== 401 || orig._retried) throw err;
    orig._retried = true;

    if (isRefreshing) {
      // Queue this request until refresh completes
      return new Promise(resolve => {
        waiters.push(token => {
          orig.headers['Authorization'] = `Bearer ${token}`;
          resolve(api(orig));
        });
      });
    }

    isRefreshing = true;
    const { token } = await refreshTokens();
    tokenStore.set(token);
    waiters.forEach(cb => cb(token));
    waiters = [];
    isRefreshing = false;
    orig.headers['Authorization'] = `Bearer ${token}`;
    return api(orig);
  }
);

// ─── Proactive: schedule refresh before expiry ───
function scheduleRefresh(accessToken: string) {
  const { exp } = parseJwt(accessToken);
  const msLeft = exp * 1000 - Date.now() - 60_000; // 60s before expiry
  setTimeout(async () => {
    const { token } = await refreshTokens();
    tokenStore.set(token);
    scheduleRefresh(token); // reschedule for new token
  }, Math.max(msLeft, 0));
}
