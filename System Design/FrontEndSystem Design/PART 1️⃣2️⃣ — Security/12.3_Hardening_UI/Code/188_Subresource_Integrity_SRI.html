How SRI protects against CDN compromise

❌ Without SRI — Polyfill.io scenario
1. You ship: <script src="https://cdn.polyfill.io/...">
2. Attacker buys domain
3. Serves malicious JS
4. Every user's browser executes attacker code
5. Auth tokens stolen ⛔
✅ With SRI — attacker blocked
1. You ship: integrity="sha384-abc123"
2. Attacker swaps CDN file
3. Browser hashes received bytes
4. Hash mismatch → BLOCK ✓
5. onerror fires → loads backup ✅
Critical requirement: crossorigin="anonymous"
Without crossorigin="anonymous", the browser uses no-cors mode — it can't inspect the response bytes, so it silently skips the integrity check entirely. Always pair integrity + crossorigin together.

SRI coverage: what it protects and what it doesn't

Resource TypeSRI SupportNotes
<script src>✅ Full supportMost critical — JS execution blocked on mismatch
<link rel="stylesheet">✅ Full supportBlocks CSS injection attacks (CSS keyloggers)
<link rel="preload">✅ Full supportVerify before execution, not just loading
<img>, <video>❌ Not supportedToo much format variance / srcset complexity
fetch() / XHR❌ Not supportedUse CSP or validate application-side
Service Worker importScripts❌ Not supportedUse Service Worker Content-Security-Policy header
Self-hosted resources⚠️ PointlessSRI only adds value for resources you don't control
CSP amplifier: require-sri-for
Content-Security-Policy: require-sri-for script style — enforces that ALL external scripts/styles must have an integrity attribute. Developers can't accidentally omit it.

Production SRI patterns

<!-- ✅ Complete SRI tag with fallback -->
<script
  src="https://cdn.jsdelivr.net/npm/react@18.2.0/umd/react.production.min.js"
  integrity="sha384-Zug+QiDoJOrZ5t4lssLdxGhVrurbmBWoR1Km2zxZAim7zcEtdJYCiBQ4iE8wv/J"
  crossorigin="anonymous"
  onerror="loadFallback('react')"
></script>

<!-- ✅ Multiple algorithms for fallback (any match accepts) -->
<script
  src="https://cdn.example.com/lib.js"
  integrity="sha256-oldHash sha384-newHash"
  crossorigin="anonymous"
></script>

// Webpack: automatic SRI on all output chunks
import SubresourceIntegrityPlugin from 'webpack-subresource-integrity';

const config = {
  output: { crossOriginLoading: 'anonymous' },  // required for chunk SRI
  plugins: [
    new SubresourceIntegrityPlugin({
      hashFuncNames: ['sha384'],
      enabled: process.env.NODE_ENV === 'production',
    }),
  ],
};

// Generate hash at build time (Node.js)
import { createHash } from 'crypto';
import { readFileSync } from 'fs';

function computeSRI(filepath: string, algo = 'sha384'): string {
  const content = readFileSync(filepath);
  const hash = createHash(algo).update(content).digest('base64');
  return `${algo}-${hash}`;
}
